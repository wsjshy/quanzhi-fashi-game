# 游戏减负设计方案 v1.0

> 设计日期：2026-08-14
> 目标版本：v0.9.0
> 核心问题：玩家负担过重，时间+体力双重限制导致不敢探索
> 设计原则：**时间是硬限制，体力是软提示，战斗不耗续航**

---

## 一、问题诊断

### 1.1 玩家反馈原话

> "玩这个游戏负担很重，对于时间的规划比较精细，一天根本没时间去多尝试点其他内容，比如开了新图，又如何呢，我根本不敢过去探索。需要减负，不能做成现在这种依靠时间和精力去探索的形式，至少不能同时依靠时间和精力。"

### 1.2 核心问题：双重硬限制

当前游戏同时用两个独立的硬限制来约束玩家行动：

| 系统 | 机制 | 效果 |
|------|------|------|
| **时间** | 每天24小时，每个行动消耗1-8小时 | 玩家需要精确规划时间分配 |
| **体力** | 每个行动消耗体力，体力为0无法行动 | 玩家需要管理体力恢复 |
| **HP/MP** | 战斗消耗，需要时间/物品恢复 | 探索新地图有续航风险 |

**三个资源同时管理，导致玩家每一步都在算账：时间够不够？体力够不够？HP/MP够不够？**

### 1.3 负担的具体表现

1. **探索恐惧**：新地图=时间消耗+体力消耗+战斗消耗+恢复成本，风险极高
2. **时间焦虑**：一天24小时不够用，做了A就做不了B
3. **体力墙**：体力为0时完全无法行动，只能被动等待
4. **续航焦虑**：连续战斗后HP/MP不足，需要花时间恢复
5. **决策瘫痪**：选项太多但资源太少，玩家不敢尝试新内容

### 1.4 根因分析

时间和体力实际上在做**同一件事**——限制行动频率。但用两个独立系统来做同一件事，导致：
- 玩家认知负担翻倍（要同时管两个资源）
- 行动成本被双重计算（移动既耗时间又耗体力）
- 恢复成本叠加（恢复体力要时间，恢复HP/MP也要时间）

## 二、行业参考与设计灵感

### 2.1 Chained Echoes：战斗后自动回满

**设计**：每场战斗结束后，所有角色的HP/MP全部恢复，负面状态清除。

**效果**：
- 玩家可以自由探索，不用担心连续战斗把资源耗光
- 每场战斗都是独立的挑战，而不是续航测试
- 减少药品囤积焦虑，减少"没满血是否回复"的决策负担
- 战斗难度通过**少量但精心设计的遭遇**来保证，而不是消耗战

**关键引用**：
> "战斗后自动回血回蓝，减少了用药品的数量，减少了每次战斗前需要做没有满血是否回复的决定，也间接减少了钱的花销。"
> "每场战斗都让你充分使用全部技能，而不是省着蓝药。"

### 2.2 Gothic 1 Remake：无体力战斗

**设计**：战斗系统完全没有体力条，闪避和攻击不消耗体力。

**效果**：
- 去掉体力不代表变简单，错误来自决策而非空资源条
- 很多玩家把体力等同于难度，但体力只是制造焦虑的工具
- 探索时没有"体力墙"，玩家可以自由行动

**关键引用**：
> "没有体力反而更有挑战性，因为你的错误来自糟糕的决策而不是空资源条。"

### 2.3 终末地：减法设计

**设计**：日常减负不是笼统减少，而是重构日常流程，压缩"玩家知道该怎么做但仍需花时间去做"的操作环节。

**效果**：
- 优化削减的不是内容，而是内容之间的填充
- 玩家时间花在决策和体验上，而不是机械操作

**关键引用**：
> "减的不是内容，而是内容之间的填充。压缩一切'玩家知道该怎么做但仍需花时间去做'的操作。"

### 2.4 SLG减负原则：策略前置

**设计**：把不产生策略价值的重复操作砍掉，把真正需要决策的内容前置。

**效果**：
- 玩家的每一分钟都花在"想"和"选"上，而不是机械点击
- 自动铺路是最直观的一刀

### 2.5 Outward：分层风险经济

**设计**：饥饿口渴不直接杀死玩家，而是降低体力和生命恢复。

**效果**：
- 你可以在饥饿时战斗，但恢复和持续能力崩溃
- 创造分层风险经济，而不是二元生存状态

### 2.6 时间银行/离线收益

**设计**：离线时时间累积，回来后用Time Bank快进操作。

**效果**：
- 玩家按自己节奏玩，不需要挂机
- 不逼玩家在线

## 三、核心设计方案

### 3.1 设计原则

```
时间是硬限制（剧情骨架，不能去掉）
体力是软提示（从"能不能玩"变成"玩得好不好"）
战斗不耗续航（战后恢复，探索无恐惧）
探索是收益（从"成本"变成"奖励"）
```

### 3.2 改动一：体力系统软化（核心）

#### 当前问题
- 体力为0时完全无法行动，形成"体力墙"
- 每个行动都消耗体力，包括移动/对话/商店等无策略价值的操作
- 玩家需要频繁休息恢复体力，占用大量时间

#### 新设计

**体力不再阻止行动，只影响效率：**

| 体力区间 | 状态 | 效果 | UI提示 |
|----------|------|------|--------|
| >60% | 精力充沛 | 正常效率，无影响 | 绿色 |
| 30%-60% | 有些疲惫 | 修炼经验-30%，战斗伤害-10% | 黄色 |
| <30% | 非常疲惫 | 修炼经验-60%，战斗伤害-25%，10%概率战斗后受伤 | 橙色 |
| =0 | 精疲力竭 | 战斗伤害-40%，20%概率受伤，修炼经验-80% | 红色 |

**体力消耗规则重制：**

| 行动类型 | 是否消耗体力 | 说明 |
|----------|-------------|------|
| 战斗 | ✅ 消耗（每场5-15） | 战斗是主要体力消耗 |
| 修炼/冥修 | ✅ 消耗（每次10-25） | 修炼消耗精神力 |
| 移动/旅行 | ❌ 不消耗 | 探索自由，不被体力阻挡 |
| 对话/商店/图书馆 | ❌ 不消耗 | 无策略价值的操作不耗体力 |
| 等待/休息 | ❌ 不消耗（恢复） | 休息恢复体力 |

**体力恢复：**
- 原地休息：恢复到80%（不固定1小时，按缺多少补多少）
- 宿舍休息：恢复到100%
- 睡觉到第二天：恢复到100%
- 体力药水：恢复50点

#### 为什么这样设计
1. **消除体力墙**：玩家永远不会因为体力为0而完全无法行动
2. **保留策略性**：体力低时效率降低，玩家仍有动力去休息
3. **探索自由**：移动不耗体力，玩家可以自由探索新地图
4. **战斗仍是核心消耗**：战斗消耗体力，连续战斗仍有累积压力

### 3.3 改动二：战斗后恢复（核心）

#### 当前问题
- 战斗后HP/MP不恢复，连续探索后资源耗尽
- 玩家需要花时间休息恢复，进一步压缩可探索时间
- 探索新地图有"打几架就没蓝了"的续航焦虑

#### 新设计

**战斗胜利后自动恢复：**

| 资源 | 恢复比例 | 说明 |
|------|----------|------|
| HP | 80%最大HP | 不是100%，保留一点续航感 |
| MP | 80%最大MP | 不是100%，Boss战前仍会选择休息 |
| 负面状态 | 100%清除 | 所有debuff清除 |
| 体力 | 不恢复 | 体力仍需通过休息恢复 |

**战斗失败：**
- 不扣时间，不扣钱
- 回到战斗前状态（HP/MP恢复到战斗前）
- 可以重试或调整装备后再战
- 最多扣5%当前经验作为轻微惩罚

#### 为什么这样设计
1. **消除续航焦虑**：连续战斗不会把资源耗光
2. **每场战斗独立**：战斗是独立的挑战，不是续航测试
3. **保留策略性**：80%而非100%，Boss战前玩家仍会选择休息到满
4. **失败无惩罚**：玩家可以大胆尝试挑战强敌，不怕失败

### 3.4 改动三：移动零消耗（核心）

#### 当前问题
- 移动消耗0.5小时+5体力，双重成本
- 探索新地图需要反复移动，成本累积
- 玩家因为移动成本而不敢去新地方

#### 新设计

| 消耗项 | 当前 | 改为 |
|--------|------|------|
| 移动时间 | 0.5小时 | 0.5小时（保留，时间是硬限制） |
| 移动体力 | 5体力 | 0体力（移除） |

**快速旅行：**
- 已解锁的地点之间可以快速旅行
- 快速旅行消耗0.5小时，不消耗体力
- 首次到达新地点仍需正常旅行（解锁快速旅行点）

### 3.5 改动四：探索奖励机制

#### 当前问题
- 探索新地图只有成本，没有额外奖励
- 玩家没有动力去探索，只有恐惧

#### 新设计

**首次探索奖励：**

| 探索行为 | 奖励 |
|----------|------|
| 首次到达新地点 | 50经验 + 20金币 |
| 首次与新NPC对话 | 20经验 |
| 首次发现隐藏地点 | 100经验 + 随机道具 |
| 首次完成地点事件 | 30经验 + 声望 |

**探索进度追踪：**
- 每个地点显示"探索度"（已发现NPC/事件/隐藏）
- 探索度100%时获得额外奖励
- UI显示"还有X个未发现内容"

#### 为什么这样设计
1. **把探索从成本变成收益**：玩家有动力去新地方
2. **降低未知恐惧**：知道有奖励，探索更有安全感
3. **增加成就感**：探索度系统给玩家明确的目标

### 3.6 改动五：时间系统优化

时间系统是剧情的骨架（课程表、大事件、NPC作息），不能去掉，但可以减负：

#### 课程自动执行
- 有课时自动去上课，不需要玩家手动点"上课"
- 上课期间玩家可以选择"认真听讲"（经验+）或"走神修炼"（修炼经验+）
- 逃课仍有惩罚，但不需要玩家手动操作

#### 快速休息
- 原地休息改为"恢复到体力80%"，不固定1小时
- 按缺多少补多少，缺20体力就休息0.5小时，缺50就休息1小时
- UI显示"休息到体力80%（约X小时）"

#### 时间跳跃
- 可以直接跳到下一个有事件的时间点
- 如"跳到晚上"、"跳到明天上课"、"跳到博城灾难"
- 跳跃期间自动恢复体力到80%

#### 每日总结
- 每天结束时显示"今天做了什么、获得了什么"
- 减少玩家记忆负担
- 显示"明天有什么安排"

### 3.7 改动六：UI减负

#### 顶部状态栏简化
- 只显示：HP/MP/体力/时间/金币
- 其他属性（等级/经验/声望等）收进角色面板
- 体力用颜色提示状态（绿/黄/橙/红），不显示具体数字

#### 行动按钮智能排序
- 推荐行动排在最前面（如"该上课了"时上课按钮高亮）
- 体力低时"休息"按钮高亮
- 新地点有未探索内容时"探索"按钮有提示

#### 探索提示
- 新地图显示"建议等级"和"可能遇到的妖魔"
- 降低探索未知恐惧
- 显示"首次探索奖励：50经验+20金币"

#### 一键恢复
- 背包里有恢复药时，HP/MP低时自动提示"一键使用"
- 不需要玩家手动打开背包找药

## 四、战斗力平衡保证

### 4.1 用户担忧

> "不影响游戏战斗力的平衡，目前的战斗系统我觉得还是可以的，并且可扩展性也比较好。"

### 4.2 平衡机制

1. **战斗后恢复80%而非100%**
   - 连续战斗仍有累积压力（每次剩80%，连续3场后只剩51%）
   - Boss战前玩家仍会选择休息到满
   - 不会变成"无脑战斗"

2. **体力软限制仍影响战斗**
   - 体力低时伤害降低（最高-40%）
   - 玩家不能无限战斗，仍需要休息恢复
   - 体力成为战斗策略的一部分

3. **战斗数量减少但质量提升**
   - 减少随机遭遇频率（从10%降到5%）
   - 每场战斗设计更精细
   - 参考Chained Echoes："每个区域遭遇数量少但设计精"

4. **装备/技能/天赋仍是核心**
   - 战斗深度来自系统本身，不是资源续航
   - 减负不改变战斗机制，只改变战斗前后的资源管理

5. **Boss战仍有挑战**
   - Boss战不触发战后恢复（Boss战是独立的高难度挑战）
   - Boss战前玩家需要确保状态良好
   - Boss战失败可以重试，但需要重新准备

### 4.3 数值平衡调整

| 项目 | 当前 | v0.9.0调整 | 原因 |
|------|------|-----------|------|
| 随机遭遇概率 | 10% | 5% | 战后恢复后遭遇太频繁会过于简单 |
| 敌人攻击力 | 基准 | +10% | 补偿战后恢复带来的难度降低 |
| 敌人HP | 基准 | +15% | 补偿战后恢复带来的难度降低 |
| 修炼经验 | 基准 | -20% | 体力软化后修炼更频繁，需要降低单次收益 |
| 战斗经验 | 基准 | 不变 | 战斗仍是主要经验来源 |

## 六、风险与应对

### 6.1 风险1：战后恢复导致战斗太简单

**应对**：
- 恢复80%而非100%，保留累积压力
- 敌人攻击力+10%，HP+15%补偿
- 随机遭遇概率降低，每场战斗更有质量
- Boss战不触发恢复

### 6.2 风险2：体力软化后玩家不休息

**应对**：
- 体力低时伤害-40%，战斗效率大幅降低
- 体力低时有20%概率受伤（debuff）
- 修炼经验-80%，升级速度大幅降低
- 玩家会主动选择休息来恢复效率

### 6.3 风险3：探索奖励导致升级太快

**应对**：
- 首次探索奖励是一次性的，不会重复获得
- 奖励数值适中（50经验约等于1-2场战斗）
- 修炼经验-20%补偿
- 探索奖励主要是引导，不是主要经验来源

### 6.4 风险4：存档兼容性

**应对**：
- 新增字段（exploredLocations等）有默认值
- 旧存档加载时自动初始化新字段
- SAVE_VERSION不变（0.8.7），因为只是新增字段不改变结构

## 七、设计哲学总结

### 7.1 核心转变

```
旧设计：资源管理 = 游戏内容
  玩家花80%时间在"算资源"上，只有20%时间在"体验内容"

新设计：资源管理 = 辅助工具
  玩家花20%时间在"管资源"上，80%时间在"体验内容"
```

### 7.2 减负的本质

减负不是减少内容，而是**减少内容之间的填充**：
- 不减少战斗数量，但减少战斗后的恢复时间
- 不减少探索地点，但减少探索的移动成本
- 不减少修炼选项，但减少体力管理的认知负担

### 7.3 参考游戏的共同特点

| 游戏 | 减负设计 | 核心洞察 |
|------|----------|----------|
| Chained Echoes | 战斗后回满 | 续航不是乐趣，决策才是 |
| Gothic 1 Remake | 无体力 | 体力制造焦虑，不制造乐趣 |
| 终末地 | 压缩填充操作 | 减的是填充，不是内容 |
| 波西亚时光 | 体力槽+睡觉恢复 | 体力是软限制，不是硬墙 |
| 伊洛纳 | 无强制主线 | 自由是最大的减负 |

### 7.4 最终目标

> 玩家打开游戏时想的是"今天我要去探索哪里、挑战谁"，
> 而不是"今天我的时间和体力够做什么"。

## 八、经验沉淀

### 8.1 设计教训

1. **不要用两个系统做同一件事**：时间和体力都在限制行动频率，导致双重负担
2. **硬限制要少而精**：一个游戏最多1-2个硬限制，太多会导致决策瘫痪
3. **软限制比硬限制好**：软限制让玩家有选择，硬限制让玩家被迫等待
4. **探索应该有奖励，不应该有惩罚**：玩家因为奖励去探索，不是因为不探索就落后
5. **失败不应该有重惩罚**：重惩罚导致玩家不敢尝试，不敢尝试就没有乐趣

### 8.2 可复用的设计模式

1. **战后恢复模式**：适用于任何有连续战斗的RPG
2. **体力软化模式**：从"能不能玩"到"玩得好不好"
3. **首次探索奖励**：引导玩家探索新内容
4. **移动零消耗**：消除探索的物理成本

### 8.3 后续验证指标

v0.9.0上线后需要验证：
- 玩家平均每天探索的新地点数量是否增加
- 玩家休息/恢复的时间占比是否降低
- 玩家战斗失败后的重试率是否提高
- 玩家反馈"负担重"的比例是否降低
