## 一、快速开始

### 1.1 直接运行（无需构建）

项目根目录的 `index.html` 已包含构建产物，**双击即可运行**，无需服务器、无需安装依赖。

```
双击 index.html → 浏览器打开 → 开始游戏
```

### 1.2 开发模式（热更新）

```bash
# 安装依赖（首次）
npm install

# 启动开发服务器
npm run dev
# 访问 http://localhost:5173
# 修改代码后自动刷新
```

### 1.3 重新构建

```bash
# 构建并复制到根目录
npm run build:copy

# 构建完成后双击 index.html 即可运行
```

### 1.4 一键构建并运行

```bash
npm run play
# 或双击 build-and-play.bat
```

```
├── tests/                  # 自动化测试
├── docs/                   # 开发文档

```

## 三、构建配置

### 3.1 Vite配置

`vite.config.js`：
- `base: './'` — 相对路径，确保构建后可直接打开
- `resolve.alias` — `@`→`src/`，`@data`→`src/data/`，`@engine`→`src/engine/`
- `build.outDir` — 构建输出到 `dist/`，然后 `build:copy` 脚本复制到根目录

### 3.2 package.json scripts

| 命令 | 作用 |
|------|------|
| `npm run dev` | 启动开发服务器（热更新） |
| `npm run build` | Vite构建到dist/ |
| `npm run build:copy` | 构建并复制到根目录 |
| `npm run play` | 构建并打开index.html |
| `npm run test` | 运行自动化测试 |

### 3.3 构建产物

构建后根目录生成：
- `index.html` — 入口HTML（内联CSS/JS）
- `assets/` — 构建后的资源文件

**注意**：构建产物已提交到Git，确保用户克隆后可直接运行。

## 四、开发工作流

### 4.1 标准开发流程

```
1. 读 AGENTS.md 确认方向
2. 读 TODO.md 找到当前任务
3. 新系统 → 先写设计文档（docs/version-design/）
4. 用户确认对齐
5. 开发模式 npm run dev
6. 修改代码（src/data/ 或 src/engine/）
7. 自动化测试 node tests/run.js
8. 冒烟测试（浏览器验证）
9. 重新构建 npm run build:copy
10. 文档同步（AGENTS/TODO/CHANGELOG/README）
11. Git commit + push
```

### 4.2 代码规范

- **ES Modules**：使用 `export const` 和 `import`，同时保持window兼容挂载
- **数据驱动**：能用JS对象配置的就不写代码
- **模块化**：每个功能独立成文件，单文件不超过500行（核心入口除外）
- **向后兼容**：新增内容不影响已有内容，旧接口保留委托

### 4.3 调试工具

游戏内置调试工具（`src/engine/debug.js`）：
- 标题界面点击"调试"按钮进入
- 快速设置等级、金币、物品
- 快速触发大事件、战斗
- 查看存档数据、NPC状态

**开发时用debug快速推进，不要从Lv.1手动推到中期。**

## 五、自动化测试

### 5.1 运行测试

```bash
node tests/run.js
```

输出示例：
```
L1数据完整性: 35通过/0失败/2警告 (0.03s)
L2战斗逻辑: 31通过/0失败 (0.02s)
L2.5天赋战斗状态: 35通过/0失败 (0.02s)
L2.6双天赋装备: 14通过/0失败 (0.01s)
L3成长流程: 13通过/0失败 (0.03s)
总计: 128通过/0失败/2警告 (0.11s)
```

### 5.2 测试层级

| 层级 | 文件 | 覆盖范围 | 运行时机 |
|------|------|---------|---------|
| L1 | data-integrity.js | 数据完整性（ID唯一/引用存在/格式正确） | 改数据后必跑 |
| L2 | battle-logic.js | 战斗逻辑（伤害计算/元素克制/状态效果） | 改战斗后必跑 |
| L2.5 | talent-combat.js | 天赋战斗状态 | 改天赋后必跑 |
| L2.6 | dual-talent.js | 双天赋装备 | 改天赋/装备后必跑 |
| L3 | progression.js | 成长流程（觉醒/突破/修炼） | 改成长后必跑 |

### 5.3 测试原则

- **分层测试**：L1-L3用自动化脚本（0.1秒），L4体验才用浏览器
- **真黑盒**：浏览器测试时测试者不知道代码逻辑，纯玩家视角
- **体验优先**：功能正常 ≠ 好玩，体验问题和bug同等重要

## 六、Git工作流

### 6.1 分支策略

- `master` — 开发分支（日常开发在此分支）
- `gh-pages` — 部署分支（GitHub Pages，自动从master构建部署）

### 6.2 Git路径

Git不在PATH，必须用完整路径：
```bash
D:\Git\cmd\git.exe
```

### 6.3 提交规范

```
<类型>: <简短描述>

<详细说明（可选）>
```

类型：
- `feat` — 新功能
- `fix` — bug修复
- `docs` — 文档更新
- `refactor` — 代码重构
- `test` — 测试相关
- `chore` — 构建/工具/配置

### 6.4 部署到GitHub Pages

```powershell
# 自动化部署脚本（推荐）
.\tools\deploy.ps1 -Version "v3.2.0" -Message "版本描述"
```

部署地址：https://wsjshy.github.io/quanzhi-fashi-game/

**部署前必须确保master分支工作区干净**，否则切换分支会失败。

## 七、常见问题

### Q: 修改代码后浏览器没有变化？
A: 开发模式下检查是否保存了文件；直接打开index.html需要先运行 `npm run build:copy` 重新构建。

### Q: 测试报错 "Cannot find module"？
A: 检查import路径是否正确，别名 `@data/` 和 `@engine/` 是否正确使用。

### Q: Git命令报错 "git不是内部或外部命令"？
A: Git不在PATH，必须用完整路径 `D:\Git\cmd\git.exe`。

### Q: 构建后index.html打不开？
A: 检查vite.config.js的 `base: './'` 是否正确，确保使用相对路径。

### Q: 存档丢失？
A: 存档存在localStorage中，清除浏览器数据会丢失。使用debug工具的导出/导入功能备份。
