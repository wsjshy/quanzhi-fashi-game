# 机制型妖魔特性设计方法论

> **核心理念**：妖魔强度来自独特机制和特性，而非纯数值堆砌。玩家需要观察敌人机制、预判回合节奏、针对性选择策略。

---

## 一、设计原则

### 1.1 核心原则

1. **机制优先，数值辅助**：每个妖魔至少有1个独特机制，数值加成只是补充
2. **弱点明确**：每个妖魔都有可被利用的弱点（物理/魔法/元素/回合节奏）
3. **回合可预判**：机制有明确的冷却时间，玩家可以观察和规划
4. **难度分层**：奴仆级简单，战将级有弱点，统领级多机制组合
5. **原著溯源**：机制设计参考小说原文描述，不凭空编造

### 1.2 反模式（禁止）

- ❌ 纯数值堆砌（只有攻击+X%、防御+X%）
- ❌ 无弱点的全能型妖魔
- ❌ 随机触发不可预判的机制
- ❌ 机制过于复杂（超过5个机制）
- ❌ 与原著设定矛盾的机制

## 二、机制类型分类

### 2.1 按触发方式分类

| 类型 | 说明 | 示例 |
|------|------|------|
| **被动型** | 持续生效，无需触发 | 钢铁身躯（物理减伤）、暗属性抗性 |
| **触发型** | 满足条件时触发 | 狂暴（HP<50%）、血怒（HP越低越强） |
| **机制型** | 按冷却回合主动释放 | 掘地突袭、三段冲刺、战争践踏 |
| **受击型** | 受到攻击时触发 | 骨刺护甲（反弹伤害） |
| **首击型** | 第一次攻击时触发 | 暗影突袭（首击必暴） |

### 2.2 按效果分类

| 类型 | 说明 | 设计要点 |
|------|------|---------|
| **伤害型** | 造成额外伤害 | 有冷却，伤害倍率1.2-2.0 |
| **控制型** | 眩晕/恐惧/致盲/流血 | 概率30%-70%，持续1-3回合 |
| **状态型** | 自身增益/玩家减益 | 攻击/防御/速度/命中 |
| **形态型** | 切换形态，属性变化 | 飞行/落地，狂暴/正常 |
| **召唤型** | 召唤小怪或模拟围攻 | 简化为额外伤害 |
| **弱点型** | 对特定攻击类型易伤 | 魔法易伤、暗系易伤 |

## 三、不同级别妖魔的设计规范

### 3.1 奴仆级妖魔

**定位**：基础敌人，让玩家学习机制

| 项目 | 规范 |
|------|------|
| 机制数量 | 1-2个 |
| 机制复杂度 | 简单（单一效果） |
| 冷却时间 | 3-4回合 |
| 弱点 | 1个明确弱点 |
| 数值加成 | 少量（10%-20%） |

**示例**：
- 巨眼猩鼠：掘地突袭（每3回合）+ 猩红光束（穿防）
- 黑畜妖：恐惧尖啸（每3回合）+ 暗属性抗性

### 3.2 战将级妖魔

**定位**：精英敌人，需要策略应对

| 项目 | 规范 |
|------|------|
| 机制数量 | 2-3个 |
| 机制复杂度 | 中等（组合效果） |
| 冷却时间 | 2-3回合 |
| 弱点 | 1-2个弱点，需要针对性选择 |
| 数值加成 | 中等（20%-40%） |

**示例**：
- 三眼魔狼：钢铁身躯（物理减伤/魔法易伤）+ 骨刺齐射（每2回合）
- 骨刺狰：骨刺再生（每回合回血）+ 骨刺护甲（物理反弹）+ 战争践踏（每3回合）
- 血纹巨魔鼠：血怒（HP越低越强）+ 撕裂（流血+治疗减益）+ 极速冲锋（每3回合）

### 3.3 统领级妖魔

**定位**：BOSS，多阶段多机制组合

| 项目 | 规范 |
|------|------|
| 机制数量 | 3-4个 |
| 机制复杂度 | 高（多机制联动） |
| 冷却时间 | 2-4回合 |
| 弱点 | 多个弱点，需要综合策略 |
| 数值加成 | 较高（40%-100%） |
| 特殊机制 | 开局威压/形态切换/召唤 |

**示例**：
- 翼苍狼：翱翔天际（飞行/落地切换）+ 狼啸号令（召唤）+ 风刃风暴（AOE）+ 统领威压（开局减益）

### 3.4 君主级妖魔（未来扩展）

**定位**：终极BOSS，多阶段战斗

| 项目 | 规范 |
|------|------|
| 机制数量 | 4-5个 |
| 阶段设计 | 2-3个阶段，每阶段机制不同 |
| 特殊机制 | 场地效果、无敌阶段、狂暴阶段 |

## 四、设计流程

### 4.1 标准流程

```
1. 查阅原著 → 2. 提取特征 → 3. 设计机制 → 4. 确定弱点 → 5. 平衡数值 → 6. 实现代码 → 7. 测试验证
```

### 4.2 详细步骤

**步骤1：查阅原著**
- Grep `全职法师.txt` 搜索妖魔名称
- 提取原文中的描述：外形、能力、行为模式、弱点
- 记录关键特征（如"钢铁般结实身躯"、"飞行能力"、"号令妖魔"）

**步骤2：提取特征**
- 从原文描述中提取可转化为游戏机制的特征
- 外形特征 → 防御/抗性机制
- 能力特征 → 主动技能机制
- 行为特征 → AI/触发机制
- 弱点特征 → 易伤机制

**步骤3：设计机制**
- 根据妖魔级别确定机制数量
- 选择机制类型（被动/触发/机制/受击/首击）
- 确定冷却时间和效果数值
- 确保机制之间有联动或互补

**步骤4：确定弱点**
- 每个妖魔至少有1个明确弱点
- 弱点可以是：伤害类型（物理/魔法）、元素系别、回合节奏
- 弱点应该让玩家有"哦，原来应该这样打"的顿悟感

**步骤5：平衡数值**
- 机制伤害倍率：奴仆级1.2-1.5，战将级1.3-1.8，统领级1.5-2.0
- 控制概率：奴仆级30%-50%，战将级40%-60%，统领级50%-70%
- 减益幅度：10%-30%
- 确保机制强度不超过纯数值加成的2倍

**步骤6：实现代码**
- 在 `demon-traits.js` 中定义特性
- 在 `battle.js` 中实现机制触发逻辑
- 复用已有机制类型，避免重复造轮子

**步骤7：测试验证**
- `node tests/run.js` 跑自动化测试
- 浏览器端测试实际战斗体验
- 验证机制是否正常触发、冷却是否正确、弱点是否有效

## 五、常见机制模板

### 5.1 伤害型机制

```javascript
{
    id: "skill_name",
    name: "技能名称",
    description: "每X回合造成Y%伤害",
    type: "mechanic",
    mechanic: "damage_skill",
    cooldown: 3,
    effects: {
        damageMultiplier: 1.5,
        element: "fire"  // 可选：元素类型
    }
}
```

### 5.2 控制型机制

```javascript
{
    id: "skill_name",
    name: "技能名称",
    description: "每X回合造成伤害+Y%概率Z状态",
    type: "mechanic",
    mechanic: "control_skill",
    cooldown: 3,
    effects: {
        damageMultiplier: 0.8,
        controlType: "stun",  // stun/fear/blind/bleed
        controlChance: 0.5,
        controlDuration: 2
    }
}
```

### 5.3 形态切换机制

```javascript
{
    id: "form_switch",
    name: "形态切换",
    description: "每X回合切换形态",
    type: "mechanic",
    mechanic: "form_switch",
    cooldown: 2,
    effects: {
        formA: { attackBonus: 0.3, dodgePenalty: 0.1 },
        formB: { dodgeBonus: 0.5, attackPenalty: 0.2 }
    }
}
```

### 5.4 触发型机制

```javascript
{
    id: "berserk",
    name: "狂暴",
    description: "HP低于X%时触发",
    type: "trigger",
    trigger: "low_hp",
    threshold: 0.5,
    effects: {
        attackBonus: 0.3,
        speedBonus: 0.2
    }
}
```

### 5.5 弱点机制

```javascript
{
    id: "weakness",
    name: "弱点",
    description: "受到X类型伤害增加Y%",
    type: "passive",
    effects: {
        magicDamageTaken: 0.2,  // 魔法易伤20%
        // 或
        elementWeakness: "fire",  // 火系易伤
        elementDamageBonus: 0.3
    }
}
```

### 6.3 新增机制类型时的实现步骤

1. 在 `demon-traits.js` 中定义 `type: "mechanic"` 特性，指定 `mechanic` 字段
2. 在 `battle.js` 的机制触发循环中添加 `if (mech === 'xxx')` 分支
3. 实现机制效果（伤害/控制/状态/形态切换）
4. 设置冷却 `this.enemy.mechanicCooldowns[mech] = trait.cooldown`
5. 调用 `this.endEnemyTurn()` 结束回合（如果机制替代普通攻击）

## 七、平衡原则

### 7.1 机制强度平衡

- **机制伤害 ≤ 普通攻击 × 2.0**
- **控制概率 ≤ 70%**
- **减益幅度 ≤ 30%**
- **持续时间 ≤ 3回合**

### 7.2 级别间强度差距

- 奴仆级机制：简单、低伤害、低控制概率
- 战将级机制：中等、有弱点、需要策略
- 统领级机制：复杂、多机制联动、需要综合策略

### 7.3 玩家应对空间

- 每个机制都应该有明确的应对方法
- 防御/控制/爆发/治疗都应该有发挥空间
- 不应该有"无解"的机制

## 八、原著溯源示例

### 8.1 翼苍狼

**原文描述**：
- "统领级妖魔"
- "一声咆哮，号令成百上千妖魔"
- "飞行能力"
- "风系魔法"
- "整个博城能在它一击之下活着的只有军部首领斩空"

**转化为机制**：
- 统领级 → 统领威压（开局减益）
- 号令妖魔 → 狼啸号令（召唤）
- 飞行能力 → 翱翔天际（形态切换）
- 风系魔法 → 风刃风暴（AOE）

### 8.2 三眼魔狼

**原文描述**：
- "三只眼睛，270度视角"
- "钢铁般结实身躯"
- "锋利棱角骨刺"

**转化为机制**：
- 270度视角 → 闪避+15%，无法被偷袭
- 钢铁身躯 → 物理减伤40%，魔法易伤20%
- 锋利骨刺 → 骨刺齐射（伤害+流血）

## 九、检查清单

新增机制型妖魔特性时，检查以下项目：

- [ ] 已查阅原著，提取关键特征
- [ ] 机制数量符合级别规范（奴仆1-2，战将2-3，统领3-4）
- [ ] 至少有1个明确弱点
- [ ] 机制有明确冷却时间，可预判
- [ ] 机制强度符合平衡原则
- [ ] 玩家有明确的应对方法
- [ ] 战斗逻辑已实现（mechanic类型）
- [ ] 自动化测试通过
- [ ] 浏览器端测试验证

## 十、未来扩展方向

1. **场地机制**：妖魔改变战斗场地（燃烧地面、毒雾、地震）
2. **多阶段BOSS**：HP阈值触发阶段变化，机制改变
3. **元素联动**：妖魔机制与玩家元素技能产生互动
4. **AI行为树**：根据玩家行为动态选择机制
5. **妖魔组合**：多妖魔战斗时的机制联动
