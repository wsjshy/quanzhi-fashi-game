# UI/UX设计规范

> 本文档定义UI设计原则、多端自适应、交互设计、布局规范。
> 最后更新：2026-09-09 | 适用版本：v3.13.0
> 核心UI模块：`src/engine/ui.js` + 30+个子模块（ui-*.js）

---

## 一、核心设计原则

### 1.1 非滚动优先
- **核心功能与信息必须在单屏聚焦呈现**
- 主界面（行动面板/属性面板/地图）不应该需要滚动
- 只有长列表（背包/任务列表/对话历史）允许滚动
- 设计时先考虑"一屏能放下什么"，再考虑"放不下的怎么办"

### 1.2 多端自适应
- **PC端横版布局**：左侧主内容区，右侧常驻角色属性面板
- **手机端竖版布局**：上下结构，属性面板可折叠/切换
- **平板**：根据屏幕宽度自动选择横版或竖版
- 断点：<768px竖版，≥768px横版

### 1.3 交互设计
- **鼠标悬停（PC）**：显示额外信息（tooltip），如物品详情、NPC关系
- **手机长按**：等效于PC悬停，显示额外信息
- **点击反馈**：按钮点击有视觉反馈（颜色变化/缩放）
- **操作确认**：不可逆操作需要确认（如删除存档）
- **键盘支持**：ESC关闭弹窗，Enter确认，数字键快速选择

### 1.4 美术感
- **摒弃方正布局**：避免纯矩形网格，用圆角、卡片、错落布局
- **色彩主题**：暗色背景+元素色系点缀，避免大面积紫色/靛蓝
- **字体层次**：标题/正文/辅助文字三级层次
- **动效**：适度的过渡动画，不花哨但有反馈

## 二、布局规范

### 2.1 PC端横版布局（≥768px）
```
┌──────────────────────────────────────┬──────────────┐
│                                      │              │
│         主内容区（70%）               │  属性面板    │
│  - 地图/场景/对话/战斗                │  （30%常驻） │
│  - 行动按钮                           │  - 角色头像  │
│  - 消息显示                           │  - 等级/经验 │
│                                      │  - 属性数值  │
│                                      │  - 元素/技能 │
│                                      │  - 快捷栏    │
└──────────────────────────────────────┴──────────────┘
```

**要求**：
- 主内容区和属性面板都不需要滚动
- 属性面板常驻，随时可见角色状态
- 战斗时主内容区显示战斗界面，属性面板显示战斗状态

### 2.2 手机端竖版布局（<768px）
```
┌──────────────────────┐
│  顶部状态栏（等级/HP/MP）│
├──────────────────────┤
│                      │
│   主内容区（可滚动）   │
│   - 地图/场景/对话    │
│   - 战斗界面          │
│                      │
├──────────────────────┤
│  底部导航栏           │
│  [属性][背包][任务][地图]│
└──────────────────────┘
```

**要求**：
- 顶部状态栏精简，只显示最关键信息
- 底部导航栏固定，4-5个入口
- 属性面板通过底部导航切换，不常驻
- 按钮足够大，适合触屏（最小44x44px）

### 2.3 弹窗规范
- **z-index必须大于9999**（#game-container的z-index是9999）
- 居中显示，最大宽度不超过屏幕80%
- 有关闭按钮（X）+ ESC关闭 + 点击遮罩关闭
- 遮罩层半透明黑色（rgba(0,0,0,0.7)）
- 弹窗内容过多时内部滚动，不是整个页面滚动

### 2.4 战斗UI（内联展开式）
- **不再用全屏弹窗**，而是在主内容区内联展开
- 战斗界面包含：敌人信息/玩家信息/技能按钮/战斗日志
- 技能按钮展开式：点击技能分类展开该系技能列表
- 战斗日志可折叠，不占主视野
- 组队战斗时显示队友状态条

## 三、色彩规范

### 3.1 主色调
- 背景：深色系（#1a1a2e / #16213e）
- 卡片：稍浅的深色（#0f3460 / #1f4068）
- 文字：浅色（#eaeaea / #ffffff）
- 辅助文字：灰色（#a0a0a0）

### 3.2 元素色系
| 元素 | 主色 | 用途 |
|------|------|------|
| 火系 | #ff6633 | 火系技能/图标/边框 |
| 冰系 | #66ccff | 冰系技能/图标/边框 |
| 雷系 | #ffcc00 | 雷系技能/图标/边框 |
| 土系 | #cc9966 | 土系技能/图标/边框 |
| 风系 | #99ff99 | 风系技能/图标/边框 |
| 水系 | #6699ff | 水系技能/图标/边框 |
| 光系 | #ffffcc | 光系技能/图标/边框 |
| 暗系 | #9966ff | 暗系技能/图标/边框 |

### 3.3 状态色
- 成功/正向：绿色（#4caf50）
- 警告/负向：红色（#f44336）
- 信息/中性：蓝色（#2196f3）
- 金币/稀有：金色（#ffd700）

### 3.4 品质色（装备/物品）
| 品质 | 颜色 |
|------|------|
| 普通 | 白色/灰色 |
| 优秀 | 绿色 |
| 稀有 | 蓝色 |
| 史诗 | 紫色 |
| 传说 | 橙色/金色 |

### 3.5 避免
- ❌ 大面积紫色/靛蓝（用户明确不喜欢）
- ❌ 高饱和度刺眼配色
- ❌ 纯黑纯白对比过强

## 四、交互细节规范

### 4.1 按钮
- 主按钮：填充背景色，白色文字
- 次按钮：透明背景，边框+文字
- 禁用按钮：灰色，不可点击
- 悬停效果：亮度变化+轻微缩放
- 点击效果：按下状态（颜色加深）
- 最小尺寸：PC 32px高，手机 44px高

### 4.2 列表
- 每项有明确的视觉分隔（边框/背景色交替）
- 关键信息突出（名称/数量）
- 次要信息弱化（描述/详情）
- 可点击项有悬停效果
- 空状态有友好提示

### 4.3 进度条
- HP：红色渐变
- MP：蓝色渐变
- 经验：金色/绿色渐变
- 显示数值（当前/最大）
- 变化时有动画过渡

### 4.4 Tooltip（悬停提示）
- PC：鼠标悬停0.3秒后显示
- 手机：长按显示
- 内容：名称+描述+属性（如适用）
- 位置：自动避免超出屏幕
- 样式：深色背景，浅色文字，圆角

### 4.5 消息提示
- 操作结果用toast提示（底部/顶部，自动消失）
- 重要消息用弹窗（需要确认）
- 连续多条消息排队显示，不重叠
- 消息关闭后界面必须可点击（检查遮罩层）

## 五、各系统UI规范

### 5.1 战斗UI
**布局**（PC横版）：
```
┌──────────────────────────────────────┬──────────────┐
│  敌人信息（头像/名字/HP条/状态效果）   │  玩家属性    │
│                                      │  （常驻面板） │
│  [战斗动画区域]                       │              │
│                                      │              │
│  战斗日志（可折叠）                    │              │
├──────────────────────────────────────┤              │
│  技能按钮区（内联展开）                │              │
│  [火][冰][雷][土][风][水][道具][防御]  │              │
│  → 展开后显示该系技能列表              │              │
└──────────────────────────────────────┴──────────────┘
```

**技能UI（内联展开式）**：
- 默认显示元素分类按钮（一排）
- 点击某系后，下方展开该系技能列表
- 技能按钮显示：技能名/MP消耗/冷却状态
- 再次点击同系或其他系，切换展开内容
- 不可用技能（MP不足/冷却中）灰色显示

**战斗反馈**：
- 伤害数字飘字（红色伤害/绿色治疗/黄色暴击）
- 状态效果图标显示
- 元素克制提示（"效果拔群"/"效果不佳"）
- 战斗结束评价（S/A/B/C/D）

**相关模块**：`ui-battle.js`、`ui-damage-number.js`、`battle-visual-feedback.js`

### 5.2 对话UI
- NPC头像+名字在顶部
- 对话文本居中，支持多条随机
- 选项列表在底部，每个选项一行
- 选项有条件时，不满足条件的不显示（不是灰色禁用）
- 对话历史可滚动查看
- 对话界面显示当前关系等级（陌生人/朋友/挚友等）
- 关系变化时有提示（"穆宁雪对你的好感提升了"）

**相关模块**：`ui-dialogue.js`、`ui-character.js`

### 5.3 地图UI
**大地图**：
- 2D可视化地图，地点用图标+名称标注
- 地点之间有连线表示连通
- 当前位置高亮
- 可前往的地点可点击，锁定的地点灰色+锁图标
- 点击地点显示详情（名称/描述/可执行行动）

**地点行动面板**：
- 进入地点后显示可执行的行动列表
- 每个行动：图标+名称+描述+时间消耗
- 行动按类型分组（修炼/猎魔/探索/社交/商店）
- 不可用行动（条件不满足）灰色显示+提示原因

**相关模块**：`ui-map.js`、`ui-daily.js`

### 5.4 背包UI
- 物品网格布局，按类型分类（消耗品/装备/材料/魔具）
- 物品图标+名称+数量
- 点击物品显示详情弹窗（属性/描述/操作按钮）
- 装备有品质色边框
- 装备卡片有"重铸"按钮（v3.10）
- 装备对比：当前装备 vs 候选装备

**相关模块**：`ui-inventory.js`

### 5.5 锻造UI（v3.9+）
- 左侧：配方列表（按等级分组，显示解锁状态）
- 右侧：选中配方详情（产出装备/所需材料/金币消耗）
- 材料显示：拥有数量/所需数量，不足时红色
- 精魄注入区（v3.10）：选择精魄类型，实时显示品质概率变化
- 锻造按钮：材料不足时禁用
- 结果弹窗：显示锻造出的装备（品质色+词缀）

**相关模块**：`ui-forge.js`、`forge.js`

### 5.6 悬赏UI（v3.12+）
- 双标签：可接悬赏 / 进行中
- 左侧：悬赏列表（等级色标/目标/奖励/有效期）
- 右侧：选中悬赏详情（描述/目标进度/接取或领奖按钮）
- 顶部：已接取悬赏数量（x/3）
- 进度条：击杀进度（2/3）
- 完成状态：可领奖时高亮显示

**相关模块**：`ui-bounty.js`、`bounty.js`

### 5.7 闭关UI（v3.11+）
- 时长选择：1天/3天/7天/30天（显示收益倍率）
- 地点选择：学校/家里/猎者联盟/灵地（显示加成）
- 特殊事件说明：顿悟/灵感/心流/突破契机/走火入魔
- 闭关进度：剩余时间/已获得收益
- 提前出关按钮：收益打折

**相关模块**：`ui-retreat.js`、`retreat.js`

### 5.8 年度考核UI（v3.13+）
- 阶段指示：3次魔法释放的进度
- 每次释放：选择技能+瞄准方向+蓄力程度
- 评分实时显示：威力/控制力/稳定性/创意
- 最终评级：S/A/B/C/D（品质色）
- 奖励展示：金币/经验/声望/物品
- NPC反应：唐月/穆白根据评分有不同对话

**相关模块**：`ui-annual-exam.js`、`annual-exam.js`

### 5.9 商店UI
- 商品列表（分页或分类标签）
- 每个商品：图标/名称/价格/库存
- 购买数量选择
- 出售标签：出售背包物品
- 金币显示在顶部

**相关模块**：`ui-shop.js`

### 5.10 天赋UI
- 天赋列表（按系别分组）
- 天赋详情：效果/触发条件/等级
- 天赋选择界面（觉醒时）
- 天生天赋展示

**相关模块**：`ui-talent-detail.js`、`ui-element-selection.js`

## 六、Debug面板规范

### 6.1 开启方式
- 标题界面点击"调试"按钮
- 或URL加 `?debug=1`

### 6.2 面板布局
- 浮动面板，可拖动
- 分类标签：角色/物品/传送/剧情/战斗/天赋/跳过
- 每个分类下有对应快捷操作
- 操作后立即生效，有反馈提示

### 6.3 Debug功能要求
- 每次新增系统后，检查debug面板是否需要对应功能
- 新NPC/新地点/新任务要能在debug中快速访问
- 新系统（锻造/悬赏/闭关/年度考核）要有debug快速触发
- debug面板本身也要测试，不能坏了

**相关模块**：`debug.js`

## 七、性能与体验

### 7.1 响应速度
- 按钮点击响应 <100ms
- 页面切换 <300ms
- 战斗回合切换 <500ms
- 存档读写 <200ms

### 7.2 动画
- 过渡动画 200-300ms
- 不使用超过500ms的动画（除非是特殊效果）
- 动画用CSS transform/opacity，避免触发重排
- 低端设备可降级动画

### 7.3 错误处理
- JS错误不应该导致白屏
- 关键操作有try-catch
- 错误时有友好提示，不是技术报错
- 控制台输出 `[DEBUG]` 前缀的日志方便调试

## 八、UI改动检查清单

每次UI改动后检查：
- [ ] PC端横版布局正常
- [ ] 手机端竖版布局正常
- [ ] 主界面不需要滚动（非滚动优先）
- [ ] 弹窗z-index>9999，可正常关闭
- [ ] 按钮点击有反馈
- [ ] 悬停/长按tooltip正常
- [ ] 色彩符合规范（无大面积紫色）
- [ ] 文字清晰可读
- [ ] 没有元素被遮挡
- [ ] 控制台无报错
- [ ] 新系统在debug面板有快速入口
- [ ] 新UI模块在架构说明.md中登记
