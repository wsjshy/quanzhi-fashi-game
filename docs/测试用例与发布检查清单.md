## 🐛 已知Bug模式与预防

### Bug模式1：对象/数组类型混淆
**现象**：调用数组方法（如sort、map、filter）时报错"xxx不是函数"
**原因**：数据是对象{}而不是数组[]
**易发位置**：getAllXxx() 类方法返回值
**预防方法**：
- 使用 `Object.values()` 将对象转为数组
- 调用数组方法前先确认类型
- 统一数据返回格式（尽量统一返回数组）

**历史案例**：
- 妖魔图鉴 enemies.sort 报错 → 修复：`Object.values(DataManager.getAllEnemies())`

### Bug模式2：事件监听器泄漏
**现象**：界面完全无法点击，所有按钮都没反应
**原因**：全局事件监听器没有被正确移除，持续拦截所有事件
**易发位置**：弹窗/消息系统的全局点击拦截
**预防方法**：
- 使用闭包保存监听器引用，不要依赖全局变量
- 每条消息/弹窗管理自己的监听器
- 添加安全超时机制，确保监听器一定会被移除
- 添加卡住检测与自动恢复机制

**历史案例**：
- 消息弹窗后界面卡住 → 根本原因：多条消息时后面的消息覆盖了_globalClickInterceptor，导致前面的拦截器无法移除 → 修复：使用局部变量保存每条消息自己的拦截器引用

### Bug模式3：点击穿透
**现象**：点击弹窗按钮后，下面的按钮也被触发了
**原因**：事件冒泡/延迟点击导致穿透
**易发位置**：弹窗关闭后立即触发底层按钮
**预防方法**：
- 添加点击冷却时间
- 关闭后短时间内阻止点击
- 使用遮罩层拦截
- 全局点击拦截器

### Bug模式4：状态不同步
**现象**：UI显示和实际状态不一致
**原因**：修改了状态但没有更新UI，或者反之
**易发位置**：属性变化、任务进度、物品数量
**预防方法**：
- 统一状态管理，修改状态后自动触发UI更新
- 每次操作后调用 render() 更新界面
- 添加状态校验机制

### Bug模式5：数据引用错误
**现象**：显示undefined或者报错"Cannot read property of undefined"
**原因**：引用了不存在的ID
**易发位置**：任务奖励、物品掉落、技能学习
**预防方法**：
- 添加数据存在性检查
- 发布前检查所有引用的ID是否存在
- 写单元测试验证数据一致性

## 🧪 测试流程规范

### 开发自测流程
1. 开发完成新功能后
2. 运行 `node --check` 检查所有修改的JS文件语法
3. 本地打开游戏，测试新增功能的基本流程
4. 测试相关联的旧功能是否受影响
5. 检查数据引用是否正确（物品ID/敌人ID/地点ID等）
6. 更新 TODO.md 和 CHANGELOG.md
7. 提交代码，写清楚提交信息

### 发布前测试流程
1. 完整运行"发布前检查清单"
2. 重点测试消息弹窗系统（最容易出bug的地方）
3. 重点测试新增功能
4. 手机端测试（用户主要用手机玩）
5. 确认所有bug都已修复
6. 推送部署
7. 部署后在线验证

### Bug修复流程
1. 复现bug，确认问题
2. 定位根本原因（不要只修表面现象）
3. 修复代码
4. 验证修复有效
5. 检查是否有类似的潜在问题
6. 沉淀经验到本文档
7. 提交修复

## 💡 开发经验总结

### 1. 消息系统是最高风险模块
- 消息系统涉及全局事件监听、状态管理、异步操作，最容易出bug
- 每次修改消息系统都要非常谨慎
- 必须测试连续多条消息的场景
- 必须测试关闭后界面是否正常

### 2. 数据驱动开发要注意数据一致性
- 所有数据都在 data/ 目录下，代码逻辑尽量不动
- 但是添加新数据时要检查引用的ID是否存在
- 任务链、物品掉落、技能学习等都要验证

### 3. 防御性编程很重要
- 不要假设数据一定存在
- 添加类型检查和存在性检查
- 添加安全恢复机制
- 出错时要有降级处理

### 4. 手机端适配不能忽视
- 用户主要用手机玩游戏
- 触屏操作和鼠标操作有差异
- 屏幕尺寸小，布局要适配
- 点击区域要足够大

### 5. 测试要覆盖边界场景
- 不要只测正常流程
- 要测连续操作、快速点击、异常输入等边界场景
- 很多bug只在特定条件下才会出现

### 6. 沉淀经验很重要
- 每个bug都要总结根本原因
- 记录到本文档，避免以后再犯
- 形成可复用的开发规范
- 新人开发前先看本文档
