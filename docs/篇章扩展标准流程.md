# 篇章扩展标准流程（以博城篇为标准模板）

> **总原则**：博城篇是标准范本，后续篇章按本流程自然扩展。所有系统预留扩展接口，新增内容只加数据/配置，不改核心架构。

---

## 总：篇章扩展六步流程

```
小说拆解 → 数据提取 → 标准化添加 → 系统接入 → 测试验证 → 文档沉淀
```

| 步骤 | 做什么 | 产出 |
|------|--------|------|
| 1.拆解 | 逐章精读，提取8维度内容 | 拆解记录文件 |
| 2.提取 | 分类整理，去重，确认原著出处 | 待添加数据清单 |
| 3.添加 | 按数据格式规范写入对应文件 | 技能/妖魔/NPC/地点等数据 |
| 4.接入 | 配置到现有系统（日程/掉落/触发条件/解锁） | 系统配置 |
| 5.测试 | 功能测试+体验测试+回归测试 | 测试报告 |
| 6.文档 | 更新TODO/CHANGELOG/README/拆解进度 | 文档同步 |

**强制规则**：新增数据前必须Grep去重；原著内容标记`isCanon`+出处；设计先对齐再实施。

## 分：各系统扩展点详解

### 一、地图系统

**扩展点**：新增大地图、子地点、地点行动、地图连通性

**在哪里改**：
- `engine/data/locations.js` — 地点数据（大地图+子地点+行动列表）
- `engine/map.js` — 地图渲染逻辑（数据驱动，一般不用改）
- `engine/ui.js` — 地图UI坐标和连线（`renderMapScreen`）

**怎么扩展**：
1. 大地图：在`DataLocations`添加键，配置`id/name/description/mapX/mapY/mapIcon/unlocked`
2. 子地点：在大地图的`actions`数组添加行动项（id/name/icon/timeCost/effects/eventChance/events）
3. 连通性：地图UI中配置地点间连线（坐标自动计算）
4. 解锁条件：`unlockCondition`（等级/flag/剧情节点）

**注意**：一个大地图=一个剧情周期；地点要有明确功能；地点描述含特殊NPC/功能。

---

### 二、战斗系统

#### 2.1 技能

**扩展点**：新系别、新等级、新技能、新状态效果

**在哪里改**：`engine/data/skills.js`

**怎么扩展**：
- 技能格式：`id/name/description/element/type/mpCost/baseDamage/damageMultiplier/hitRate/critRate/targetType/cooldown/tier/statusEffects`
- 等级体系：初阶→中阶→高阶→超阶（tier字段），每级1-3级（skill-level.js管理）
- 状态效果：`statusEffects`数组，支持burn/freeze/stun/slow/buff/debuff等
- 玩家获取：事件addSkill、图书馆learnRandomSkill、NPC传授、修炼解锁

**注意**：同系技能要有差异化（低级低耗高频，高级高耗战略）；新增系别要在`UI.getElementInfo`配置图标/颜色/描述。

#### 2.2 妖魔

**扩展点**：新妖魔、新等级、新技能、新掉落

**在哪里改**：`engine/data/enemies.js`

**怎么扩展**：
- 妖魔格式：`id/name/level/tier/element/hp/attack/defense/speed/skills/drops/exp/gold`
- 等级体系：奴仆级→战将级→统领级→君主级→帝王级
- 技能引用：`skills`数组引用已存在的技能ID（或新增妖魔专属技能，标记`isDemonSkill`）
- 出现地点：locations.js行动中配置遇敌

**注意**：数值与等级匹配；掉落物品必须已存在；妖魔技能不消耗MP。

#### 2.3 战斗机制

**扩展点**：元素反应、状态配合、元素能量、技能冷却

**在哪里改**：`engine/battle.js`
- `calculateDamage` — 伤害计算（含状态配合：冻结×2/燃烧+30%/麻痹暴击+20%）
- `castSkillImmediate` — 技能释放（元素能量积累、冷却设置）
- `elementEnergy` / `skillCooldowns` — 能量和冷却状态

**怎么扩展**：
- 新元素反应：在`calculateDamage`添加状态判定逻辑
- 新战斗机制：在battle.js添加对应状态处理（参考现有状态效果）
- 能量/冷却：已有通用框架，新技能通过`cooldown`字段配置即可

**注意**：战斗机制改动需充分测试平衡；优先用数据配置，少改核心逻辑。

---

### 三、剧情系统

#### 3.1 随机事件

**扩展点**：新事件、新触发条件、新效果类型

**在哪里改**：`engine/data/events.js` + `engine/event.js`

**怎么扩展**：
- 事件格式：`id/name/description/trigger/chance/conditions/once/choices`
- 触发类型：exploring/travel/rest/scheduled
- 选项效果：exp/gold/hp/mp/addItem/addSkill/learnRandomSkill/setFlag/unlockLocation/npcOpinion/startBattle
- 新效果类型：在`event.js`的`applyEffects`添加处理逻辑

**注意**：事件要有实际影响；选项有差异化；符合原著人设。

#### 3.2 大事件

**扩展点**：新剧情篇章、多阶段事件、多分支结局

**在哪里改**：`engine/data/big-events.js` + `engine/big-event.js`

**怎么扩展**：
- 大事件格式：多阶段（phases），每阶段有文本/选项/条件/效果
- 触发：`BigEventSystem.checkAndTrigger()`按条件自动触发
- 分支：选项设置不同flag，后续阶段根据flag走不同路线

**注意**：大事件是剧情关键节点，要有铺垫和收束；玩家选择要有真实影响力。

#### 3.3 任务

**扩展点**：新主线/支线/日常任务、新任务类型

**在哪里改**：`engine/data/quests.js`

**怎么扩展**：
- 任务格式：`id/name/description/type/objectives/rewards/trigger/chain`
- 任务类型：main/side/daily/achievement
- 目标类型：kill/collect/talk/explore/levelup等
- 任务链：`chain`字段配置前置/后续任务

**注意**：任务奖励与难度匹配；日常任务要有明确的"日"定义（游戏内天数）。

---

### 四、NPC系统

#### 4.1 NPC基础数据

**扩展点**：新NPC、新属性、新关系

**在哪里改**：`engine/data/characters.js`

**怎么扩展**：
- NPC格式：`id/name/gender/element/level/personality/description/dialogues/relations`
- 对话：`dialogues`对象，按话题/条件/关系分级
- 关系：`relations`对象，NPC间初始关系值

**注意**：人设不可破坏；对话符合性格和身份；关系变化有事件支撑。

#### 4.2 NPC日程

**扩展点**：新NPC日程、日程变化

**在哪里改**：`engine/game.js`的`_npcSchedules`

**怎么扩展**：
- 日程格式：`morning/afternoon/evening`，每个时段`location/activity/chance`
- 地点必须是已存在的大地图ID
- 所有关键NPC都要有日程（不是只有莫凡）

**注意**：日程符合身份和原著设定；三个时段都要配置。

#### 4.3 NPC状态与关系

**扩展点**：NPC记忆、好感度、信任度、关系网

**在哪里改**：`engine/npc-state.js`（系统逻辑，一般不用改）+ 事件中配置效果

**怎么扩展**：
- 好感度变化：事件效果`npcOpinion: {npcId: value}`
- NPC记忆：对话树的`memoryTags`条件/效果
- 关系网：NPC间关系通过`world.js`或事件动态变化

**注意**：关系提升要有合理事件，不是凭空刷；玩家影响力通过自然行为实现，不搞刻意针对。

#### 4.4 NPC成长

**扩展点**：NPC等级提升、技能解锁、位置迁移

**在哪里改**：`engine/npc-growth.js`

**怎么扩展**：
- 成长节点：`{after: "story_node_id", level: 10, addSkills: [...], addElements: [...]}`
- 触发：剧情节点/flag/玩家等级
- 效果：升级、加技能、加系别、换位置

**注意**：NPC成长符合原著剧情节奏；关键NPC才有成长线。

---

### 五、玩家系统

**扩展点**：新属性、新天赋、新背包格子、新技能槽

**在哪里改**：`engine/player.js`

**怎么扩展**：
- 属性：在`defaultStats`添加新属性，UI同步显示
- 天赋：觉醒时随机选择，在`talents`配置池，效果在对应系统处理
- 技能：`skills`数组，通过`learnSkill`添加
- 背包：`inventory`系统，容量可扩展

**注意**：玩家是主角，不对标莫凡；天赋系统预留进化接口（灵种/魂种）。

---

### 六、物品与经济系统

**扩展点**：新物品、新装备、新商店、新货币

**在哪里改**：
- `engine/data/items.js` — 物品/装备数据
- `engine/data/shops.js` — 商店数据
- `engine/shop.js` — 商店逻辑（一般不用改）

**怎么扩展**：
- 物品格式：`id/name/type/rarity/description/effect/price/sellPrice`
- 装备格式：额外`slot/statBonus/setBonus`
- 商店：`shopId/items`数组（itemId+price+stock）
- 掉落：在enemies.js的`drops`配置

**注意**：经济平衡（金币获取/消耗）；装备等级差异合理；低级装备不浪费（强化/继承/出售）。

---

### 七、UI系统

**扩展点**：新界面、新布局、横竖版适配

**在哪里改**：`engine/ui.js`

**怎么扩展**：
- 新界面：添加`renderXxxScreen`方法，在`game.state`切换时调用
- 横竖版：通过`window.innerWidth > window.innerHeight`判断，CSS媒体查询或JS条件渲染
- 新按钮/面板：在对应render方法中添加HTML

**注意**：UI改动必须同时验证横版和竖版；主界面尽量不滚动；重要信息优先展示；额外信息用悬停/长按。

---

### 八、时间与世界状态系统

**扩展点**：新时段、新日期事件、新势力、新声望

**在哪里改**：
- `engine/game.js` — 时间推进（`advanceTime`）
- `engine/data/world.js` — 势力/声望/世界flag
- `engine/world-state.js` — 世界状态逻辑

**怎么扩展**：
- 时段：morning/afternoon/evening/night（已有），新时段在时间系统添加
- 日期事件：`scheduledEvents`，按游戏内天数触发
- 势力：`factions`对象，声望值变化影响商店/任务/NPC态度
- 世界flag：`setFlag`/`hasFlag`，用于剧情分支判断

**注意**：时间是叙事刻度不是稀缺资源；世界状态变化要有事件支撑。

---

### 九、天赋与进化系统

**扩展点**：新天赋、新灵种/魂种、新进化路线

**在哪里改**：
- 天赋数据 — `engine/data/characters.js`或独立配置
- `engine/player.js` — 天赋效果处理
- 各系统 — 天赋实际生效（如战斗伤害加成）

**怎么扩展**：
- 天赋：觉醒时选择，`id/name/rarity/description/effect`
- 灵种/魂种：特殊天赋，改变系别效果（如千钧雷种）
- 进化：天赋随等级/剧情进化，效果增强

**注意**：天赋要有实际游戏影响；稀有度差异合理；预留进化接口。

---

### 十、Debug与测试系统

**扩展点**：新debug命令、新测试存档、新测试用例

**在哪里改**：
- `engine/debug.js` — debug面板和命令
- `docs/测试用例与发布检查清单.md` — 测试用例
- `docs/测试存档体系与最小单元化测试指南.md` — 测试方法

**怎么扩展**：
- debug命令：在debug.js添加新功能（快速升级/学技能/传送到地点/触发事件）
- 测试存档：关键节点存档，方便快速测试
- 测试用例：新功能对应新增测试项

**注意**：新功能必须在debug中可快速触发；黑盒测试不知道代码逻辑，用debug推进到对应阶段。

## 附：博城篇标准完成度清单

| 类别 | 标准 | 检查点 |
|------|------|--------|
| 战斗 | 各系初阶1-3级技能齐全 | 8大元素系+植物/治愈/召唤 |
| 战斗 | 奴仆级妖魔≥10种 | 覆盖主要出现地点 |
| 战斗 | 战将级妖魔≥2种 | 关键BOSS |
| NPC | 关键NPC≥8人 | 含主角团+重要配角 |
| NPC | 所有关键NPC有日程 | 早/午/晚三时段 |
| NPC | 关键NPC有个人事件链 | 至少1条/人 |
| 地图 | 大地图含≥8子地点 | 每个地点有明确功能 |
| 地图 | 地点连通性正确 | 地图连线合理 |
| 剧情 | 主线完整 | 从觉醒到篇章高潮 |
| 剧情 | 影响力事件≥5个 | 可改变剧情走向 |
| 系统 | 修炼/战斗/社交/经济/时间 | 五大基础系统可用 |
| 文档 | 所有文档同步更新 | TODO/CHANGELOG/README |
