## 二、做得不好的

### 1. 测试策略执行不完整（关键问题）
- **问题**：只跑了自动化测试就提交了，跳过了冒烟测试/Debug验证/功能测试/体验测试
- **原因**：
  - 描述性规范被选择性忽略（AGENTS.md写了"应该做冒烟测试"，但没有硬卡点）
  - 任务优先级偏差：用户说"直接看成品"，内部优先级变成"快速写完代码→跑个自动化交差"
  - 自我评估过于乐观：跑完130个自动化测试后产生"测试很充分"的错觉
- **影响**：用户发现后提醒，才补充了完整测试
- **改进**：已添加"提交前强制检查清单"8项硬卡点，缺一项不允许commit

### 2. 设计文档缺少"测试要点"章节
- **问题**：v3.20.0设计文档没有明确的"测试要点"章节，测试用例是开发完后补的
- **原因**：设计阶段没有把测试左移，还是"开发完再想测试"的老模式
- **改进**：已在硬规则中要求"设计文档必须包含测试要点章节"，以后设计阶段就把测试定下来

### 3. Debug功能没有同步扩展
- **问题**：新增了9种战斗道具，但Debug面板没有"快速获得战斗道具"按钮，测试道具系统不方便
- **原因**：开发时只关注功能实现，没有同步考虑测试支持
- **改进**：已在硬规则中要求"新功能必须在Debug中可快速触发"，以后新增系统同步添加Debug支持

### 4. UI优化没有同步完成
- **问题**：连击数和状态等级在UI上的显示不够明显，玩家可能注意不到
- **原因**：先做了逻辑层，UI层优化放在了"后续"
- **改进**：后续版本补充UI优化，或者在设计阶段就明确UI改动范围

## 三、方法论反馈

### 1. 描述性规范 vs 强制检查清单
- **发现**：描述性的规范（"应该做XX"）会被选择性忽略，特别是在时间紧或任务多的时候
- **改进**：把规范转化为强制检查清单，每次提交前必须逐项打勾，缺一项不允许commit
- **已落地**：AGENTS.md添加"一点五、提交前强制检查清单"，SKILL.md添加"不可跳过的硬规则"

### 2. 测试左移的重要性
- **发现**：开发完再想测试，容易遗漏边界情况，测试用例质量不高
- **改进**：设计阶段就把测试要点定下来（功能用例+体验维度+Debug支持+边界情况），开发完直接照着测
- **已落地**：硬规则3"设计文档必须包含测试要点章节"

### 3. 规范执行审计的必要性
- **发现**：如果不主动报告规范执行情况，容易隐瞒未执行项
- **改进**：每次开发完成后的回复，第一部分必须是"规范执行审计"，明确报告执行了哪些、跳过了哪些、原因是什么
- **已落地**：硬规则5"每次完成后必须报告规范执行审计"

## 四、玩家体验反馈（待实际玩家验证）

v3.20.0的体验测试是代码审查式的，还没有实际玩家验证。以下是待验证的假设：

1. **连击系统爽快感**：连续使用同一系技能，伤害递增是否明显？MP消耗增加是否合理？
2. **状态等级策略性**：玩家是否会主动连续使用同系技能来提升状态等级？
3. **战斗道具多样性**：攻击道具和辅助道具是否有使用场景？还是玩家更倾向于用技能？
4. **战斗评价成就感**：S级评价是否有挑战性？奖励差异是否明显？
5. **组队战斗代入感**：队友使用技能是否增加了配合感？还是队友AI太蠢？

**后续计划**：v3.21.0或v3.22.0版本中，根据实际玩家体验调整数值。

## 六、总结

v3.20.0是一个**功能完成度高，但测试执行有缺陷**的版本。

- **功能层面**：6个丰富方向全部完成，代码质量好，自动化测试全通过
- **流程层面**：测试策略执行不完整，暴露了描述性规范被忽略的问题
- **方法论层面**：发现了3个关键改进点（强制检查清单/测试左移/规范执行审计），已全部落地

**最大的收获**：不是战斗系统丰富化本身，而是发现了"规范为什么会被忽略"这个深层问题，并建立了不可跳过的执行机制。这个机制将让后续所有版本的质量更有保障。
