# 大事件系统设计方案

> 完善现有的定时大事件系统，支持多阶段、分支选择、影响世界状态、多个结局等高级功能。
> 最后更新：2026-08-11

---

## 一、设计目标

1. **多阶段事件**：一个大事件可以有多个阶段，逐步推进
2. **分支选择**：玩家的选择会影响事件走向和结局
3. **世界状态影响**：事件会改变世界状态、NPC关系、势力声望等
4. **条件触发**：根据玩家等级、属性、任务进度、世界状态等条件触发不同分支
5. **多个结局**：每个大事件可以有多个结局，根据玩家的选择和属性决定
6. **连锁事件**：一个大事件的结果会影响后续的大事件
7. **向后兼容**：现有的简单大事件（入学考核等）继续可用，不需要修改

### 2.2 阶段结构

每个阶段可以有：
- 剧情文本
- 选项（可选）
- 自动判定（根据属性/条件）
- 战斗（可选）
- 效果（属性、物品、声望、世界状态等）

```javascript
{
    id: "phase_1_warning",
    name: "妖魔异动",
    description: "最近雪峰山的妖魔活动异常频繁...",
    type: "narrative", // narrative/choice/battle/auto
    // 选择型阶段的选项
    choices: [
        {
            text: "去调查一下",
            nextPhase: "phase_2_investigate",
            conditions: {
                minLevel: 6
            },
            effects: {
                reputation: {
                    "military": 5
                }
            }
        },
        {
            text: "告诉老师",
            nextPhase: "phase_2_report",
            effects: {
                reputation: {
                    "school": 10
                }
            }
        },
        {
            text: "不管它，继续修炼",
            nextPhase: "phase_2_ignore",
            effects: {}
        }
    ],
    // 自动判定型阶段的判定规则
    autoCheck: {
        attribute: "level",
        thresholds: [
            { value: 7, nextPhase: "phase_2_strong" },
            { value: 5, nextPhase: "phase_2_normal" },
            { value: 0, nextPhase: "phase_2_weak" }
        ]
    },
    // 战斗型阶段的敌人
    battle: {
        enemyId: "demon_general",
        winPhase: "phase_3_win",
        losePhase: "phase_3_lose"
    },
    // 阶段效果（进入阶段时立即应用）
    effects: {
        exp: 100,
        gold: 50,
        items: [
            { itemId: "health_potion", count: 3 }
        ],
        worldState: {
            "demon_threat_level": "high"
        },
        npcRelation: {
            "mo_fan": 10
        },
        flags: {
            "bocheng_warning_known": true
        }
    },
    // 是否是结局阶段
    isEnding: false,
    endingId: null
}
```

## 三、系统功能设计

### 3.1 事件触发

1. **定时触发**：到达指定天数自动触发
2. **条件触发**：满足条件时触发（任务完成、物品获得、世界状态变化等）
3. **手动触发**：通过NPC对话、地点行动等手动触发

### 3.2 事件推进

1. **按阶段推进**：从第一阶段开始，根据玩家选择或自动判定进入下一阶段
2. **分支选择**：玩家选择不同选项进入不同分支
3. **属性判定**：根据玩家属性自动判定结果
4. **战斗判定**：通过战斗决定下一阶段
5. **结局判定**：到达结局阶段后，显示结局并应用奖励

### 3.3 状态保存

大事件的状态保存在玩家存档中：
```javascript
player.scheduledEventState = {
    currentEventId: "event_bocheng_disaster",
    currentPhaseId: "phase_2_investigate",
    choicesMade: ["choice_1", "choice_3"],
    flags: {
        "saved_xiaohou": true
    },
    startTime: 45,
    currentDay: 47
}
```

### 3.4 事件界面

1. **剧情界面**：显示剧情文本，带选项按钮
2. **战斗界面**：进入战斗
3. **结局界面**：显示结局和奖励
4. **事件回顾**：可以查看已经经历的事件阶段

## 六、与其他系统的交互

1. **时间系统**：大事件按天推进，可能跨越多天
2. **战斗系统**：战斗型阶段调用战斗系统
3. **任务系统**：大事件可以触发任务，任务也可以触发大事件
4. **世界状态系统**：大事件改变世界状态，世界状态也影响大事件
5. **NPC系统**：大事件影响NPC关系，NPC关系也影响大事件选项
6. **声望系统**：大事件影响势力声望，声望也影响大事件选项
7. **成就系统**：大事件结局可以解锁成就（待实现）

---

## 七、设计原则

1. **玩家选择有意义**：每个选择都要有实际影响，不是摆设
2. **属性有价值**：玩家的属性点、技能选择会影响事件结果
3. **多周目可玩性**：不同的选择会有不同的结局，鼓励多周目
4. **难度适中**：不会因为选错一个选项就彻底完蛋，但会有不同的体验
5. **剧情连贯**：大事件的剧情要和小说原著保持一致
6. **渐进式实现**：先做基础框架，再逐步添加高级功能
