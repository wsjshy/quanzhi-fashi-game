# 玩家影响力系统设计

> 版本：v0.19.0 核心系统设计
> 日期：2026-08-15
> 定位：这是游戏的核心差异化系统——玩家不是莫凡的跟班，而是能真正改变剧情走向的独立主角

---

## 一、设计背景与方向校准

### 问题
之前的"恋爱系统"方向偏差。穆宁雪谈恋爱只是用户举例说明"玩家要有真实影响力"，并非真的要做恋爱游戏。约会系统中"邀请穆宁雪去雪峰山看日落"不符合其高冷天才的人设。

### 核心需求重新定义
**玩家有真实影响力 = 玩家的行动和选择能改变原著的剧情走向、NPC命运和势力格局。**

不是：和NPC谈恋爱
而是：
- 争夺原著中莫凡的机缘（地圣泉、魂种、传承）
- 干预NPC的命运（警告危险、拯救生命）
- 影响NPC之间的关系（调解矛盾、改变立场）
- 在大事件中做出不同于原著的选择，改变结局

### 人设原则
- 穆宁雪：高冷冰系天才，外冷内热，不会轻易和人"约会"。与玩家的关系提升应通过"修炼请教"、"家族事务"、"共同经历危机"等符合人设的方式
- 莫凡：桀骜不驯的双系天才，是玩家的同学/竞争者/潜在盟友，有自己的行动线
- 所有NPC的互动方式必须符合其人设，不能通用化

## 二、影响力系统核心框架

### 2.1 影响力点数（Influence Points）
- 玩家通过完成任务、帮助NPC、关键选择获得影响力点数
- 影响力是玩家"改变剧情"的资源基础
- 高影响力解锁更多剧情分支选项

### 2.2 影响力维度
影响力不是单一数值，分多个维度：
- **个人影响力**：与关键NPC的关系总和（好感+信任+熟悉）
- **势力声望**：在各势力（学校、猎法师协会、穆氏家族、军方）的声望
- **事迹影响力**：完成的关键事件、拯救的人数、改变的剧情节点

### 2.3 剧情节点干预机制
在关键剧情节点，系统检查玩家的影响力条件：
- 满足条件 → 出现"干预选项"，玩家可以做出不同于原著的选择
- 不满足 → 按原著剧情发展
- 干预成功 → 剧情分支改变，后续剧情相应调整
- 干预失败 → 有惩罚（NPC受伤/死亡、势力关系恶化等）

## 三、短期实装功能（v0.19.0）

### 3.1 莫凡机缘竞争系统（核心）

**设计思路**：原著中莫凡获得的关键机缘，玩家可以竞争。这是最直接的"改变剧情"体现。

**第一个可竞争机缘：地圣泉修炼机会**
- 原著：莫凡通过唐月老师获得地圣泉修炼机会，实力大幅提升
- 玩家竞争条件：
  - 等级≥5
  - 与唐月信任度≥30
  - 学校声望≥20
- 竞争方式：
  - 唐月提出地圣泉机会时，如果玩家满足条件，出现"我也想去地圣泉修炼"选项
  - 玩家与莫凡竞争（考核/比试/唐月选择）
  - 玩家成功 → 玩家获得地圣泉修炼，莫凡走替代路线（去其他地方修炼）
  - 玩家失败 → 莫凡获得，按原著发展
- 影响：
  - 玩家获得地圣泉修炼的属性加成
  - 莫凡的成长路线改变，后续与莫凡的互动相应调整
  - 唐月对玩家的态度变化

**后续可竞争机缘（中期）**：
- 三步塔修炼名额
- 猎法师协会特殊任务
- 魂种/灵种发现
- 特殊传承（恶魔系、暗影系等）

### 3.1.2 影响力事件库（持续扩充）

#### 事件2：宇昂决斗的替代方案（v0.19.1）
- **原著**：穆卓云安排玩家在宇昂成年礼上决斗，胜者获得地圣泉机会
- **影响力分支**：如果玩家与穆宁雪信任≥40，可请穆宁雪向穆卓云求情
  - 选择A：按原著决斗（击败宇昂，获得通行证）
  - 选择B：请穆宁雪调解（穆卓云改为考核制，不用死斗，但需要通过三项测试）
  - 选择C：直接放弃（宇昂获胜，玩家错失地圣泉，但穆宁雪好感+20）
- **影响**：选择B避免了与宇昂的死斗，宇昂存活可能在后续剧情中出现；选择C改变了地圣泉归属

#### 事件3：唐月的秘密指导（v0.19.1）
- **原著**：唐月暗中指导莫凡，给他开小灶
- **影响力分支**：如果玩家与唐月信任≥50，唐月会主动提出给玩家特殊指导
  - 接受：获得1个技能点+随机属性+5，莫凡好感-5（少了一次机缘）
  - 拒绝：唐月好感+10，莫凡好感+5（让给莫凡）
- **触发**：与唐月对话时随机触发（信任≥50时20%概率）

#### 事件4：雪峰山妖魔异动预警（v0.20.0前置）
- **原著**：博城灾难前妖魔异动未被及时重视
- **影响力分支**：玩家在雪峰山探索时有概率发现妖魔异常聚集
  - 报告军方：军方声望+15，博城灾难时防御增强（减少损失）
  - 报告学校：学校声望+10，学校提前组织疏散
  - 不报告：按原著发展，灾难损失更大
- **影响**：直接影响v0.21.0博城灾难分支的结果

#### 事件5：穆宁雪的家族压力（v0.20.0）
- **原著**：穆宁雪承受穆氏家族的压力，与莫凡关系复杂
- **影响力分支**：与穆宁雪信任≥50时，她会倾诉家族压力
  - 帮她想办法：穆宁雪信任+15，可能解锁穆氏家族线
  - 倾听安慰：穆宁雪好感+10
  - 建议她反抗家族：穆宁雪好感+5但穆氏家族声望-20

#### 事件6：三步塔修炼名额竞争（v0.22.0）
- **原著**：莫凡获得三步塔特殊修炼名额
- **影响力分支**：学校考核中玩家成绩优异时可竞争名额
- 类似地圣泉机制

### 3.2 社交互动系统（重构约会系统）

**将"约会系统"重构为"深度社交互动"**，每个NPC的互动方式符合其人设：

**穆宁雪的互动选项**（非约会）：
- 请教冰系魔法（需要好感≥10，获得冰系经验+好感）
- 一起修炼（需要好感≥30，在三步塔/修炼场共同修炼，获得经验+信任）
- 讨论家族事务（需要信任≥40，了解穆氏家族内情，影响后续家族线）
- 共同执行任务（需要好感≥50，一起猎魔/完成任务，大幅提升关系）

**通用互动框架**：
- 每个NPC有自己的互动选项列表，符合其人设
- 互动需要达到一定关系等级解锁
- 互动是提升关系的手段，关系是影响力的基础
- 移除"约会"、"告白"、"is_lover"等恋爱导向内容

### 3.3 影响力UI
- 角色面板新增"影响力"标签页
- 显示：个人影响力、各势力声望、已改变的剧情节点
- 剧情节点显示"原著走向"vs"当前走向"对比

## 四、中期功能（v0.20.0-v0.22.0）

### 4.1 NPC命运预警系统
- 在NPC遭遇危险前，如果玩家与该NPC关系足够好（信任≥50），可以提前警告
- 示例：博城灾难前，警告特定NPC撤离，改变其命运
- 警告成功 → NPC存活，后续剧情中该NPC继续存在并可能帮助玩家
- 警告失败 → NPC不信，按原著发展（可能死亡）

### 4.2 博城灾难分支
- 玩家在博城灾难中的行动改变死亡人数和破坏程度
- 高影响力玩家可以组织撤离、拯救关键NPC
- 不同的灾难结果影响后续剧情（如穆氏家族态度、猎法师协会评价）

### 4.3 关系调解系统
- 高影响力时可以调解NPC之间的矛盾
- 示例：调解穆宁雪和莫凡的矛盾（需要双方好感都高）
- 调解成功 → NPC之间关系改善，可能解锁联合任务
- 调解失败 → 关系恶化，可能影响玩家与双方的关系

### 4.4 莫凡平行故事线
- 莫凡有自己的修炼/任务/人际关系，不受玩家直接控制
- 玩家可以影响莫凡（竞争机缘、合作任务、调解矛盾）
- 莫凡的成长路线因玩家干预而改变

## 七、人设检查清单

每个NPC的互动选项必须通过以下检查：
- [ ] 符合该NPC的性格设定（高冷的不会主动热情，傲慢的不会低声下气）
- [ ] 符合该NPC的身份（学生/老师/家族成员/猎人）
- [ ] 关系提升有合理的事件支撑，不是凭空刷好感
- [ ] 没有恋爱导向的内容（除非该NPC人设本身如此，且用户明确要求）
- [ ] 互动结果对剧情有实际影响，不只是数值变化

## 八、方向二次校准：分支-瓶颈叙事架构（v0.20.0+ 核心重构）

> 2026-08-15 基于行业研究（博德之门3、极乐迪斯科、辐射新维加斯）重新校准

### 8.1 问题诊断

当前v0.19.0的"影响力事件"本质是**玩家替换莫凡体验原著剧情**——抢地圣泉、抢唐月指导、改决斗规则。这仍然是在复刻莫凡的剧情线，只是换了个人。

**真正的影响力不是"我来当莫凡"，而是"我的选择让剧情走向原著没有的方向"。**

### 8.2 行业最佳实践：Branch-and-Bottleneck（分支-瓶颈结构）

博德之门3、极乐迪斯科、辐射新维加斯都采用此架构：
- **瓶颈（Bottleneck）**：大事件必然发生（博城灾难、宇昂决斗、地圣泉开启）
- **分支（Branch）**：玩家在瓶颈之间的选择以多种形式影响瓶颈的表现和结果
- **汇合（Convergence）**：分支后重新汇合到主线，但**保留每条路径的独特痕迹**

关键原则（来自黑曜石Josh Sawyer GDC讲座）：
1. **选择表达角色，不是表达剧情**——好的选择问"你是谁"，不是"接下来发生什么"
2. **延迟后果**——选择的回报在三个场景后到来，不是下一行
3. **反应分层**——低成本（一句NPC反馈）/中成本（任务变化）/高成本（NPC生死）/超高成本（阵营结局）
4. **信息节点而非流程节点**——每个任务节点提供信息和表达机会，不只是"到A点打B"
5. **NPC记忆**——重要NPC记得玩家的关键选择

### 8.3 我们的重构方案

#### 架构1：NPC记忆系统（核心基础）
- 每个重要NPC有`memoryTags`数组，记录玩家的关键行为
- 后续对话中引用记忆（"你上次帮了我..."、"我还记得你说过..."）
- 记忆影响NPC态度和可用选项
- 示例：玩家嘲笑过莫凡→`mo_fan_teased=true`→后续莫凡对话语气变化→决斗时莫凡可能帮玩家或坑玩家

#### 架构2：高密度小分支（替代3个大事件）
- 不在3个大事件上做分支，而是在每个对话/任务中加2-3个小分支
- 小分支设置flag，flag在后续事件中重新组合
- 示例：和王老板聊天时选择"打听宇昂"→`knows_yu_ang_plot=true`→决斗前有"揭穿阴谋"选项

#### 架构3：信息差系统
- 不同选择获得不同信息
- 信息影响后续选项可用性
- 信息有多个来源，避免单点断链

#### 架构4：莫凡自主行动线（非"玩家替换莫凡"）
- 莫凡有自己的日程、修炼、人际关系，独立于玩家
- 玩家可以影响莫凡（帮他/坑他/竞争/合作），但不是"抢他的机缘"
- 莫凡的行动因玩家影响而改变，创造原著没有的剧情

### 8.4 v0.20.0 实施计划

#### 核心1：NPC记忆系统
- `npc-state.js`新增`memoryTags`字段和`addMemory`/`hasMemory`方法
- 对话树支持`memoryTag`条件和效果
- 为莫凡、穆宁雪、唐月添加5-8条记忆触发

#### 核心2：高密度小分支示范
- 莫凡对话树新增3个小分支（嘲笑/鼓励/请教），每个设置不同memoryTag
- 宇昂决斗前根据memoryTag和信息flag出现不同选项
- 唐月对话根据玩家是否帮过莫凡有不同反应

#### 核心3：信息差示范
- 王老板处新增"打听宇昂"选项，获得`knows_yu_ang_plot`
- 决斗前如果有此信息，可选择"当众揭穿"（非战斗解决）

### 8.5 与v0.19.0的关系

v0.19.0的3个影响力事件（地圣泉/决斗/唐月指导）**保留但重新定位**：
- 它们是"瓶颈事件"的分支选项，不是全部
- v0.20.0在它们之间填充高密度小分支和NPC记忆
- 最终体验：玩家不是在3个节点做选择，而是在整个游戏过程中持续感受到世界在回应自己

## 九、NPC关系网络系统（v0.21.0+ 核心架构）

> 2026-08-15 基于社交物理引擎（Social Physics Engine）和Crosston Tavern研究

### 9.1 核心洞察

玩家的影响力不只是"玩家-NPC"关系，还会改变**NPC之间的关系网络**。

**举例**：玩家和穆宁雪关系加深 → 穆宁雪对莫凡的态度变化 → 穆宁雪和莫凡不会发展原著中的恋爱关系 → 后续剧情完全不同。

这才是真正的"世界在回应你"——你改变了整个社交网络的结构，而不只是你和某个NPC的关系。

### 9.2 理论基础：社交物理引擎

来自学术研究（Social Physics Engines in Games）：
- **关系是有向图**：A对B的态度 ≠ B对A的态度
- **关系传播**：社交事件影响当事人，再扩散到旁观者
- **小团体涌现**：关系紧密的NPC自然抱团，不是设计的而是演化的
- **玩家间接影响**：玩家通过对话告诉A关于B的事，改变A对B的看法

来自Crosston Tavern（AAAI论文）：
- 玩家可以操纵NPC之间的关系（撮合/拆散/挑拨）
- 玩家给NPC设定目标，间接影响NPC行为
- 核心玩法不是"我和NPC关系好"，而是"我改变了NPC之间的关系"

### 9.3 系统设计

#### 架构1：NPC-NPC有向关系图

每个NPC对其他NPC有独立的opinion/trust：
```js
// npc-state.js 扩展
npcRelationships: {
  mu_ningxue: {
    mo_fan: { opinion: -15, trust: 0, type: "complicated" },  // 穆宁雪对莫凡
    tang_yue: { opinion: 20, trust: 25, type: "acquaintance" },
    player: { opinion: -10, trust: 0, type: "complicated" }  // 对玩家
  },
  mo_fan: {
    mu_ningxue: { opinion: 30, trust: 10, type: "crush" },  // 莫凡对穆宁雪（原著暗恋）
    player: { opinion: 0, trust: 0, type: "classmate" }
  }
}
```

#### 架构2：玩家行为影响NPC-NPC关系

触发场景：
1. **玩家和A关系好** → A对玩家的朋友/敌人态度变化
   - 玩家和穆宁雪信任≥50 → 穆宁雪对莫凡的opinion -10（因为更关注玩家了）
2. **玩家告诉A关于B的事** → A对B的看法改变
   - 玩家告诉莫凡"穆宁雪说你坏话" → 莫凡对穆宁雪opinion -15
3. **社交事件传播** → 旁观者态度变化
   - 玩家在公共场合帮莫凡说话 → 在场NPC对莫凡opinion +5
4. **玩家撮合/拆散** → 直接改变NPC-NPC关系
   - 高影响力时可选择"帮莫凡追穆宁雪"或"挑拨他们关系"

#### 架构3：关系驱动的剧情分支

NPC-NPC关系达到阈值时触发剧情变化：
- 穆宁雪对莫凡opinion < 0 → 不会发展恋爱关系 → 原著中"穆宁雪帮莫凡"的事件不会发生
- 莫凡对穆宁雪opinion > 80 → 莫凡会主动追求 → 新剧情线
- 唐月和莫凡关系好 → 唐月会给莫凡更多指导 → 莫凡成长更快 → 竞争更激烈

### 9.4 第一个实装：穆宁雪-莫凡关系动态

**原著设定**：莫凡暗恋穆宁雪，穆宁雪对莫凡态度复杂（青梅竹马+家族矛盾）。

**玩家影响路径**：
1. 玩家和穆宁雪信任≥50 → 穆宁雪对莫凡opinion -10（注意力转移到玩家）
2. 玩家在穆宁雪面前说莫凡好话/坏话 → 穆宁雪对莫凡opinion ±15
3. 玩家帮莫凡追穆宁雪 → 莫凡对玩家opinion +20，穆宁雪对莫凡opinion +10
4. 玩家挑拨离间 → 双方关系恶化

**剧情后果**：
- 穆宁雪对莫凡opinion < 0 → 博城灾难中穆宁雪不会帮莫凡 → 莫凡可能受伤/死亡 → 重大剧情分支
- 穆宁雪对莫凡opinion > 50 → 按原著发展恋爱线

## 十、小说拆解方法论升级（v0.21.0+）

### 10.1 问题

之前的小说拆解只记录"发生了什么"，没有记录**因果关系**和**分支可能性**。这导致设计影响力事件时只能"替换主角体验剧情"，而不是"创造新剧情"。

### 10.2 新拆解模板

每章小说拆解时，必须记录以下维度：

#### 维度1：剧情节点（What happened）
- 事件名称、参与NPC、地点、时间
- 事件的直接结果

#### 维度2：因果链（Why it happened）
- 这个事件是由什么前置事件导致的？
- 哪些NPC的关系/选择导致了这个结果？
- 如果某个前置条件不同，事件会怎么变？

#### 维度3：关系依赖（Relationship dependencies）
- 这个事件依赖哪些NPC之间的关系？
- 如果A对B的态度不同，事件会怎么发展？
- 玩家可以通过改变哪些关系来影响这个事件？

#### 维度4：分支点（Branch points）
- 在这个事件中，玩家有哪些可能的干预方式？
- 每种干预会导致什么替代结果？
- 替代结果对后续剧情有什么连锁影响？

#### 维度5：NPC动机（NPC motivations）
- 每个参与NPC的目标是什么？
- 什么会改变他们的选择？
- 玩家可以如何利用这些动机？

### 10.3 示例：博城灾难拆解

**旧方式**：博城发生妖魔袭击，莫凡拯救了很多人。

**新方式**：
- **因果链**：雪峰山妖魔异动 → 军方未重视 → 妖魔大规模入侵 → 博城被围
- **关系依赖**：唐月信任玩家 → 玩家提前知道异动 → 可提前预警
- **分支点**：
  - 玩家提前报告军方 → 军方准备充分 → 死亡人数减少50%
  - 玩家组织同学撤离 → 学校伤亡减少
  - 玩家和穆宁雪关系好 → 穆宁雪加入玩家的救援行动
  - 玩家挑拨穆宁雪和莫凡 → 莫凡分心 → 救援效率降低
- **NPC动机**：莫凡想救心夏、穆宁雪想保护家族、唐月想保护学生

### 10.4 拆解工具升级

在现有的小说拆解文档中，每章添加以下结构化字段：
```
## 第X章 标题
### 剧情摘要
### 因果链（前置→事件→后果）
### 参与NPC及动机
### 关系依赖（哪些NPC关系影响此事件）
### 玩家可干预点（3-5个）
### 替代结果（每种干预的后果）
### 对后续章节的影响
```
