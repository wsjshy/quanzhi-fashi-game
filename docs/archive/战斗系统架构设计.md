# 战斗系统架构设计

## 设计理念

**可扩展 + 解耦 + 数据驱动**，战斗系统是游戏的核心，必须保证：
- 新增效果类型不需要改主逻辑
- 新增系统不需要改战斗代码
- 所有内容都可以通过数据配置
- 跟着小说逐步扩充，不设上限

---

## 整体架构

战斗系统采用**三层架构**：

```
┌─────────────────────────────────────────┐
│           内容数据层（最灵活）           │
│  妖魔数据 / 技能数据 / 天赋数据 / 物品数据  │
│  纯数据，新增只需要加 JSON               │
├─────────────────────────────────────────┤
│           效果类型层（逐步扩充）         │
│  效果注册表 / 状态效果 / 天赋效果类型     │
│  模块化新增，每个效果类型独立             │
├─────────────────────────────────────────┤
│           基础框架层（最稳定）           │
│  回合逻辑 / 伤害计算 / 事件总线 / AI框架  │
│  一次写好，永久复用                      │
└─────────────────────────────────────────┘
```

---

## 核心模块

### 1. 战斗主逻辑（battle.js）
- 回合制战斗流程
- 伤害计算基础
- 玩家行动处理
- 敌人行动处理
- 战斗状态管理

### 2. 战斗AI（battle-ai.js）
- 基于Utility AI（效用系统）
- 6种AI类型：激进、保守、控制、爆发、游击、战术
- 给每个可能的行动打分，选择分数最高的执行
- 评分因素：自身状态、对手状态、技能效果、元素克制、冷却、MP消耗

### 3. 效果注册表（battle-effect.js）
- 统一的效果类型注册机制
- 每个效果类型有独立的处理器
- 新增效果类型只需要注册处理器
- 支持多触发时机

### 4. 事件总线（battle-event.js）
- 发布/订阅模式
- 系统间通过事件通信，不直接调用
- 新增系统只需要订阅事件
- 战斗逻辑和其他系统完全解耦

## 效果注册表（Effect Registry）

### 设计思想

所有效果（天赋效果、技能效果、状态效果、物品效果等）都统一注册到效果注册表，每个效果类型有独立的处理器。

**好处：**
- 新增效果类型不需要改战斗主逻辑
- 代码更清晰，每个效果类型独立维护
- 更容易测试和调试
- 可扩展性极强

### 效果处理器接口

```javascript
{
    name: "效果名称",
    description: "效果描述",
    
    // 被动属性加成（可选）
    getPassiveBonuses(effect) {
        return { attack: 10, defense: 5 };
    },
    
    // 攻击前触发（可选）
    onBeforeAttack(effect, context) { ... },
    
    // 攻击命中时触发（可选）
    onHit(effect, context) { ... },
    
    // 受击前触发（可选）
    onBeforeHit(effect, context) { ... },
    
    // 受击后触发（可选）
    onAfterHit(effect, context) { ... },
    
    // 回合开始时触发（可选）
    onTurnStart(effect, context) { ... },
    
    // 回合结束时触发（可选）
    onTurnEnd(effect, context) { ... },
    
    // 首次攻击触发（可选）
    onFirstAttack(effect, context) { ... },
    
    // 战斗开始时触发（可选）
    onBattleStart(effect, context) { ... },
    
    // 战斗结束时触发（可选）
    onBattleEnd(effect, context) { ... }
}
```

### 已注册的效果类型（共19种）

**基础属性类（7种）：**
- attack_bonus - 攻击加成
- defense_bonus - 防御加成
- speed_bonus - 速度加成
- hp_bonus - 生命加成
- dodge_bonus - 闪避加成
- hit_bonus - 命中加成
- all_stats_bonus - 全属性加成

**元素类（2种）：**
- element_damage_bonus - 元素伤害加成（通用，支持8种元素）
- element_resistance - 元素抗性（通用，支持8种元素）

**伤害减免类（2种）：**
- physical_damage_reduction - 物理伤害减免
- magic_damage_reduction - 魔法伤害减免

**特殊效果类（8种）：**
- damage_reflect - 伤害反弹
- blood_rage - 血怒（血量越低攻击越高）
- regeneration - 再生（回合结束恢复HP）
- first_strike_crit - 首次攻击必定暴击
- bleed_on_hit - 攻击流血
- poison_on_hit - 攻击中毒
- control_immunity - 控制免疫
- multi_strike - 多段攻击

**待补充的效果类型：**
- 元素弱点
- 攻击减速
- 攻击冰冻
- 攻击眩晕
- 攻击致盲
- 攻击束缚

### 使用方式

```javascript
// 注册效果类型
EffectRegistry.register('my_effect', {
    name: '我的效果',
    description: '效果描述',
    getPassiveBonuses(effect) {
        return { attack: effect.value };
    }
});

// 计算被动加成
const bonuses = EffectRegistry.calculatePassiveBonuses(effects);

// 触发某个时机的效果
EffectRegistry.trigger('onHit', effects, context);
```

## 事件总线（Event Bus）

### 设计思想

战斗中的各种事件都通过事件总线发布，各个系统（天赋、成就、灵魂、任务等）通过订阅事件来响应，系统间不直接调用。

**好处：**
- 系统间完全解耦
- 新增系统不需要改战斗代码
- 事件可以被多个系统同时订阅
- 更容易调试和追踪

### 标准事件类型

**战斗生命周期：**
- battleStart - 战斗开始
- battleEnd - 战斗结束
- turnStart - 回合开始
- turnEnd - 回合结束

**攻击相关：**
- playerAttack - 玩家攻击
- enemyAttack - 敌人攻击
- hit - 命中
- crit - 暴击
- miss - 闪避
- damage - 受到伤害

**技能相关：**
- skillCast - 技能释放
- skillChannel - 技能引导
- skillComplete - 技能完成
- interrupt - 打断

**状态相关：**
- statusApplied - 状态施加
- statusRemoved - 状态移除

**其他行动：**
- defend - 防御
- heal - 治疗
- flee - 逃跑
- summon - 召唤

**死亡：**
- playerDeath - 玩家死亡
- enemyDeath - 敌人死亡

**成长：**
- expGain - 获得经验
- levelUp - 升级

**成就：**
- achievement - 成就解锁

**掉落：**
- dropItem - 物品掉落
- dropSoul - 残魄/精魄掉落

### 已接入的事件（共20个核心事件）

**战斗生命周期：**
- battleStart - 战斗开始 ✅

**召唤：**

### 使用方式

```javascript
// 订阅事件
BattleEventBus.on(BattleEvents.BATTLE_END, (data) => {
    console.log('战斗结束', data);
});

// 订阅一次性事件
BattleEventBus.once(BattleEvents.PLAYER_ATTACK, (data) => {
    console.log('玩家第一次攻击', data);
});

// 发布事件
BattleEventBus.emit(BattleEvents.PLAYER_ATTACK, {
    damage: 100,
    isCrit: true,
    isMiss: false
});

// 取消订阅
BattleEventBus.off(BattleEvents.BATTLE_END, handler);
```

## AI系统（Utility AI）

### 设计思想

基于效用系统（Utility AI），给每个可能的行动打分，选择分数最高的执行。

**好处：**
- AI行为更智能，会根据情况调整策略
- 不同类型的妖魔有不同的行为模式
- 可扩展性强，新增AI类型只需要加配置

### AI类型

1. **aggressive（激进型）** - 全力输出，不顾防御
2. **defensive（保守型）** - 懂得自我保护，血量低时优先防御/治疗
3. **controller（控制型）** - 优先控制敌人，再进行输出
4. **burst（爆发型）** - 积攒资源，寻找机会一波爆发
5. **kiter（游击型）** - 打一下防御一下，风筝对手
6. **tactical（战术型）** - 最智能，会根据玩家状态调整策略

### 评分因素

- 自身状态（HP、MP、buff/debuff）
- 对手状态（HP、MP、buff/debuff）
- 技能效果（伤害、治疗、控制）
- 技能冷却
- 元素克制
- 生存压力

## 可扩展性设计

### 新增妖魔
1. 在 enemies.js 里加数据
2. 配置技能、天赋、AI类型
3. 不需要改代码 ✅

### 新增技能
1. 在 skills.js 里加数据
2. 配置伤害、效果、冷却等
3. 如果是新的效果类型，在效果注册表注册处理器
4. 大部分情况不需要改代码 ✅

### 新增天赋效果
1. 如果是已有效果类型，直接加数据
2. 如果是新效果类型，在效果注册表注册处理器
3. 不需要改战斗主逻辑 ✅

### 新增系统（成就、任务、灵魂等）
1. 订阅需要的事件
2. 在事件处理函数里实现逻辑
3. 不需要改战斗代码 ✅

## 小说驱动式开发

战斗系统的开发遵循**小说驱动式开发**原则：

1. **看到一个加一个** - 不是固定一卷加多少，而是小说里看到一个就加一个
2. **已经拆解的不用重头来** - 单独找到对应位置补充数据即可
3. **可扩充性是核心标准** - 所有系统都要是可扩充的
4. **不要固化** - 不要把机制写死，要留扩展空间

**开发流程：**
```
拆解小说章节
    ↓
发现新内容（妖魔/魔法/天赋/机制）
    ↓
检查现有效果类型能不能实现？
    ├─ 能 → 直接加数据 ✅
    └─ 不能 → 新增效果类型（写代码）→ 然后加数据
```
