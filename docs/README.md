# 文档总览

> 本文档是docs/目录的入口。所有文档按职责分类，各司其职。
> 项目总入口见 [AGENTS.md](../AGENTS.md)。

## 目录结构

```
docs/
├── README.md                        # 本文件（文档总览）
├── 方法论文档（活跃，根目录）        # 怎么做——开发流程、规范、指南
├── 核心设计文档（活跃，根目录）      # 是什么——系统架构、设计方案
├── version-design/                 # 版本设计文档（按版本归档）
├── test-reports/                   # 测试报告（黑盒测试、回归测试）
├── reference/                      # 参考资料（攻略、规划、状态记录）
├── 小说拆解/                        # 小说逐章拆解内容
└── archive/                        # 废弃文档（保留历史，不删除）
```

## 其他目录

- **version-design/** - 各版本的设计文档（v0.48.0_*.md等），按版本归档，开发完成后不再修改
- **test-reports/** - 所有黑盒测试报告、回归测试报告，命名格式：`黑盒测试报告_vX.Y.Z_描述.md`
- **reference/** - 攻略、规划、状态记录等参考资料
- **小说拆解/** - 小说逐章拆解内容
- **archive/** - 废弃文档，保留历史不删除

## 文档维护规则

### 1. 何时必须更新文档

| 开发动作 | 必须更新的文档 |
|---------|--------------|
| 新增数据字段/格式变化 | 数据格式规范.md |
| 新增系统/机制 | 对应核心设计文档 + version-design/新版本设计 |
| 测试方法改进 | 测试方法论.md + 测试工具文档 |
| 新增功能测试点 | 测试用例与发布检查清单.md |
| 遇到新坑并解决 | 开发踩坑记录与通用经验.md |
| 部署流程变化 | 部署经验总结.md |
| 版本发布 | CHANGELOG.md + AGENTS.md版本号 + ui.js标题 + README.md |

### 2. 文档生命周期

- **活跃文档**（根目录的方法论+核心设计）：持续维护，每次相关变更时更新
- **版本设计文档**（version-design/）：开发完成后归档，不再修改
- **测试报告**（test-reports/）：一次性产物，写完后归档
- **参考资料**（reference/）：定期审查，过时的移到archive/
- **废弃文档**（archive/）：保留历史，不删除

### 3. 文档审计

每完成一个大版本（如v1.0），执行一次文档审计：
1. 检查活跃文档是否与当前代码一致
2. 将过时的参考资料移到archive/
3. 更新AGENTS.md的文档导航
4. 清理重复文档
