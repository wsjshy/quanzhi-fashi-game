# 非战斗系统可扩展性设计文档

> 本文档定义全职法师网页游戏非战斗系统的数据驱动架构和扩展方式。
> 所有非战斗内容（NPC、地点、任务、事件、商店等）通过数据文件配置，不硬编码逻辑。
> 新增内容只需添加数据，无需修改引擎代码。

---

## 一、设计原则

### 1.1 数据驱动
所有非战斗内容通过数据文件定义。引擎只负责解析数据和执行通用逻辑。

### 1.2 注册表模式
任务类型、objective类型、reward类型、事件效果类型等使用注册表模式。
新类型只需注册处理器，不需要修改现有代码。

### 1.3 条件系统
任务接取/完成、地点解锁、对话选项、事件触发等统一使用条件表达式。
条件类型可扩展，新条件只需注册条件检查器。

### 1.4 效果系统
任务奖励、对话效果、事件结果、地点动作等统一使用效果处理器。
效果类型可扩展，新效果只需注册效果执行器。

### 1.5 事件总线
系统间通过事件总线通信，降低耦合。
参照战斗系统的 `battle-event.js` 模式。

## 二、现有系统架构

### 2.2 NPC系统（characters.js）

**已实现能力：**
- 基础属性：id/name/title/description/elements/level/HP/MP/攻防速/skills
- 位置和可用时间：location/availableTimes
- 简单对话：dialogue数组（trigger/text）
- 给予任务：givesQuests
- 性格系统：personality（8维度：brave/kind/honest/impulsive/loyal/arrogant/greedy/curious，0-1）
- 送礼偏好：giftPreferences（loved/liked/disliked/各倍率/每日限制）
- 关系上限：relationshipCap（maxOpinion/maxTrust/canRomance/canBeMentor/canBeRival）
- NPC间关系：relationships（opinion/trust/type/label）
- **分支对话树**：dialogueTree
  - nodes：节点id/texts/mood/choices
  - choices：id/text/condition/effects/nextNode/action/actionData
  - condition：minOpinion/minLevel/notNpcFlags/npcFlags/minDay/notFlags/hasItem等
  - effects：opinion/trust/exp/gold/npcFlags/giveInfo/giveItem/startQuest/familiarity等
  - action：start_battle/close等

**扩展方式：** 新增NPC只需在characters.js中添加一个key，按照上述格式填写数据。

### 2.3 地点系统（locations.js）

**已实现能力：**
- 基础属性：id/name/description/backgroundColor/unlocked
- 解锁条件：unlockCondition（minLevel/questCompleted/hasItem/minOpinion/level/quest）
- 地点动作：actions数组
  - 动作属性：id/name/description/icon/timeCost/staminaCost/effects/eventChance/events/condition/shopId/npcs/npcRate/isClassAction
  - effects支持：exp/gold/hp/mp/stamina/addItem/npcOpinion/reputation/happiness/mp等
  - condition支持：minLevel/hasItem/minOpinion等
- 连接地点：connectedLocations
- NPC列表：npcs/npcRate
- 敌人列表：enemies/enemyRate/enemyLevelBonus/dropRateBonus/expBonus/warriorDemonChance
- 安全区：isSafeZone
- 商店：shops
- 课程表：classSchedule（morning/afternoon，每节subject/name/teacher/exp/mpCost/hpCost/injuryChance）

**扩展方式：** 新增地点只需在locations.js中添加一个key。新动作类型通过注册动作处理器扩展。

### 2.4 事件系统（events.js）

**已实现能力：**
- 基础属性：id/name/description/trigger/chance/once
- 条件：conditions数组（type/value/operator）
- 选项：choices数组（text/effects/resultText）
- effects支持：exp/gold/hp/mp/stamina/addItem/shopDiscount/npcOpinion等

**扩展方式：** 新增事件只需在events.js中添加。新触发场景和效果类型通过注册扩展。

### 2.5 商店系统（shops.js）

**已实现能力：**
- 基础属性：id/name/factionId/description
- 商品列表：items数组（itemId/price/stock，stock=-1表示无限）
- 阵营关联：factionId

**扩展方式：** 新增商店只需添加数据。拍卖系统等特殊商店类型通过注册新商店类型扩展。

### 2.6 任务系统（quests.js）

**已实现能力：**
- 基础属性：id/name/description/giver/type/objectives/rewards/prerequisites/nextQuest/isMainQuest
- 对话：dialogueStart/dialogueInProgress/dialogueComplete（简单三段式）
- 任务类型：story/hunt/collect/explore/duel/side/investigate/favor
- objective类型：reach/kill/collect/talk/duel/level/attend_class/library/eat
- rewards支持：exp/gold/items/reputation/unlocks
- 前置条件：prerequisites（任务id数组）
- 等级要求：requiredLevel
- 重复任务：repeatable/cooldown

**需要增强：**
- 对话应复用characters.js的dialogueTree系统，支持分支对话
- 条件系统应统一使用通用条件表达式
- 需要更多objective类型（escort/defend/stealth/puzzle/talk_multiple等）
- 需要更多reward类型（unlockLocation/unlockShop/repFaction/skill/specialItem等）
- 任务链分支选择（不同选择导致不同结果）
- 任务失败条件
- 任务计时

### 2.7 NPC成长系统（阶段化数据）

**问题**：NPC随剧情推进实力变化（莫凡Lv3→Lv20+、赵满延中阶→高阶、召唤兽进化、妖魔蜕皮），不能为每个阶段复制完整数据。

**设计原则**：基础数据 + 成长事件，系统自动计算当前状态。一套系统同时管理NPC成长、召唤兽进化、妖魔蜕皮/进化。

#### 2.7.4 系统实现

```javascript
const NPCGrowthService = {
  // 获取NPC在指定剧情阶段的状态
  getNpcState(npcId, storyStage = null) {
    const npc = DataCharacters[npcId];
    if (!npc.growth) return this.getDefaultState(npc);
    const stage = storyStage || player.currentStoryStage;
    let state = { ...npc.growth.base };
    for (const event of npc.growth.events) {
      if (this.isStageReached(event.after, stage)) {
        state = this.applyGrowthEvent(state, event);
      }
    }
    state.stats = this.calculateStats(npc, state.level, state.elements);
    return state;
  },

  // 切磋用战斗数据
  getDuelData(npcId, storyStage = null) {
    const state = this.getNpcState(npcId, storyStage);
    return {
      id: `${npcId}_${state.form || 'default'}`,
      name: npc.name,
      level: state.level,
      elements: state.elements,
      skills: state.skills,
      equipment: state.equipment,
      traits: state.traits,
      maxHp: state.stats.hp,
      maxMp: state.stats.mp,
      attack: state.stats.attack,
      defense: state.stats.defense,
      speed: state.stats.speed,
      form: state.form,
    };
  },

  // 回忆切磋：过去某个节点的NPC状态
  getHistoricalState(npcId, storyStage) {
    return this.getNpcState(npcId, storyStage);
  },
};
```

#### 2.7.5 切磋/挑战功能

- **当前切磋**：系统按当前storyStage计算NPC状态，生成战斗
- **回忆切磋**：选择过去剧情节点，用当时的NPC状态对战（需好感度门槛）
- **奖励**：切磋胜利给少量经验/金币/好感度，不影响主线
- **可扩展性**：新NPC只需定义growth，自动支持切磋

#### 2.7.6 扩展方式

- 新NPC：定义base + events，不需要为每个阶段写完整数据
- 新剧情阶段：在对应NPC的events数组中加一条
- 新怪物形态：用form字段切换
- 战斗中进化：触发battle_molt_X事件，实时更新敌人状态
- 属性自动计算：等级→HP/MP/攻防，复用玩家公式

## 三、统一条件系统

### 3.1 条件表达式格式

所有系统（任务、地点、对话、事件等）使用统一的条件格式：

```javascript
condition: {
  // 等级条件
  minLevel: 10,
  maxLevel: 20,
  
  // 任务条件
  questCompleted: "quest_id",
  questActive: "quest_id",
  questNotCompleted: "quest_id",
  
  // 物品条件
  hasItem: "item_id",
  hasItemCount: { itemId: "item_id", count: 5 },
  
  // NPC关系条件
  minOpinion: { npcId: "npc_id", value: 30 },
  minTrust: { npcId: "npc_id", value: 20 },
  
  // 标志条件
  flags: ["flag1", "flag2"],        // 必须有这些标志
  notFlags: ["flag3"],               // 不能有这些标志
  npcFlags: { npcId: "npc_id", flags: ["flag1"] },
  notNpcFlags: { npcId: "npc_id", flags: ["flag2"] },
  
  // 时间条件
  minDay: 5,
  maxDay: 30,
  timeOfDay: ["morning", "afternoon"],
  
  // 阵营声望
  minReputation: { factionId: "faction_id", value: 100 },
  
  // 属性条件
  minRealm: "middle",  // 中阶
  hasElement: "thunder",
  minSkillLevel: { skillId: "skill_id", level: 2 },
  
  // 组合条件
  all: [cond1, cond2],  // AND
  any: [cond3, cond4],  // OR
  not: cond5,           // NOT
}
```

### 3.2 条件检查器注册表

```javascript
const ConditionCheckers = {
  minLevel: (player, val) => player.level >= val,
  maxLevel: (player, val) => player.level <= val,
  questCompleted: (player, val) => player.completedQuests.includes(val),
  hasItem: (player, val) => player.hasItem(val),
  minOpinion: (player, val) => player.getNpcOpinion(val.npcId) >= val.value,
  // ... 更多条件检查器
  
  // 组合条件
  all: (player, conditions) => conditions.every(c => checkCondition(player, c)),
  any: (player, conditions) => conditions.some(c => checkCondition(player, c)),
  not: (player, condition) => !checkCondition(player, condition),
};

function checkCondition(player, condition) {
  for (const [key, val] of Object.entries(condition)) {
    if (ConditionCheckers[key]) {
      if (!ConditionCheckers[key](player, val)) return false;
    }
  }
  return true;
}
```

**扩展方式：** 新增条件类型只需 `ConditionCheckers[newType] = (player, val) => { ... }`

### 4.2 效果执行器注册表

```javascript
const EffectHandlers = {
  exp: (player, val) => player.gainExp(val),
  gold: (player, val) => player.gold += val,
  addItem: (player, val) => player.addItem(val.itemId, val.count || 1),
  npcOpinion: (player, val) => player.changeNpcOpinion(val.npcId, val.value),
  startQuest: (player, val) => player.startQuest(val),
  unlockLocation: (player, val) => player.unlockLocation(val),
  // ... 更多效果执行器
};

function applyEffects(player, effects) {
  for (const [key, val] of Object.entries(effects)) {
    if (EffectHandlers[key]) {
      EffectHandlers[key](player, val);
    }
  }
}
```

**扩展方式：** 新增效果类型只需 `EffectHandlers[newType] = (player, val) => { ... }`

  // 触发新事件

GameEvents.on('npcOpinionChanged', (npcId, newOpinion) => {
  // 解锁新对话选项
  // 触发NPC专属事件
});

GameEvents.on('locationUnlocked', (locationId) => {
  // 发现新任务
  // 触发探索成就
});

GameEvents.on('battleWon', (enemyId, rewards) => {
  // 更新击杀计数（任务objective）
  // 检查悬赏完成

GameEvents.on('itemObtained', (itemId, count) => {
  // 检查收集任务
  // 触发合成提示

## 八、扩展指南

### 8.1 新增NPC

1. 在 `engine/data/characters.js` 中添加NPC数据
2. 如果NPC会战斗，在 `engine/data/enemies.js` 中添加战斗数据
3. 在对应地点的 `npcs` 数组中添加NPC id
4. 如果NPC有任务，在 `engine/data/quests.js` 中添加任务并在NPC的 `givesQuests` 中引用
5. 如果NPC有对话树，在NPC的 `dialogueTree.nodes` 中添加对话节点

### 8.2 新增地点

1. 在 `engine/data/locations.js` 中添加地点数据
2. 设置 `connectedLocations` 连接到已有地点
3. 添加 `actions`（动作列表）
4. 如果有敌人，添加 `enemies` 和 `enemyRate`
5. 如果有NPC，添加 `npcs` 和 `npcRate`
6. 如果有商店，添加 `shops` 或在action中引用shopId
7. 设置 `unlockCondition`（如果初始锁定）

### 8.3 新增任务

1. 在 `engine/data/quests.js` 中添加任务数据
2. 在发布NPC的 `givesQuests` 中引用任务id
3. 设置 `objectives`（目标列表）
4. 设置 `rewards`（奖励）
5. 设置 `prerequisites`（前置条件）
6. 如果是任务链的一部分，设置 `nextQuest`/`prevQuest`

### 8.4 新增事件

1. 在 `engine/data/events.js` 中添加事件数据
2. 设置 `trigger`（触发场景：training/exploring/combat/rest等）
3. 设置 `chance`（触发概率）
4. 设置 `conditions`（触发条件）
5. 添加 `choices`（选项和效果）
6. 在对应地点/动作的 `events` 数组中引用事件id

### 8.5 新增商店

1. 在 `engine/data/shops.js` 中添加商店数据
2. 添加商品列表（itemId/price/stock）
3. 在对应地点的 `shops` 数组或action的 `shopId` 中引用

### 8.6 新增物品

1. 在 `engine/data/items.js` 中添加物品数据
2. 如果可购买，在对应商店中添加
3. 如果是妖魔掉落，在对应妖魔的 `drops` 中添加
4. 如果可合成，在合成配方中添加
