# 对话树与剧情连锁系统设计

## 一、设计理念

对话不是简单的"接任务-交任务"，而是玩家与 NPC 建立关系、探索世界、影响剧情的主要方式。每个 NPC 都有自己的想法、秘密和故事，玩家通过对话逐渐了解他们，甚至改变他们的命运。

**核心原则**：
- 对话有深度，不是一次性消耗品
- 选择有后果，说过的话会被记住
- 对话能触发剧情，影响世界
- 不同的 NPC 有不同的说话方式和话题

---

## 二、对话树系统 (DialogueTree)

### 2.1 整体结构

每个 NPC 都有一棵完整的对话树，包含多个对话主题和分支。

```
NPC 对话树
├── 默认对话 (default)
│   ├── 选项 1 → 话题 A
│   ├── 选项 2 → 话题 B
│   └── 选项 3 → 结束
├── 话题 A
│   ├── 选项 1 → 话题 A1
│   └── 选项 2 → 返回
├── 话题 B
│   └── ...
└── 特殊对话 (满足条件才出现)
    ├── 好感度达标后解锁
    ├── 特定事件后解锁
    ├── 特定时间解锁
    └── 持有特定物品解锁
```

### 2.2 数据格式

```javascript
{
  npcId: "mo_fan",
  npcName: "莫凡",
  version: "1.0",

  // 对话节点
  nodes: {
    // 默认对话入口
    "default": {
      id: "default",
      // 对话文本（可以有多条，随机选一条）
      texts: [
        "嘿，新来的？有什么事吗？",
        "怎么，找我有事？",
        "..."
      ],
      // 说话的语气/表情
      mood: "casual",  // casual/serious/angry/happy/sad/surprised
      // 选项
      choices: [
        {
          id: "ask_about_school",
          text: "问问学校的情况",
          // 显示条件（不满足就不显示这个选项）
          condition: {
            minOpinion: -10,
            flags: { "first_meet": true }
          },
          // 选择后的效果
          effects: {
            opinion: +2,
            flags: { "asked_about_school": true },
            giveInfo: "school_basic_info"
          },
          // 跳转到哪个对话节点
          nextNode: "about_school"
        },
        {
          id: "ask_about_training",
          text: "请教修炼技巧",
          condition: {
            minOpinion: 10,
            minLevel: 2
          },
          effects: {
            opinion: +3,
            exp: 10
          },
          nextNode: "training_tips"
        },
        {
          id: "challenge",
          text: "要不要切磋一下？",
          condition: {
            minOpinion: 30,
            minLevel: 3
          },
          effects: {
            opinion: +5
          },
          nextNode: "challenge_mo_fan",
          // 特殊动作：触发战斗
          action: "start_battle",
          actionData: { enemyId: "mo_fan_ spar" }
        },
        {
          id: "leave",
          text: "没什么事，先走了",
          effects: {},
          nextNode: null  // null 表示结束对话
        }
      ]
    },

    // 关于学校的话题
    "about_school": {
      id: "about_school",
      texts: [
        "天澜魔法高中嘛，就那样。老师教的都是基础，真正的本事还得自己练。",
        "学校里最厉害的是穆宁雪，冰系天才，不过性格冷得像冰一样。"
      ],
      mood: "casual",
      choices: [
        {
          id: "ask_mu_ningxue",
          text: "穆宁雪是谁？",
          condition: {
            notFlags: ["knows_mu_ningxue"]
          },
          effects: {
            opinion: +1,
            flags: { "knows_mu_ningxue": true },
            giveInfo: "mu_ningxue_intro"
          },
          nextNode: "about_mu_ningxue"
        },
        {
          id: "ask_teachers",
          text: "老师们怎么样？",
          effects: {
            opinion: +1
          },
          nextNode: "about_teachers"
        },
        {
          id: "back",
          text: "原来是这样",
          effects: {},
          nextNode: "default"
        }
      ]
    },

    // 更多对话节点...
  },

  // 对话的全局条件
  globalConditions: {
    // 对话是否可用（比如 NPC 不在就不能对话）
    available: {
      location: "tianlan_school",
      timeOfDay: ["morning", "afternoon"]
    }
  },

  // 一次性对话（触发后不再出现）
  oneTimeDialogues: [
    "first_meet",
    "after_saving_life"
  ]
}
```

### 2.3 对话条件系统

选项和对话节点都可以有条件，满足条件才会显示。

**支持的条件类型**：

| 条件类型 | 说明 | 例子 |
|---------|------|------|
| `minOpinion` | 最低好感度 | `minOpinion: 20` |
| `maxOpinion` | 最高好感度 | `maxOpinion: -10` |
| `minTrust` | 最低信任度 | `minTrust: 30` |
| `minLevel` | 玩家最低等级 | `minLevel: 5` |
| `hasItem` | 持有特定物品 | `hasItem: { itemId: "magic_herb", count: 5 }` |
| `hasQuest` | 有特定任务 | `hasQuest: "quest_1"` |
| `completedQuest` | 完成过特定任务 | `completedQuest: "quest_1"` |
| `flags` | 有特定标记 | `flags: { "met_mo_fan": true }` |
| `notFlags` | 没有特定标记 | `notFlags: ["knows_secret"]` |
| `timeOfDay` | 特定时段 | `timeOfDay: ["night"]` |
| `dayRange` | 特定天数范围 | `dayRange: { min: 5, max: 10 }` |
| `location` | 在特定地点 | `location: "xuefeng_mountain"` |
| `knownInfo` | 知道特定信息 | `knownInfo: "demon_increase_warning"` |

**条件组合**：
- 默认是 AND 关系（所有条件都满足）
- 可以用 `or` 字段表示 OR 关系
- 可以嵌套

```javascript
condition: {
  or: [
    { minOpinion: 50 },
    { 
      and: [
        { completedQuest: "quest_1" },
        { minTrust: 20 }
      ]
    }
  ]
}
```

### 2.4 对话效果系统

选择对话选项后会产生各种效果。

**支持的效果类型**：

| 效果类型 | 说明 | 例子 |
|---------|------|------|
| `opinion` | 改变好感度 | `opinion: +5` |
| `trust` | 改变信任度 | `trust: +3` |
| `respect` | 改变敬重度 | `respect: +2` |
| `fear` | 改变畏惧度 | `fear: +10` |
| `exp` | 获得经验 | `exp: 20` |
| `gold` | 获得/失去金币 | `gold: +50` |
| `addItem` | 获得物品 | `addItem: { itemId: "potion", count: 3 }` |
| `removeItem` | 失去物品 | `removeItem: { itemId: "letter", count: 1 }` |
| `flags` | 设置标记 | `flags: { "knows_secret": true }` |
| `giveInfo` | 给予信息 | `giveInfo: "demon_warning"` |
| `startQuest` | 开始任务 | `startQuest: "quest_2"` |
| `completeQuest` | 完成任务 | `completeQuest: "quest_1"` |
| `startBattle` | 开始战斗 | `startBattle: { enemyId: "thug" }` |
| `triggerEvent` | 触发事件 | `triggerEvent: "event_1"` |
| `changeNpcLocation` | NPC 改变位置 | `changeNpcLocation: { npcId: "mo_fan", location: "xuefeng_mountain" }` |
| `updateRelationship` | 改变 NPC 间关系 | `updateRelationship: { npcA: "a", npcB: "b", opinionChange: +10 }` |
| `addMemory` | 给 NPC 增加记忆 | `addMemory: { type: "favor", content: "...", importance: 0.5 }` |

## 三、剧情连锁系统 (StoryChain)

### 3.1 设计理念

剧情不是线性的，而是像一张网。玩家的每个选择都会产生影响，这些影响会积累起来，最终导致不同的剧情走向。

**核心概念**：
- **伏笔**：早期的小事件，后期才显现影响
- **连锁反应**：一个事件触发另一个事件
- **分支汇聚**：不同的分支可能最终汇聚到同一个大事件，但玩家的准备程度不同
- **蝴蝶效应**：微小的选择导致巨大的差异

### 3.2 剧情节点 (StoryNode)

每个剧情节点都是一个独立的事件，有触发条件和后果。

```javascript
{
  id: "story_node_001",
  name: "莫凡被冤枉",
  type: "story_event",  // story_event / dialogue_event / battle_event / world_event
  importance: 0.7,

  // 触发条件
  trigger: {
    type: "dialogue",       // dialogue / event / time / location / action
    source: "mo_fan",       // 触发源
    condition: {
      flags: { "mo_fan_cheating_rumor": true },
      minOpinion: 30
    }
  },

  // 玩家的选择
  choices: [
    {
      id: "defend_mo_fan",
      text: "站出来帮莫凡说话",
      condition: {
        minOpinion: 40,
        minLevel: 3
      },
      effects: {
        opinion: +20,
        trust: +15,
        reputation: { mu_family: -10 },
        flags: { "defended_mo_fan": true }
      },
      outcomeText: "你站出来为莫凡作证，帮他洗清了冤屈。莫凡非常感激你。",
      nextNodes: ["mo_fan_becomes_friend"]
    },
    {
      id: "stay_out_of_it",
      text: "装作没看见",
      condition: {},
      effects: {
        opinion: -5,
        flags: { "ignored_mo_fan_trouble": true }
      },
      outcomeText: "你选择了明哲保身。莫凡虽然没说什么，但你能感觉到他有些失望。",
      nextNodes: ["mo_fan_distrust"]
    },
    {
      id: "side_against_him",
      text: "跟着大家一起指责他",
      condition: {
        maxOpinion: -10
      },
      effects: {
        opinion: -30,
        trust: -20,
        reputation: { mu_family: +5 },
        flags: { "betrayed_mo_fan": true }
      },
      outcomeText: "你跟着大家一起指责莫凡。他冷冷地看了你一眼，什么都没说。",
      nextNodes: ["mo_fan_becomes_enemy"]
    }
  ],

  // 对世界的影响
  worldEffects: {
    globalFlags: { "mo_fan_incident_happened": true },
    npcEffects: {
      "mo_fan": {
        opinion: -10  // 事件本身对莫凡的影响
      }
    }
  }
}
```

### 3.3 剧情链的追踪

系统会追踪所有已触发的剧情节点，以及玩家的选择。

**剧情状态数据**：
```javascript
{
  triggeredNodes: [
    {
      nodeId: "story_node_001",
      choiceId: "defend_mo_fan",
      timestamp: { day: 10, period: "afternoon" },
      consequences: ["mo_fan_becomes_friend"]
    }
  ],
  activeChains: [
    "mo_fan_arc_1"
  ],
  completedChains: [],
  playerChoices: {
    "mo_fan_side": "friend",
    "mu_family_relation": "neutral"
  }
}
```

### 3.4 伏笔与回收

**伏笔的设计**：
- 早期的对话中提到某个名字
- 某个 NPC 行为异常
- 某个地点有奇怪的现象
- 某个物品有特殊的描述

**伏笔的回收**：
- 后期某个事件中，之前的伏笔显现意义
- 玩家如果注意到了伏笔，会有优势
- 没注意到的话，可能会遭遇意外

**例子**：
- 伏笔：唐月老师偶尔会提到"黑教廷"这个词
- 回收：后来黑教廷真的出现了，如果玩家之前注意到了，会提前有心理准备

## 四、信息系统 (InformationSystem)

### 4.1 设计理念

玩家在游戏中会收集到各种信息，这些信息会影响对话选项、事件触发、任务接取等。信息是玩家推理和决策的基础。

### 4.2 信息分类

| 类别 | 说明 | 例子 |
|------|------|------|
| `world` | 世界观信息 | "魔法分为八大元素" |
| `npc` | NPC 相关信息 | "莫凡是天生双系" |
| `quest` | 任务相关信息 | "雪峰山有妖魔出没" |
| `event` | 事件相关信息 | "最近妖魔活动频繁" |
| `secret` | 秘密信息 | "穆家有个秘密" |
| `rumor` | 传闻（可能是假的） | "听说黑教廷潜入了博城" |
| `skill` | 技能知识 | "雷系魔法速度最快" |

### 4.3 信息的作用

1. **解锁对话选项**：知道某些信息后，会出现新的对话选项
2. **影响 NPC 态度**：知道 NPC 的秘密，可以用来威胁或讨好
3. **触发事件**：收集到足够的信息，会触发某个事件
4. **任务提示**：给出任务的线索和提示
5. **剧情铺垫**：为大事件做铺垫

### 4.4 信息的获取途径

- NPC 对话
- 探索发现
- 任务奖励
- 书籍/公告/报纸
- 随机事件
- 观察环境

## 五、对话的多样性设计

### 5.1 对话的变化

同一个 NPC 在不同情况下说的话不一样：

1. **好感度不同**：态度不同，说的话不同
2. **时间不同**：早上和晚上说的话不同
3. **地点不同**：在学校和在街上说的话不同
4. **事件后不同**：经历某个事件后，对话内容变化
5. **玩家状态不同**：玩家等级高了，NPC 态度变化
6. **心情不同**：NPC 心情好和心情不好说的话不同

### 5.2 重复对话的设计

玩家反复和同一个 NPC 对话，内容不能完全一样：

- 第一次对话：自我介绍、基本信息
- 第二次对话：更深的话题
- 多次对话后：聊一些私事、秘密
- 每天第一次对话：问候 + 新话题
- 同一天重复对话："怎么又是你？" / "还有事吗？"

### 5.3 NPC 语气设计

每个 NPC 有自己独特的说话方式：

- **莫凡**：随意、有点痞、直来直去
- **穆宁雪**：冷淡、话少、用词正式
- **唐月**：温柔、耐心、像大姐姐
- **王老板**：精明、市侩、热情

## 六、数据存储格式规范

### 6.1 文件结构

```
content/
└── dialogues/
    ├── npcs/
    │   ├── mo-fan.json        // 莫凡的完整对话树
    │   ├── mu-ningxue.json    // 穆宁雪的对话树
    │   ├── tang-yue.json      // 唐月的对话树
    │   └── ...
    ├── story/
    │   ├── main-quest.json    // 主线剧情链
    │   ├── side-quests.json   // 支线剧情链
    │   └── character-arcs/    // 角色个人剧情
    │       ├── mo-fan-arc.json
    │       └── ...
    └── info/
        ├── world-info.json    // 世界观信息库
        └── rumors.json        // 传闻库
```

### 6.2 命名规范

- 对话节点 ID：用小写英文 + 下划线，语义清晰
- 剧情节点 ID：`story_` 前缀 + 描述性名称
- 信息 ID：`info_` 前缀 + 分类 + 名称

## 七、扩展原则

1. **渐进式添加**：先加基础对话，再加深度对话
2. **质量优先**：每个 NPC 的对话都要精心设计，有自己的性格
3. **前后呼应**：前面说的话，后面要有呼应
4. **选择有意义**：每个重要选择都要有实际后果
5. **可组合性**：不同的剧情链可以互相交叉影响

---

## 八、后续扩展方向

1. **语音系统** - 重要对话有语音
2. **表情系统** - NPC 对话时有表情变化
3. **动作系统** - NPC 对话时有动作
4. **对话回忆** - 玩家可以回看之前的重要对话
5. **关系变化提示** - 对话后提示好感度变化（可选）
6. **多语言支持** - 对话文本支持多语言
