# 小说内容逐章拆解方法论与工作流

> **核心原则**：不粗略概括，深入文本，逐章精读，拔设定、扒内容，把可游戏化的元素拆解出来。
> 
> **不是照抄剧情**，而是提取：人物设定、地点场景、世界观规则、关系互动、可做的任务/事件/物品/对话。

---

## 一、当前项目与小说的结合现状

### 1.1 已结合的内容（粗略转化阶段）
- 主要NPC：莫凡、穆宁雪、唐月、张小侯、赵满延等（基础设定，对话较少）
- 主要地点：天澜魔法高中、博城市街、雪峰山、莫凡家、穆家庄园（基础框架）
- 大事件：博城灾难（有事件链和多结局，但铺垫不足）
- 妖魔：11+奴仆级、2个战将级（基础属性，缺少小说中的习性描写）
- 任务：28+任务（多为原创，与小说剧情结合不深）

### 1.2 存在的问题
1. **NPC深度不足**：只有基础设定，缺少小说中的具体对话、性格细节、个人剧情
2. **剧情结合松散**：任务和事件多为原创，没有真正从小说中提取
3. **世界观细节缺失**：小说中的很多设定（社会结构、魔法常识、生活细节）没有体现
4. **地点内容单薄**：地点只有行动列表，缺少小说中的场景描写和氛围
5. **关系网不完整**：NPC之间的关系只有基础数据，缺少小说中的具体互动

### 1.3 解决思路
- **逐章精读拆解**：从第1章开始，一章一章读，把所有可游戏化的内容提取出来
- **建立拆解数据库**：每章的拆解结果结构化存储，便于后续转化
- **分批转化**：拆解一批，转化一批，测试一批，迭代优化

## 二、逐章拆解模板

每章按以下维度拆解，确保不遗漏：

### 2.1 出场人物（Person）
| 字段 | 说明 | 提取方式 |
|------|------|---------|
| 姓名 | 人物全名 | 直接提取 |
| 身份 | 职业/地位/角色 | 从描写和对话中推断 |
| 外貌 | 外貌描写 | 直接提取原文关键词 |
| 性格表现 | 本章体现的性格 | 从行为、对话、选择中提取 |
| 说话方式 | 语气、用词、口头禅 | 从对话原文中提取 |
| 能力 | 元素/等级/技能 | 从描写和对话中提取 |
| 重要性 | S/A/B/C级 | 根据角色定位判断 |
| 首次出场 | 是否是本章首次出场 | 标记 |

### 2.2 地点场景（Location）
| 字段 | 说明 | 提取方式 |
|------|------|---------|
| 地点名称 | 完整地名 | 直接提取 |
| 环境描写 | 场景细节 | 直接提取原文关键词 |
| 氛围 | 场景给人的感觉 | 从描写中推断 |
| 出现的人物 | 本章在此地点出现的人 | 关联人物 |
| 发生的事件 | 本章在此地点发生的事 | 关联事件 |
| 可游戏化 | 是否可以做成游戏地点 | 判断 |

### 2.3 世界观设定（Worldbuilding）
| 字段 | 说明 | 提取方式 |
|------|------|---------|
| 设定名称 | 设定的名称 | 直接提取 |
| 设定内容 | 具体规则/常识 | 从原文中提取 |
| 设定类型 | 魔法体系/社会结构/生活常识/历史/地理 | 分类 |
| 重要性 | 核心/重要/一般/细节 | 判断 |
| 可游戏化 | 如何体现在游戏中 | 设计转化方式 |

### 2.4 剧情事件（Event）
| 字段 | 说明 | 提取方式 |
|------|------|---------|
| 事件名称 | 简短描述 | 概括 |
| 事件内容 | 具体发生了什么 | 详细描述 |
| 参与人物 | 涉及的人物 | 关联人物 |
| 地点 | 发生地点 | 关联地点 |
| 事件类型 | 主线/支线/日常/战斗/对话/转折 | 分类 |
| 可游戏化 | 如何转化为游戏任务/事件 | 设计 |

### 2.5 关系互动（Relationship）
| 字段 | 说明 | 提取方式 |
|------|------|---------|
| 人物A | 第一个人 | 关联人物 |
| 人物B | 第二个人 | 关联人物 |
| 关系类型 | 亲情/友情/爱情/敌对/师生/雇佣等 | 从互动中推断 |
| 关系状态 | 当前关系如何 | 从描写和对话中提取 |
| 互动内容 | 本章的具体互动 | 详细描述 |
| 对话原文 | 关键对话 | 直接提取（可用于游戏对话） |
| 关系变化 | 本章关系是否有变化 | 标记 |

### 2.6 可游戏化元素（Gameable）
这是拆解的核心输出，直接指导游戏开发：

| 类型 | 说明 | 转化方向 |
|------|------|---------|
| NPC | 可做成游戏NPC的人物 | characters数据 |
| 地点 | 可做成游戏地点的场景 | locations数据 |
| 任务 | 可做成任务的剧情片段 | quests数据 |
| 事件 | 可做成随机事件/剧情事件 | events数据 |
| 物品 | 可做成物品/装备的东西 | items数据 |
| 对话 | 可直接用的对话内容 | dialogueTree数据 |
| 敌人 | 可做成敌人的妖魔/人类 | enemies数据 |
| 设定 | 需要在游戏中体现的世界观 | UI/任务/对话中体现 |

### 2.7 伏笔线索（Foreshadowing）
| 字段 | 说明 |
|------|------|
| 伏笔内容 | 具体的伏笔描述 |
| 伏笔类型 | 人物/事件/设定/物品 |
| 预期回收 | 预计在什么时候回收（如果知道） |
| 游戏化方式 | 如何让玩家发现这个伏笔 |

## 三、拆解工作流

### 3.1 单次拆解流程
```
1. 读取一章原文
   ↓
2. 按7个维度逐段精读，标记关键内容
   ↓
3. 填写拆解模板，结构化记录
   ↓
4. 重点提取"可游戏化元素"，给出具体转化建议
   ↓
5. 与已有的游戏数据对比，标记"已存在/需新增/需完善"
   ↓
6. 存入拆解数据库（本文档的章节拆解部分）
```

### 3.2 批量转化流程
```
拆解10-20章
   ↓
整理可游戏化元素清单
   ↓
按优先级排序（NPC > 地点 > 任务 > 事件 > 物品 > 对话）
   ↓
分批写入game-data.js
   ↓
测试验证
   ↓
更新文档
```

### 3.3 拆解原则
1. **宁多勿漏**：宁可多提取一些细节，也不要遗漏
2. **原文为据**：所有提取都要有原文依据，不脑补
3. **结构化**：按模板填写，便于后续检索和转化
4. **可操作**：可游戏化元素要给出具体的转化建议，不是空泛的"可以做成任务"
5. **关联化**：人物、地点、事件之间要建立关联

### 9.1 characters.js重复定义问题（重要！）

**问题描述**：

**原因分析**：

- 建议统一在文件末尾追加新NPC，避免在中间插入

### 9.2 数据格式双轨问题

**问题描述**：

**处理建议**：

## 十、小说内容转化完整性检查清单（必做！）

> **重要提醒**：把数据写进数据文件 ≠ 融进游戏。每次转化完成后，必须按以下清单逐项检查，否则新增的NPC/敌人/物品可能永远不会被玩家遇到。

### 10.1 敌人转化检查

| 检查项 | 检查方法 | 常见错误 |
|--------|---------|---------|
| 敌人已加入地点enemies数组 | Grep地点文件中的enemies数组 | 只在enemies.js定义了，但地点没引用 → 永远不会遇敌 |
| 敌人技能全部存在 | Grep skills.js确认每个skillId | 引用了不存在的技能ID → 战斗时技能无效 |
| 敌人掉落物品全部存在 | Grep items.js确认每个dropItems的itemId | 掉落不存在的物品 → 战斗胜利报错 |
| 敌人属性合理 | 对比同等级现有敌人的HP/攻击/防御 | 属性过高或过低 → 战斗体验失衡 |
| 敌人出现地点合理 | 确认locations字段与小说设定一致 | 城市安全区出现高级妖魔 → 不符合设定 |

**关键代码位置**：
- 敌人定义：engine/data/enemies.js
- 地点enemies数组：engine/data/locations.js 中每个地点的 enemies: []
- 遇敌逻辑：engine/map.js 的 	riggerRandomBattle() 读取 location.enemies

### 10.2 NPC转化检查

| 检查项 | 检查方法 | 常见错误 |
|--------|---------|---------|
| NPC已加入地点行动的npcs数组 | Grep地点文件中action.npcs | **只加了地点级别的npcs数组，游戏不读！** 必须加到具体行动（如talk）的npcs数组 |
| NPC技能全部存在 | Grep skills.js确认每个skillId | 引用不存在的技能 → 战斗报错 |
| NPC对话树结构完整 | 检查dialogueTree.nodes.default存在 | 缺少default节点 → 对话打不开 |
| NPC礼物偏好物品存在 | Grep items.js确认loved/liked中的itemId | 引用不存在的物品 → 送礼时无特殊加成（不报错但体验差） |
| NPC的location字段规范 | 确认与实际地点ID一致 | 写成mu_estate但实际是mu_manor → 元数据错误（不影响游戏但不规范） |

**关键代码位置**：
- NPC定义：engine/data/characters.js
- 地点行动npcs数组：engine/data/locations.js 中 ctions[].npcs: []
- NPC获取逻辑：engine/map.js 的 performAction() 读取 ction.npcs
- **注意**：地点级别的 
pcs: [] 数组（在actions外面）**不被游戏使用**！

### 10.3 物品/装备转化检查

| 检查项 | 检查方法 | 常见错误 |
|--------|---------|---------|
| 装备type字段正确 | 确认是weapon/armor/accessory | **写成equipment → 背包筛选看不到！** |
| 装备equipSlot正确 | 确认与type一致（weapon→weapon等） | equipSlot和type不匹配 → 装备槽位错误 |
| 装备equipStats字段存在 | 确认有属性加成对象 | 缺少equipStats → 装备无效果 |
| 物品价格合理 | 对比同类物品价格 | 价格0或负数 → 经济系统崩坏 |
| 消耗品effects字段正确 | 确认hp/mp/stamina等效果 | 缺少effects → 使用无效果 |

**关键代码位置**：
- 物品定义：engine/data/items.js
- 装备筛选逻辑：engine/ui.js 第1401行 itemData.type === 'weapon' \|\| 'armor' \|\| 'accessory'
- 装备属性计算：engine/player.js 的 getTotalStats() 读取 item.equipStats

### 10.4 地点转化检查

| 检查项 | 检查方法 | 常见错误 |
|--------|---------|---------|
| shop行动有shopId | 确认shop行动包含shopId字段 | 缺少shopId → 点击商店无反应 |
| talk行动有npcs数组 | 确认talk行动包含npcs数组 | 缺少npcs → 点聊天弹空窗口 |
| 行动events数组中的事件存在 | Grep events.js确认每个eventId | 引用不存在的事件 → 触发时报错 |
| 解锁条件合理 | 确认minLevel/questCompleted与游戏进度匹配 | 条件过高 → 玩家永远到不了 |
| connectedLocations正确 | 确认与相邻地点双向关联 | 只加了单向连接 → 能去不能回 |

**关键代码位置**：
- 地点定义：engine/data/locations.js
- 商店打开逻辑：engine/map.js 读取 ction.shopId
- 事件触发逻辑：engine/map.js 读取 ction.events 数组，**不依赖事件的trigger字段**

### 10.5 事件转化检查

| 检查项 | 检查方法 | 常见错误 |
|--------|---------|---------|
| 事件已被地点行动引用 | Grep地点文件的events数组 | 只在events.js定义了，但没被任何行动引用 → 永远不会触发 |
| 事件choices结构完整 | 确认每个choice有text和effects/resultText | 缺少resultText → 选择后无反馈 |
| 事件条件格式正确 | 确认conditions数组格式与现有事件一致 | 格式错误 → 条件判断失效 |

**关键说明**：
- 事件的 	rigger 字段**不被地点行动使用**，地点行动直接通过 events: [] 数组指定事件ID
- 	rigger 字段仅用于 EventSystem.triggerRandomEvent(trigger) 的全局随机事件（如travel事件）

### 10.6 商店转化检查

| 检查项 | 检查方法 | 常见错误 |
|--------|---------|---------|
| 商店商品itemId全部存在 | Grep items.js确认每个商品 | 引用不存在的物品 → 商店显示空白 |
| 商店已被地点shop行动引用 | Grep地点文件的shopId | 只在shops.js定义了，但没被任何地点引用 → 永远打不开 |
| 商品价格合理 | 对比物品基础price | 商店价格远低于物品基础价 → 经济套利 |
