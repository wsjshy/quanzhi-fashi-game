# 天赋系统差异化设计方法论

> **文档目的**：记录天赋系统的可扩展架构、差异化设计原则、新增系别/天赋的标准流程，确保后续随着小说拆解新增系别时，天赋系统保持差异化和可扩展性。
>
> **版本**：v3.1.0 | **最后更新**：2026-08-23

---

## 一、核心设计原则

### 1.1 差异化优先，拒绝模板化

**绝对禁止**：每个系都用完全一样的天赋结构（都是resource机制、都有主动技能、都是三分支输出）。

**必须做到**：
- 每个系的common天赋使用**不同的机制类型**（火系resource/冰系state/光系form/风系trigger/治愈系passive/召唤系summon）
- **不是每个系都有主动技能**：召唤系、治愈系无主动技能，核心是召唤兽/被动光环
- 每个系的天赋分支选择符合该系特点，不都是"输出/控制/防御"三分支

### 1.2 成长曲线差异化

玩家有理由选择不同天赋，根据玩法偏好选择：

| 天赋类型 | 开局强度 | 后期强度 | 成长速度 | 适合玩家 |
|---------|---------|---------|---------|---------|
| **先天型（innate）** | ★★★★☆ | ★★★★☆ | 慢（升级收益减半） | 新手、不想刷等级、快速体验 |
| **成长型（growth）** | ★★☆☆☆ | ★★★★★ | 快 | 长线玩家、深度养成、追求极限 |
| **成熟型（mature）** | ★★★☆☆ | ★★★★☆ | 中 | 大多数玩家、平衡体验 |
| **爆发型（burst）** | ★★★★☆ | ★★★☆☆ | 前期快后期慢 | 节奏快、前期压制 |

> **重要**：先天型**不是**"无法升级"，而是"开局即达到较高等级（如Lv5），可以继续升级但升级收益减半，最终强度约为成长型Lv8的水平"。这样开局强，后期也不弱，但比纯成长型的最终极限强度稍低。

### 1.3 机制类型差异化

6种机制类型，每个系选择最符合其特点的机制：

| 机制类型 | 核心体验 | 适合系别 | 有无主动技能 |
|---------|---------|---------|------------|
| **resource（资源积累）** | 积累资源层数，满层爆发或主动消耗强化 | 火系、雷系、暗系 | 有（主动消耗资源） |
| **state（状态叠加）** | 叠加状态层数，层数越高效果越强 | 冰系、植物系 | 可选（满层引爆） |
| **form（形态切换）** | 手动或自动切换形态，不同形态不同效果 | 光系、水系 | 有（形态切换技能） |
| **trigger（条件触发）** | 满足特定条件时触发特殊效果 | 风系、土系 | 无（被动触发） |
| **passive（纯被动）** | 常驻光环或被动效果，无需主动操作 | 治愈系 | 无（纯被动） |
| **summon（召唤协同）** | 效果主要作用于召唤兽，与召唤兽协同作战 | 召唤系 | 无（召唤兽本身就是核心） |

> **设计原则**：机制类型的选择必须符合系别特点，不能为了"每个系都有主动技能"而强行添加。召唤系的"主动技能"就是召唤兽本身，治愈系的核心是被动光环，这些系不需要独立的主动技能。

## 二、可扩展架构设计

### 2.1 数据层架构

**文件**：`src/data/talents.js`

每个天赋是一个独立对象，字段结构：

```javascript
{
  id: "fire_talent_basic",           // 天赋唯一ID，格式：{element}_talent_{rarity/name}
  name: "烈焰之魂",                    // 天赋名称
  element: "fire",                     // 系别ID（新增系别时只需改这个字段）
  rarity: "common",                    // 稀有度：common/uncommon/rare/epic/legendary
  type: "growth",                      // 天赋类型：innate/growth/mature/burst
  mechanism: "resource",               // 机制类型：resource/state/form/trigger/passive/summon
  description: "...",                   // 天赋描述（一句话说明核心特点）
  maxLevel: 10,                        // 最大等级（先天型可以设为10，但升级收益减半）
  activeSkill: { ... },                // 主动技能（可选，不是每个系都有）
  evolutions: [ ... ]                  // 进化阶段数组（Lv1/Lv3/Lv5/Lv7/Lv10）
}
```

**关键可扩展点**：
- 新增系别：只需添加`element: "new_element"`的天赋对象，不需要修改引擎代码
- 新增机制类型：只需在`TALENT_MECHANISM_CONFIG`中添加配置，UI自动显示标签
- 新增天赋类型：只需在`TALENT_TYPE_CONFIG`中添加配置，UI自动显示标签

### 2.2 配置层架构

**文件**：`src/data/talents.js` 末尾

```javascript
// 机制类型配置（新增机制类型时在此添加）
export const TALENT_MECHANISM_CONFIG = {
  resource: { name: "资源积累", color: "#ff6b6b", description: "..." },
  state: { name: "状态叠加", color: "#4ecdc4", description: "..." },
  form: { name: "形态切换", color: "#ffe66d", description: "..." },
  trigger: { name: "条件触发", color: "#a8e6cf", description: "..." },
  passive: { name: "纯被动", color: "#dfe6e9", description: "..." },
  summon: { name: "召唤协同", color: "#fd79a8", description: "..." }
  // 新增机制类型在此添加
};

// 天赋类型配置（新增天赋类型时在此添加）
export const TALENT_TYPE_CONFIG = {
  innate: { name: "先天型", color: "#fbbf24", description: "..." },
  growth: { name: "成长型", color: "#60a5fa", description: "..." },
  mature: { name: "成熟型", color: "#4ade80", description: "..." },
  burst: { name: "爆发型", color: "#ff6b6b", description: "..." }
  // 新增天赋类型在此添加
};
```

**关键可扩展点**：
- 配置与数据分离，新增机制/类型时只需添加配置，不需要修改数据
- UI层自动读取配置显示标签，不需要修改UI代码

### 2.3 引擎层架构

**文件**：`src/engine/talent.js`

核心方法：
- `getTalentChoices(element)`：根据系别获取天赋候选（自动筛选`element`字段匹配的天赋）
- `getTalentEffects(talentId, level, branch)`：计算天赋在指定等级的全部效果
- `getEvolutionStages(talentId)`：获取进化阶段列表
- `needsBranchChoice(talentData)`：检查是否需要选择分支（Lv5且有branchChoices）

**关键可扩展点**：
- 引擎根据`element`字段自动筛选天赋，新增系别时不需要修改引擎
- 天赋效果计算基于`evolutions`数组，新增天赋时不需要修改引擎
- 分支选择基于`branchChoices`字段，新增分支时不需要修改引擎

### 2.4 UI层架构

**文件**：`src/engine/game-talent-select.js`

天赋选择界面自动显示：
- 类型标签（根据`type`字段从`TALENT_TYPE_CONFIG`读取）
- 机制标签（根据`mechanism`字段从`TALENT_MECHANISM_CONFIG`读取）
- 主动技能/纯被动标签（根据`activeSkill`字段判断）
- 类型描述和机制描述（从配置读取）

**关键可扩展点**：
- UI自动读取配置显示标签，新增机制/类型时不需要修改UI代码
- 天赋卡片根据天赋数据动态渲染，新增天赋时不需要修改UI代码

## 三、新增系别标准流程

### 3.1 前置条件

- 小说拆解已确认该系别存在，且有足够的设定支撑天赋设计
- 已检索原著，确认该系别的核心特点、代表技能、典型法师

### 3.2 设计步骤

#### 步骤1：确定系别核心特点

回答以下问题：
- 该系别的核心战斗风格是什么？（输出/控制/防御/辅助/召唤）
- 该系别最具代表性的技能/效果是什么？
- 该系别在原著中的典型法师是谁？他们的战斗风格是什么？
- 该系别与其他系别的核心区别是什么？

#### 步骤2：选择机制类型

根据系别核心特点，从6种机制类型中选择最符合的：

| 系别特点 | 推荐机制类型 | 例子 |
|---------|------------|------|
| 积累能量后爆发 | resource | 火系（燃点）、雷系（电荷） |
| 叠加层数持续增强 | state | 冰系（寒霜）、植物系（生长） |
| 切换形态攻防转换 | form | 光系（圣光/圣盾）、水系（涨潮/退潮） |
| 满足条件触发特效 | trigger | 风系（闪避触发）、土系（受击触发） |
| 纯辅助/团队增益 | passive | 治愈系（生命光环） |
| 围绕召唤兽协同 | summon | 召唤系（契约兽） |

> **注意**：可以新增机制类型，但必须先在`TALENT_MECHANISM_CONFIG`中添加配置，并说明与现有机制的区别。

#### 步骤3：确定是否需要主动技能

**有主动技能的情况**：
- resource机制：主动消耗资源释放强化技能
- form机制：主动切换形态

**无主动技能的情况**：
- trigger机制：被动触发，不需要主动操作
- passive机制：纯被动光环
- summon机制：召唤兽本身就是核心，不需要独立主动技能

> **原则**：不是每个系都要有主动技能。如果该系别的核心玩法不需要主动操作，就不要强行添加主动技能。

#### 步骤4：设计5个天赋（common/uncommon/rare/epic/legendary）

每个系别保持5个天赋的结构，但每个天赋有独特的机制和成长曲线：

| 稀有度 | 类型建议 | 设计要点 |
|--------|---------|---------|
| common | growth | 基础机制，有Lv5分支选择，成长平稳 |
| uncommon | mature | 特色机制，开局中等，后期不错 |
| rare | burst | 独特触发条件，前期强力，后期稍弱 |
| epic | growth | 强力机制，有明显优缺点，后期上限高 |
| legendary | innate | 开局即高等级，升级收益减半，召唤兽协同能力极强 |

#### 步骤5：设计进化阶段

每个成长型天赋有5个进化阶段（Lv1/Lv3/Lv5/Lv7/Lv10）：
- Lv1 觉醒：核心能力
- Lv3 特性：新被动/新机制
- Lv5 进化：分支选择（2-3个分支）
- Lv7 延伸：关联新能力
- Lv10 终极：传说级效果

先天型天赋只有1个终极阶段，但效果相当于成长型Lv5的强度。

### 3.3 实施步骤

1. 在`src/data/talents.js`中添加5个天赋对象
2. 为每个天赋设置正确的`element`/`rarity`/`type`/`mechanism`字段
3. 为每个天赋设计`evolutions`数组和`effects`
4. 运行`node tests/run.js`确认数据完整性测试通过
5. 在浏览器中测试天赋选择界面和战斗效果
6. 更新`docs/项目存量内容清单.md`中的天赋统计
7. 更新`README.md`中的系别和天赋数量统计

### 3.4 测试要点

- 天赋选择界面正确显示类型标签和机制标签
- 天赋效果在战斗中正确应用
- 进化阶段升级时正确触发
- Lv5分支选择正确显示和应用
- 先天型天赋开局强度合理，升级收益减半生效
- 与其他系别的天赋强度平衡

## 四、机制类型设计详解

### 4.1 resource（资源积累）

**核心循环**：攻击/技能积累资源 → 资源满层自动爆发 OR 主动消耗资源释放强化技能

**设计要点**：
- 资源上限：5-10层
- 资源获取：每次攻击/技能积累1层
- 满层效果：自动爆发（对所有敌人造成伤害）或主动消耗（释放强化技能）
- Lv5分支：爆发流（强化满层自动爆发）/ 消耗流（强化主动消耗技能）/ 叠加流（资源上限提升）

**代表系别**：火系（燃点）、雷系（电荷）、暗系（诅咒值）

### 4.2 state（状态叠加）

**核心循环**：攻击/技能叠加状态层数 → 层数越高效果越强 → 满层触发特殊效果

**设计要点**：
- 状态上限：3-10层
- 状态效果：每层+X%伤害/防御/速度
- 满层效果：冻结/麻痹/引爆/绽放
- Lv5分支：加深流（状态效果增强）/ 蔓延流（状态扩散到其他敌人）/ 持续流（状态持续时间延长）

**代表系别**：冰系（寒霜）、植物系（生长）、暗系（诅咒层数）

### 4.3 form（形态切换）

**核心循环**：手动/自动切换形态 → 不同形态有不同效果 → 战术切换攻防转换

**设计要点**：
- 形态数量：2-3种
- 切换方式：手动切换（有冷却）或自动切换（每N回合）
- 形态效果：输出形态/防御形态/治疗形态
- Lv5分支：掌控流（手动切换无冷却）/ 强化流（形态效果增强）/ 双形态（同时获得两种形态部分效果）

**代表系别**：光系（圣光/圣盾）、水系（涨潮/退潮）

### 4.4 trigger（条件触发）

**核心循环**：满足特定条件（闪避/受击/暴击/低HP）→ 触发特殊效果 → 高风险高回报

**设计要点**：
- 触发条件：闪避后/受击时/暴击时/HP低于X%时
- 触发概率：20%-100%
- 触发效果：连击/反击/护盾/狂暴
- Lv5分支：高频流（触发概率提升）/ 强效流（触发效果增强）/ 连锁流（触发后可连续触发）

**代表系别**：风系（闪避触发连击）、土系（受击触发反击）

### 4.5 passive（纯被动）

**核心循环**：常驻光环/被动效果 → 无需主动操作 → 团队增益/持续恢复

**设计要点**：
- 常驻效果：每回合恢复HP/全队伤害+X%/全队防御+X%
- 无主动技能：完全被动，不需要操作
- Lv5分支：生命流（治疗量增强）/ 净化流（每回合净化负面状态）/ 庇护流（全队减伤）

**代表系别**：治愈系（生命光环）

### 4.6 summon（召唤协同）

**核心循环**：召唤兽攻击/行动 → 积累契约/协同效果 → 召唤兽本身就是核心战斗力

**设计要点**：
- 效果作用于召唤兽：召唤兽伤害+X%/召唤兽HP+X%/召唤兽等级+X
- 无独立主动技能：召唤兽的技能就是主动技能
- 玩家与召唤兽协同：同时攻击同一目标伤害加成/共享HP/继承属性
- Lv5分支：强攻流（召唤兽伤害增强，兽潮爆发）/ 防御流（召唤兽守护替伤）/ 协同流（玩家召唤兽同时攻击加成）

**代表系别**：召唤系（契约兽）

## 五、常见坑和注意事项

### 5.1 不要模板化

**错误做法**：每个系都是resource机制+主动技能+三输出分支

**正确做法**：根据系别特点选择机制类型，不是每个系都有主动技能

### 5.2 先天型不是"无法升级"

**错误做法**：先天型maxLevel=1，完全无法升级

**正确做法**：先天型开局即Lv5强度，可以继续升级但升级收益减半，最终强度约为成长型Lv8

### 5.3 召唤系不要强行加主动技能

**错误做法**：召唤系有独立的主动技能"召唤号令"，与召唤兽无关

**正确做法**：召唤系的"主动技能"就是召唤兽本身，天赋效果主要作用于召唤兽

### 5.4 机制类型要符合系别特点

**错误做法**：治愈系用resource机制，需要积累资源才能治疗

**正确做法**：治愈系用passive机制，常驻生命光环，无需主动操作

### 5.5 新增系别时先检索原著

**错误做法**：凭想象设计新系别的天赋，与原著设定冲突

**正确做法**：先检索原著，确认该系别的核心特点、代表技能、典型法师，再设计天赋
