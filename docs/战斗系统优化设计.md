# 战斗系统优化设计文档（v0.4.0）

## 一、优化背景与问题诊断

### 原有问题
1. **伤害公式纯数值**：`damage = max(1, (attack - defense * 0.5) * multiplier)`，元素只改倍率
2. **技能同质化**：90%都是damage类型，buff/debuff效果弱
3. **元素无特性**：火系和冰系除了名字和克制关系，玩起来一样
4. **星子引导浅**：只有等待回合数，没有引导中的策略选择
5. **无组合反应**：元素之间不会互相影响

### 优化目标
让每个元素有**独特的玩法机制**，而不只是伤害数字不同。玩家选择火系就是玩爆发叠层，选择冰系就是玩控制冻结，选择雷系就是玩麻痹赌脸。

## 二、第一层：元素特性差异化（已实现）

### 各元素独特机制

| 元素 | 核心机制 | 状态效果 | 策略玩法 |
|------|----------|----------|----------|
| 🔥 火系 | 燃烧层数 | burn（可叠加3层，DOT按层数计算） | 叠层→引爆，追求高爆发 |
| ❄️ 冰系 | 冻结值累积 | freeze（累积100→frozen冻结1回合） | 控制流，冻结后接火系融化 |
| ⚡ 雷系 | 麻痹跳过 | stun（概率使敌人跳过回合） | 赌脸控制，对湿润目标×2伤害 |
| 🌪️ 风系 | 高闪避+多段 | evasion_up（闪避率+25%） | 生存流，靠闪避躲伤害 |
| 🪨 土系 | 护盾吸收 | shield（吸收伤害，护盾存在防御翻倍） | 坦克流，护盾扛伤害 |
| 💧 水系 | 回复+湿润 | wet（湿润状态，配合雷系感电） | 辅助流，挂湿润给雷系增伤 |
| ✨ 光系 | 净化（待实现） | 净化所有负面状态 | 待实现 |
| 🌑 暗影系 | 诅咒叠加（待实现） | curse（降低攻防，可叠加） | 待实现 |

### 状态效果数据结构扩展

原有结构：
```javascript
{ name, type, duration, chance, dotDamage, statModifiers }
```

扩展后新增字段：
```javascript
{
  name: "燃烧",
  type: "burn",
  element: "fire",      // 元素标签，用于组合反应判定
  dotDamage: 6,         // 每层DOT伤害
  duration: 3,
  chance: 0.8,
  stacks: 1,            // 施加层数
  maxStacks: 3,         // 最大层数
  value: 50,            // 数值型（护盾值、冻结值等）
  evasionMod: 0.25,     // 闪避修正
  speedMod: -0.5,       // 速度百分比修正
  hitRateMod: -0.3      // 命中率修正
}
```

## 三、核心机制实现

### 1. 状态效果层数叠加（applyStatusEffects）

**逻辑**：
- 同类型效果已存在时，检查是否有stacks字段
- 有stacks：层数叠加（不超过maxStacks），刷新持续时间
- 有value：数值累加（冻结值、护盾值）
- 普通效果：刷新持续时间

**冻结特殊逻辑**：
- freeze类型累积value，达到100时自动转换为frozen类型
- frozen类型持续1回合，期间敌人无法行动
- frozen状态下受到火系伤害×2（融化）

### 2. 护盾吸收（applyDamage）

**逻辑**：
- 受到伤害时，先检查目标是否有shield状态
- 护盾优先吸收伤害，护盾值不足时剩余伤害扣HP
- 护盾值归零时移除护盾状态
- 护盾不随时间消失（duration=99），只有被打掉才消失

### 3. 眩晕/冻结跳过回合（isStunned）

**逻辑**：
- 敌人回合开始时检查isStunned，有stun/frozen状态则跳过行动
- 玩家回合开始时检查isStunned，被眩晕则自动跳过，1秒后进入敌人回合
- 日志提示"XX被麻痹/冻结，无法行动！"

### 4. 元素特性伤害加成（calculateDamage + getStatusModifiers）

**逻辑**：
- calculateDamage新增target参数
- 调用getStatusModifiers获取目标所有状态修正
- 根据攻击元素应用对应倍率：
  - 目标有wet/electrified → 雷系伤害×2
  - 目标有frozen → 火系伤害×2
  - 目标有_meltBonus标记 → 火系伤害额外×1.5
- 闪避修正：目标evasionMod降低攻击者命中率

### 5. 元素组合反应（checkElementReactions）

借鉴《神界原罪》的元素组合设计，两种元素状态相遇时产生特殊效果：

| 组合 | 反应 | 效果 |
|------|------|------|
| ⚡雷 + 💧湿润 | 感电 | 湿润→感电，每回合掉15血+持续麻痹 |
| 🔥火 + ❄️冻结 | 融化 | 解除冻结，本回合火系伤害×1.5 |
| 🔥火 + 💧湿润 | 蒸汽 | 湿润→蒸汽，命中率-30% |
| 🪨土 + 💧湿润 | 泥泞 | 湿润→泥泞，速度-50% |

**触发时机**：施加新状态效果时自动检查组合反应。

## 五、第二层：元素组合反应（已实现核心4种）

### 设计思路
鼓励玩家思考**技能释放顺序**，而不是无脑放最高伤害技能。

**典型连招示例**：
1. **水雷感电流**：水锁挂湿润 → 雷印触发感电 → 持续掉血+麻痹
2. **冰火融化流**：冰蔓冻结 → 火滋引爆 → 冻结中火系×2+融化×1.5 = 3倍伤害
3. **水土控制流**：水锁挂湿润 → 地刺触发泥泞 → 速度-50%

### 待扩展反应
- 🌪️风 + 🔥火 = 火焰风暴（燃烧扩散）
- ✨光 + 🌑暗 = 湮灭（双方大量伤害）
- ❄️冰 + 💧水 = 冰冻（直接冻结）

## 六、第三层：回合策略机制（规划中）

### 1. 弱点打击奖励（借鉴《女神异闻录》1 More）
- 攻击敌人弱点元素时，有概率获得额外行动
- 或获得"星子加速"（下技能引导时间-1）

### 2. 破防机制（借鉴《八方旅人》Break）
- 敌人有"僵直值"，受弱点攻击降低
- 破防后眩晕1回合，受到伤害×2
- 玩家也可以被破防

### 3. 引导策略深化
- 加速引导：额外消耗MP，缩短1回合
- 蓄力引导：伤害+50%，延长1回合
- 硬抗引导：受到伤害+50%但不被打断

## 七、经验沉淀与踩坑记录

### 1. 状态效果类型命名一致性
- **问题**：原有麻痹用type:"paralyze"，新机制用type:"stun"判定眩晕
- **解决**：统一用stun表示"跳过回合"类效果，paralyze改为stun
- **教训**：新增机制前先梳理现有类型，避免同义不同名

### 2. calculateDamage参数扩展的连锁修改
- **问题**：calculateDamage新增target参数后，所有调用处都要改
- **解决**：用Grep找到所有调用处（3处），逐一修改
- **教训**：修改核心函数签名前，先搜索所有调用点

### 3. Edit工具的匹配问题
- **问题**：修改wind_speed时，old_string只匹配了部分内容，导致替换后留下残余代码
- **解决**：语法检查发现错误，读取上下文后删除残余
- **教训**：Edit的old_string要完整匹配到唯一位置，替换后立即语法检查

### 4. 护盾不随时间消失的设计
- **问题**：护盾如果有duration，会在还没被打掉时消失
- **解决**：护盾duration设为99，tickStatusEffects中shield类型不减少duration，只在value<=0时移除
- **教训**：不同类型的状态效果需要不同的生命周期逻辑

### 5. 元素反应的触发时机
- **问题**：元素反应应该在什么时候检查？
- **解决**：在applyStatusEffects中，每次施加新效果后检查组合反应
- **教训**：反应系统要和状态施加系统解耦，用独立函数处理

## 八、平衡调整建议（后续测试后优化）

### 当前数值可能的问题
1. 燃烧DOT 6/层×3层=18/回合，可能偏高
2. 冻结值35/次，3次就能冻结，可能太快
3. 麻痹30%概率，可能偏高或偏低
4. 护盾50点，前期可能太强

### 平衡原则
- 控制类效果（冻结/麻痹）概率不宜过高，否则玩家无脑控
- DOT类效果总伤害应低于直接伤害，但胜在持续
- 护盾值应略低于同级直接伤害，鼓励进攻而非龟缩
- 元素组合反应的加成应明显，但不破坏平衡
