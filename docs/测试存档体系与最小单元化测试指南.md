## 一、为什么需要测试存档体系

### 1.1 传统测试的问题

- **从头玩太慢**：每次测试都要从新建角色开始，浪费大量时间
- **测不到后期**：很多后期内容需要玩很久才能到，测试覆盖率低
- **难以复现**：某个特定条件下的bug，很难精确复现
- **单元测试难**：想单独测某个系统，必须先玩到那个阶段

### 1.2 测试存档体系的优势

- **秒级启动**：直接从特定进度开始，不用从头玩
- **全覆盖**：每个系统、每个阶段都有对应的存档
- **精确复现**：bug复现直接用对应存档，100%复现
- **单元化测试**：想测什么系统就用什么存档，专注高效
- **并行测试**：多个Agent同时从不同存档开始测，效率翻倍

## 三、最小单元化测试方法

### 3.1 什么是最小单元化测试

把游戏拆成一个个独立的测试单元，每个单元只测一个特定功能或场景，用对应的存档直接开始测试。

**核心原则**：
- 一次只测一个东西
- 用对应存档直接开始
- 测完就结束，不用继续玩
- 黑盒状态，纯玩家视角

### 3.2 测试单元划分

#### 按系统划分
1. **角色系统单元**：属性、等级、技能、觉醒
2. **战斗系统单元**：普通攻击、技能、状态、逃跑、元素克制
3. **任务系统单元**：接取、进度、完成、奖励、任务链
4. **地图系统单元**：移动、解锁、地点行动、NPC分布
5. **背包系统单元**：物品、使用、装备、数量
6. **商店系统单元**：购买、出售、价格、声望折扣
7. **日常系统单元**：签到、每日任务、刷新
8. **大事件单元**：触发、推进、分支、结局
9. **存档系统单元**：保存、读取、版本迁移
10. **UI界面单元**：各面板、按钮、显示、响应

#### 按场景划分
1. **新手场景**：刚创建角色，前10分钟
2. **初期场景**：1-3级，学校阶段
3. **中期场景**：4-7级，探索阶段
4. **后期场景**：8级+，大事件阶段
5. **战斗场景**：专门测战斗的存档
6. **经济场景**：专门测经济的存档

### 3.3 单元测试指令模板

给测试Agent的指令要明确：
- 从哪个存档开始
- 测什么内容
- 重点关注什么
- 测到什么程度结束

**通用模板**：
```
你的任务是：测试游戏的【XX系统】。

测试起点：使用存档【save_xx_xxx.json】，从这个进度开始玩。
测试重点：专注测试【XX系统】的各个功能点
测试方式：自然游玩，从玩家角度体验，不要知道代码实现

你需要做的：
1. 从指定存档开始游戏
2. 重点测试【XX系统】的所有功能
3. 尝试各种操作和边界情况
4. 记录所有bug和体验问题
5. 测完这个系统就结束，不用继续玩其他内容

bug严重程度：
- 严重：系统崩溃、功能完全不能用
- 较重：重要功能有问题、数据异常
- 中等：体验问题、显示错误
- 轻微：文字错误、小瑕疵

最后输出测试报告：
- 测试了哪些功能点
- 发现的bug列表（按严重程度）
- 体验问题和建议
- 整体评价
```

**战斗专项测试示例**：
```
你的任务是：测试游戏的战斗系统。

测试起点：使用战斗测试存档，从雪峰山开始
测试重点：战斗系统的所有方面
测试方式：自然游玩，多打怪，多试技能

你需要测试：
1. 普通攻击是否正常
2. 所有技能是否正常
3. 各种状态效果（灼烧、冻结、眩晕等）
4. 元素克制关系
5. 战斗道具使用
6. 逃跑功能
7. 战斗胜利/失败结算
8. 战斗会不会卡住或崩溃

重点关注：
- 战斗过程中有没有卡死
- 伤害数值对不对
- 技能效果有没有问题
- 状态效果有没有问题
- 战斗流程顺不顺畅
```

## 四、如何使用测试存档

### 4.1 导入存档到浏览器

**方法一：通过控制台导入**
1. 打开游戏页面
2. 按 F12 打开开发者工具
3. 切换到 Console 标签
4. 执行：`localStorage.setItem('quanzhi_fashi_save', '存档JSON字符串')`
5. 刷新页面，点击"继续游戏"

**方法二：通过导入工具**
（待开发：导入/导出存档工具页面）

### 4.2 测试Agent使用流程

1. **准备阶段**：
   - 选择对应的测试存档
   - 把存档导入浏览器localStorage
   - 打开游戏，确认存档正确

2. **测试阶段**：
   - 给测试Agent明确的测试范围
   - 让Agent从存档开始测试
   - Agent记录所有发现的问题

3. **结束阶段**：
   - Agent输出测试报告
   - 整理bug列表
   - 分配优先级，进入修复流程

## 五、测试存档维护规范

### 5.1 存档更新时机

- **版本更新后**：大版本更新后，重新生成所有测试存档
- **数据结构变更**：存档格式变更后，重新生成
- **新系统上线**：添加对应新系统的测试存档
- **bug修复后**：如果bug影响存档数据，重新生成

### 5.2 存档生成方法

**手动生成**：
1. 正常玩游戏到特定进度
2. 保存游戏
3. 导出localStorage中的存档数据
4. 保存为JSON文件到 tests/saves/ 目录

**工具生成**（推荐）：
- 使用存档生成工具，直接修改参数生成
- 可以精确控制等级、金币、物品、任务进度等
- 快速生成各种测试用存档

### 5.3 存档版本管理

- 每个存档文件头部注明对应游戏版本
- 版本更新时，标记旧存档是否兼容
- 不兼容的存档重新生成
- 保留历史版本存档，用于回归测试

## 六、黑盒测试纪律（重要！）

### 6.1 绝对不能告诉测试Agent的内容

- ❌ 代码实现细节
- ❌ 修复了什么bug
- ❌ 新增了什么功能
- ❌ 数值公式
- ❌ 设计思路
- ❌ 任何内部信息
- ❌ "你帮我测一下XX功能"（这会让Agent特意去测，不是自然发现）

### 6.2 可以告诉的内容

- ✅ 这是个什么游戏
- ✅ 基本操作方式
- ✅ 从哪个存档开始
- ✅ 大概的测试方向（比如"多打打怪"）
- ✅ 发现问题就记录下来

### 6.3 为什么要严格黑盒

- **玩家不知道代码怎么写的**，他们遇到的问题就是真问题
- 如果告诉Agent"我修了XXbug"，Agent会特意去测那个点，而不是自然游玩中发现
- 黑盒发现的bug优先级更高，因为真实玩家也会遇到
- 特意测出来的问题，真实玩家可能根本碰不到

## 七、测试-开发迭代流程

### 7.1 标准迭代循环

```
第1轮：
  → 开发完成新功能/修复bug
  → 生成/更新对应测试存档
  → 启动2-3个测试Agent，从不同存档开始黑盒测试
  → 收集所有bug和反馈
  → 按优先级排序

第2轮：
  → 修复P0/P1级bug
  → 做重要的体验优化
  → 更新测试存档
  → 重新启动Agent测试（验证修复+继续深入）
  → 收集新的bug和反馈

第3轮：
  → 修复剩余bug
  → 继续优化
  → Agent继续测试更深的内容
  → ...

第N轮：
  → bug数量降到可接受水平
  → 体验问题基本解决
  → 测试通过，可以发布
```

### 7.2 并行配合模式

**开发侧（主Agent）**：
- 修复bug
- 做优化
- 新增内容
- 整理和分类bug反馈
- 决定优先级
- 维护测试存档

**测试侧（子Agent）**：
- 玩游戏
- 发现bug
- 记录体验问题
- 验证修复（下一轮测试时自然验证）
- 输出测试报告

**配合方式**：
- 测试和开发并行进行，不要等
- 一批bug修完就丢回去重新测
- 测试中发现的新bug随时加入待修列表
- 形成"测试→修复→再测试→再修复"的快速迭代循环

## 九、实战经验总结

### 9.1 踩过的坑

1. **不要告诉测试Agent开发信息**：一说"我修了XXbug"，Agent就会特意去测那个点，不是自然游玩发现的，参考价值下降
2. **不要给太多指引**：指引太多就不是黑盒了，发现的问题都是你引导出来的
3. **不要只开一个Agent测试**：一个Agent测的太单一，多几个Agent视角更多元
4. **不要测一轮就完事**：第一轮只能发现表面问题，多轮迭代才能发现深层问题
5. **不要忽视体验问题**：bug要修，体验问题也要重视，很多时候体验问题比bug更影响玩家留存
6. **不要每次都从头玩**：浪费时间，用测试存档直接从对应进度开始，效率高10倍

### 9.2 成功经验

1. **测试存档是神器**：有了测试存档，测试效率提升10倍以上
2. **最小单元化很高效**：一次只测一个系统，专注，深入，覆盖率高
3. **详细记录很重要**：每一步操作都记录，复现bug就容易
4. **分级很重要**：严重bug优先修，轻微bug可以攒着一起改
5. **并行效率真的高**：3个Agent并行，相当于3倍测试速度
6. **黑盒发现的bug质量高**：都是真实玩家会遇到的问题
7. **迭代循环效果好**：一轮一轮测下来，质量提升很明显

---

## 结语

测试存档体系 + 最小单元化黑盒测试 = 高效、高质量的测试流程。

核心就是：
1. **用存档跳过前置内容**，直接测想测的东西
2. **一次只测一个单元**，专注深入
3. **纯黑盒**，从玩家角度发现真问题
4. **多Agent并行**，效率翻倍
5. **多轮迭代**，质量逐步提升

用好了，能大大提升产品质量，减少上线后的bug，让用户少操心。

## 无浏览器分层测试体系（v0.94.0新增）

### 设计理念

浏览器测试（控制浏览器、截图、点击）效率低、不可复现、依赖GUI环境。能用代码断言的就不用浏览器，只有真正的视觉/交互体验才用浏览器。

### 四层测试金字塔

```
┌─────────────────────────────────────┐
│  L4: 浏览器体验测试（仅必要时）      │  ← UI布局/交互流畅度/视觉
├─────────────────────────────────────┤
│  L3: 流程集成测试（jsdom模拟）       │  ← 创建角色→修炼→战斗→升级
├─────────────────────────────────────┤
│  L2: 函数逻辑单元测试（Node.js）     │  ← 伤害计算/状态效果/元素克制
├─────────────────────────────────────┤
│  L1: 数据完整性测试（纯Node.js）     │  ← ID唯一/引用完整/必填字段
└─────────────────────────────────────┘
```

| 层级 | 运行环境 | 速度 | 覆盖目标 | 何时用 |
|------|---------|------|---------|--------|
| L1 数据完整性 | 纯Node.js | <1秒 | 数据文件ID不重复、引用不悬空 | 每次改数据后必跑 |
| L2 函数单元 | Node.js | <5秒 | 战斗公式、状态效果、升级逻辑 | 改核心逻辑后必跑 |
| L3 流程集成 | Node.js(轻量) | <15秒 | 经验值计算、升级流程、属性成长、状态转换 | 改成长系统后必跑 |
| L4 浏览器体验 | 真实浏览器 | 慢 | 布局、动画、手感、视觉 | 发版前抽测 |

### 使用方法

```bash
# 运行所有无浏览器测试（L1+L2）
node tests/run.js

# 只运行L1数据完整性测试
node tests/run.js l1

# 只运行L2战斗逻辑测试
node tests/run.js l2

# 直接运行单个测试文件
node tests/unit/data-integrity.js
node tests/unit/battle-logic.js
```

### L1 数据完整性测试（tests/unit/data-integrity.js）

**检查项：**
1. **ID唯一性**：所有数据文件内ID不重复
2. **引用完整性**：
   - 妖魔引用的技能必须在skills.js中存在
   - 商店/任务/掉落引用的物品必须在items.js中存在
   - 任务目标妖魔必须在enemies.js中存在
3. **元素类型有效性**：技能/妖魔的元素类型必须在合法列表中
4. **必填字段**：技能(id/name/type/mpCost)、妖魔(id/name/maxHp/attack/defense)、物品(id/name/type)
5. **数值合理性**：HP/攻击/防御不能为负，MP消耗不能为负
6. **跨文件ID冲突**：技能和物品不应有同名ID（警告级别）

**已发现的真实问题（v0.94.0）：**
- 11个妖魔技能引用缺失（demon_bone_spike, ice_chain等）
- 3个任务奖励物品引用缺失（healing_potion, hunter_badge, magic_book）
- 14个妖魔掉落物品引用缺失（herb, dark_crystal等）

### L2 战斗逻辑单元测试（tests/unit/battle-logic.js）

**测试项：**
1. **元素克制计算**：火克冰1.5x、水克火1.5x、雷克水1.5x、同系抗性0.8x、无属性1.0x
2. **伤害计算**：
   - 基础伤害>0
   - 高攻击伤害更高
   - 高防御伤害更低
   - 100%暴击率触发暴击
   - 0%命中率触发未命中
3. **引导时间计算**：初阶2回合、中阶3回合、未知默认2回合

**实现方式：**
- 用vm沙箱加载battle.js
- 模拟Player、SkillSystem等全局依赖
- 直接调用纯函数（getElementBonus、calculateDamage、getCastTime）
- 不依赖浏览器DOM

### 测试工具（tests/utils.js）

**核心能力：**
- `loadDataFile(filename)`：加载数据文件（自动处理const→var）
- `loadAllData()`：批量加载所有数据文件
- `TestResult`类：测试结果收集器
  - `pass(msg)` / `fail(msg)` / `warn(msg)`
  - `checkUniqueIds(dataObj, dataName)`：检查ID唯一性
  - `checkReferences(refs, targetData, refName, sourceName)`：检查引用完整性
  - `checkRequiredFields(dataObj, dataName, requiredFields)`：检查必填字段
  - `report()`：输出测试报告

### L3 成长流程测试（tests/unit/progression.js）

**测试项：**
1. **经验值阈值计算**：Lv1=80、Lv10=596（初阶区间）、Lv11=500（中阶起点）、经验值随等级递增
2. **玩家初始化**：等级=1、经验=0、升级阈值=80
3. **获得经验与升级**：获得不足经验不升级、获得足够经验升级、升级后阈值提升
4. **属性成长验证**：连续升级后HP/攻击等属性增长

**实现方式：**
