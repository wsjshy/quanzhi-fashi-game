# 全职法师同人游戏 - 架构说明

> v3.0.0架构改造后：Vite + ES Modules模块化架构

## 设计理念

**数据驱动 + 模块化架构**，代码与内容完全分离。
- 引擎代码一次写好，永久复用
- 所有游戏内容用JS对象定义，新增内容只需加数据文件
- 按照小说卷数逐步扩充，每卷对应一个内容包
- v3.0.0起采用ES Modules模块化，支持Vite构建和HMR热更新

### 数据层设计（v3.0.0 ES Modules重构）

原 `engine/data/` 已迁移到 `src/data/`，采用ES Modules（export const）+ window兼容挂载。

- **模块化策略**：每个数据文件 `export const DataXxx = {...}`，同时在 `src/data/index.js` 统一挂载到window
- **合并入口**：`src/data/index.js` import所有模块，export `GameData` 对象，挂载27个变量到window
- **加载顺序**：Vite按依赖图自动加载，`src/main.js` 先import数据层，再import引擎层
- **向后兼容**：window.DataXxx 全局变量仍可用，所有引擎代码无需修改

### 模块化迁移策略（v3.0.0）

采用"export + window兼容"混合模式：
- 每个模块export变量，同时在文件末尾把变量挂到window（`if (typeof window !== 'undefined') window.XXX = XXX`）
- 保持HTML onclick和模块间全局调用的向后兼容
- 模块内部仍使用全局变量互相调用，未改为import引用（阶段二逐步改进）

### 核心文件拆分（v3.0.1进行中）

- `battle-utils.js` ✅ — 战斗纯函数工具（元素克制/名称/倍率）
- `ui-title.js` ✅ — 标题/角色创建界面
- 剩余：ui-map/ui-character/ui-dialogue/ui-shop/ui-battle、battle-action/battle-system、game-state/game-action等

拆分策略：每次拆分一个独立模块，保持向后兼容（原对象方法仍可用，内部委托给新模块），拆分后立即运行128测试验证。

## 核心系统模块

### 1. 玩家系统 (player.js)
- 角色属性：HP、MP、攻击、防御、速度、精神力
- 元素觉醒：已觉醒的元素列表
- 技能列表：已学习的技能
- 背包系统：道具、装备
- 金钱：金币数量
- 等级与经验
- 属性点：升级可分配
- 声望：各势力好感度

### 2. 地图系统 (map.js)
- 地点列表：当前可前往的地点
- 地点功能：每个地点有不同的行动选项
- 移动消耗：时间、金钱
- 解锁条件：某些地点需要满足条件才能进入

### 3. 时间系统 (time.js)
- 天数计数：第 N 天
- 时段：早上、下午、晚上
- 行动消耗时间：不同行为消耗不同时长
- 定时事件：特定天数触发的事件

### 4. 战斗系统 (battle.js)
- 回合制战斗
- 技能释放与冷却
- 元素克制计算
- 状态效果（灼烧、麻痹、减速等）
- 暴击与命中
- 战斗奖励（经验、金币、道具）
- 逃跑机制

### 5. 技能系统 (skill.js)
- 技能数据管理
- 伤害计算
- 状态效果施加
- 技能学习与升级

### 6. 任务系统 (quest.js)
- 任务接取与交付
- 任务进度追踪
- 任务奖励发放
- 任务链支持

### 7. 事件系统 (event.js)
- 随机事件触发
- 选项分支
- 条件判断
- 结果应用

### 8. 商店系统 (shop.js)
- 商品列表
- 购买与出售
- 价格浮动

## 扩展原则

1. **向后兼容**：新增内容不影响已有内容
2. **模块化**：每个内容单元独立成文件
3. **数据驱动**：能用 JSON 配置的就不写代码
4. **渐进式**：从简单到复杂，逐步完善
5. **可复用**：通用内容放在 shared 里
