# 全职法师同人游戏 - 架构说明

> 当前版本：v3.13.0 | 最后更新：2026-09-09
> v3.0.0架构改造后：Vite + ES Modules模块化架构
> v3.0.1核心文件拆分完成 | v3.0.2集中式状态管理

---

## 设计理念

**数据驱动 + 模块化架构**，代码与内容完全分离。
- 引擎代码一次写好，永久复用
- 所有游戏内容用JS对象定义，新增内容只需加数据文件
- 按照小说卷数逐步扩充，每卷对应一个内容包
- v3.0.0起采用ES Modules模块化，支持Vite构建和HMR热更新

## 数据层设计

原 `engine/data/` 已迁移到 `src/data/`，采用ES Modules（export const）+ window兼容挂载。

- **模块化策略**：每个数据文件 `export const DataXxx = {...}`，同时在 `src/data/index.js` 统一挂载到window
- **合并入口**：`src/data/index.js` import所有模块，export `GameData` 对象，挂载27个变量到window
- **加载顺序**：Vite按依赖图自动加载，`src/main.js` 先import数据层，再import引擎层
- **向后兼容**：window.DataXxx 全局变量仍可用，所有引擎代码无需修改

- **UI模块拆分（30+个）**：ui.js从7702行缩减到约1400行（缩减82%）

## 集中式状态管理（v3.0.2已完成）

**`src/engine/game-state.js`** — 统一管理存档序列化/反序列化/版本迁移

- **声明式schema**：70+字段声明一次，自动参与save/load/默认值填充。新增字段只需在STATE_SCHEMA中声明，无需手动改save()/load()
- **版本化迁移链**：6个历史迁移函数，按版本号链式执行，支持版本跳跃
- **Player委托模式**：Player.save()/load()内部委托给GameState，保留fallback兼容，外部接口完全不变
- **子系统统一注册**：Inventory/WorldState/NPCStateSystem通过`registerSubsystem(name, serializer, loader)`注册，统一存档
- **存档校验**：`validateSave()`检查必填字段、数值合理性、JSON格式
- **存档导出/导入**：`exportSave()`/`importSave()`支持base64编码的存档备份和分享
- **设计决策**：Player直接持有运行时状态（性能优先），GameState负责存档/读档/迁移（集中管理），不做字段代理（避免性能损耗和调试困难）

## 扩展原则

1. **向后兼容**：新增内容不影响已有内容
2. **模块化**：每个内容单元独立成文件
3. **数据驱动**：能用JS对象配置的就不写代码
4. **渐进式**：从简单到复杂，逐步完善
5. **可复用**：通用内容放在共享模块里
6. **小说驱动**：涉及小说内容必须先读原文验证，不凭记忆编造

## 构建与运行

- **直接打开**：双击根目录 `index.html` 即可运行（已包含构建产物，无需服务器）
- **开发模式**：`npm run dev`，访问 http://localhost:5173（支持热更新）
- **重新构建**：`npm run build:copy`，构建并复制到根目录
- **一键构建并运行**：`npm run play` 或双击 `build-and-play.bat`
- **自动化测试**：`node tests/run.js`（L1数据+L2战斗+L3成长，0.1秒出结果）
