# v0.73.0 游戏节奏优化

> 版本：v0.73.0
> 日期：2026-08-16
> 类型：体验优化 / 系统设计
> 目标：降低探索压力，优化游戏节奏，明确地图连通性，设计地图动态变化框架

---

## 一、当前游戏节奏问题分析

### 1.1 遇敌概率现状
- 旅行遇敌：encounterRate * 0.15（默认3%）
- 行动遇敌：encounterRate * actionModifier
  - 猎魔：2.0倍（40%）
  - 探索：默认0.3倍（6%）
  - 修炼：0.5倍（10%）
  - 上课：0.1倍（2%）
  - 休息/购物/聊天：0倍
- 精英概率：白天10%/夜晚15%（在触发战斗后判定）

### 1.2 事件触发现状
- 旅行事件：15%概率
- 行动事件：由action.eventChance决定
- 问题：旅行时15%事件+3%战斗，接近20%概率被打断，可能偏频繁

### 1.3 地图系统问题
- **连通性不明确**：地点数据没有connectedTo字段，玩家不清楚哪些地点可以互相到达
- **静态地图**：所有地点永久存在，没有随剧情变化
- **大本营固定**：永远是天澜魔法高中，没有随剧情迁移

### 1.4 用户需求
- "压力更小地探索" - 减少频繁打断
- "良好的游戏节奏" - 修炼/探索/战斗的时间分配合理
- "地图连通性明确" - 玩家清楚移动路线
- "大本营随剧情变化" - 博城灾难后学校可能变化，上课日常不会永远有

---

## 二、优化方案

### 2.1 减少探索打断

**旅行事件概率调整**：
- 旅行事件：15% → 10%
- 旅行遇敌：保持3%（encounterRate * 0.15）
- 综合打断概率：从~18%降到~13%

**行动事件优化**：
- 探索类行动的eventChance统一检查，避免过高
- 连续探索时增加"平静期"（连续2次无事件后，第3次事件概率减半）

### 2.2 优化修炼效率

**修炼经验提升**：
- 普通修炼：经验+20%（让修炼更有价值）
- 冥修：经验+30%（高级修炼方式收益更高）
- 上课：保持不变（有剧情和社交价值）

**时间消耗优化**：
- 修炼时间：2小时 → 1.5小时（减少等待感）
- 冥修时间：3小时 → 2小时
- 休息时间：保持不变

### 2.3 地图分层系统（大地图-小场景）

**核心设计原则**：一个大地图 = 一个完整剧情周期。大地图与剧情深度绑定，剧情推进时大地图的状态、可用地点、大本营都会变化。

**大地图划分**（基于小说剧情周期）：

1. **博城**（博城篇剧情周期：入学→博城灾难→灾后）
   - 剧情阶段：pre_disaster（灾难前）→ during_disaster（灾难中）→ post_disaster（灾后）
   - 大本营：天澜魔法高中（灾难前/中）→ 临时安置点（灾后）
   - 小场景：学校、市街、穆家庄园、莫凡家、地圣泉、三步塔、雪峰山等

2. **后续大地图**（待小说拆解到对应阶段时添加）
   - 古都篇、上海篇、世界学院篇等
   - 每个大地图有独立的剧情周期和地点

**数据结构设计**：
```javascript
// 大地图数据（maps.js）
const DataMaps = {
  bo_city: {
    id: "bo_city",
    name: "博城",
    storyArc: "博城篇", // 所属剧情周期
    description: "...",
    icon: "🏙️",
    connectedTo: ["xuefeng_mountain"],
    phases: {
      pre_disaster: {
        baseCamp: "tianlan_school", // 大本营
        unlockedLocations: [...], // 该阶段解锁的地点
        disabledActions: [] // 该阶段禁用的行动
      },
      during_disaster: {
        baseCamp: "tianlan_school",
        unlockedLocations: [...],
        disabledActions: ["study"] // 灾难中停课
      },
      post_disaster: {
        baseCamp: "temporary_shelter",
        unlockedLocations: [...],
        disabledActions: ["study", "train"] // 灾后学校功能变化
      }
    },
    locations: [...] // 所有可能的小场景
  }
};
```

**剧情驱动的地图变化**：
- 剧情节点触发时，调用`MapSystem.changePhase(mapId, newPhase)`
- 自动更新大本营、解锁/锁定地点、禁用/启用行动
- 玩家可以感受到世界在变化，而不是静态地图

**当前阶段实现**：
- v0.73.0实现大地图数据结构和分类
- 博城篇pre_disaster阶段的地点分类
- UI显示所属大地图名称
- 完整的剧情阶段切换在后续版本实现

### 2.4 地图动态变化框架（设计预留）

**核心设计**：地图状态随剧情节点变化，地点的可用性、功能、连接关系都会改变。

**阶段划分**（基于小说时间线）：
1. **博城学习期**（第1天-博城灾难前）
   - 大本营：天澜魔法高中
   - 主要活动：上课、修炼、城市探索
   - 可用地点：学校、城市街道、雪峰山、穆家等

2. **博城灾难期**（博城灾难事件）
   - 城市部分区域封锁
   - 学校功能暂停（上课不可用）
   - 新增灾难相关地点和事件

3. **灾后重建/迁移期**（博城灾难后）
   - 学校可能搬迁或功能变化
   - 大本营可能变化（如临时安置点）
   - 上课日常减少或消失
   - 新增新的城市/地点

**技术实现**：
- 地点新增`phase`字段：可用的剧情阶段
- 地点新增`unlockCondition`：解锁条件（剧情节点/等级/任务）
- 地点新增`disableCondition`：禁用条件
- 地点的actions可以按阶段动态显示/隐藏
- 新增`MapSystem.updateMapPhase(storyPhase)`方法，根据剧情阶段更新地图状态

**当前阶段实现**：
- v0.73.0只实现框架和数据结构
- 博城灾难后的地图变化在后续版本（拆解到对应剧情时）实现
- 当前先确保博城学习期的地图连通性正确

## 四、平衡验证

### 4.1 探索节奏测试
- 连续10次旅行，统计被打断次数
- 连续5次探索，统计事件/战斗频率
- 目标：平均3-4次行动有1次打断，而非每次都打断

### 4.2 修炼效率测试
- 从Lv1到Lv5需要多少次修炼
- 修炼时间占总游戏时间的比例
- 目标：修炼有价值但不强制刷

### 4.3 地图连通性测试
- 所有地点都有明确的connectedTo
- 从任意地点可以到达其他已解锁地点
- 没有孤立地点
