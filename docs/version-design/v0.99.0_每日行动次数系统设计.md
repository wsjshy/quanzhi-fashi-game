# v0.99.0 每日行动次数系统设计（替代体力）

> 设计日期：2026-08-17
> 目标版本：v0.99.0
> 核心思路：用"每日次数+效率递减"替代体力系统，减少双资源管理负担
> 设计原则：时间是叙事刻度，重复行为自然递减，玩家无需做资源选择题

---

## 一、问题诊断

### 1.1 当前系统的问题

当前游戏同时管理三个资源：
| 资源 | 作用 | 玩家负担 |
|------|------|---------|
| 时间 | 每天24小时，行动消耗1-8h | 高（需要规划时间分配） |
| 体力 | 行动消耗，低体力影响效率 | 中（已软化，但仍需关注） |
| HP/MP | 战斗消耗，需恢复 | 低（战斗后恢复15%/20%） |

**核心问题**：时间和体力实际上在做同一件事——限制行动频率。但用两个独立系统，导致：
- 玩家认知负担翻倍（同时管两个资源）
- 行动成本被双重计算（修炼既耗时间又耗体力）
- 恢复成本叠加（恢复体力要时间，恢复HP/MP也要时间）

### 1.2 用户洞察

> "修炼和一些行为，每天能进行的次数都是有限的，或者重复做效率会变低，这样玩家就不用做各种选择，从而造成负担，由此也就不用有体力设定了。"

**关键洞察**：
- 体力的本质是"防止玩家无限重复同一行为"
- 可以用"每日次数+效率递减"达到同样目的
- 去掉体力后，玩家只需要管时间，认知负担减半

---

## 二、核心设计方案

### 2.1 设计原则

```
时间是唯一硬限制（叙事刻度，不能去掉）
重复行为自然递减（第N次效率降低，引导多样化）
无体力条（玩家不需要管理第二个资源）
战斗风险用连续次数控制（而非体力）
```

### 2.2 每日行动次数系统

#### 行动分类与递减规则

| 行动类型 | 代表行动 | 递减规则 | 说明 |
|---------|---------|---------|------|
| **修炼** | 修炼魔法、闭关 | 1-3次100%，4-6次70%，7次后50% | 防止无限刷级 |
| **猎魔** | 猎魔、探索狩猎场 | 1-3次100%奖励，4-6次70%，7次后50% | 防止无限刷怪 |
| **逛街/探索** | 逛街、地图移动 | 1-5次有随机事件，之后无随机事件 | 移动本身不限制 |
| **对话/社交** | 找人聊天、酒馆 | 无限制 | 本来就不耗体力 |
| **休息** | 原地休息、充分休息、宿舍睡眠 | 无限制 | 恢复HP/MP |
| **商店/阅读** | 魔法商店、图书馆 | 无限制 | 本来就不耗体力 |

#### 递减效果说明

**修炼递减**：
- 第1-3次：经验100%，随机事件概率正常
- 第4-6次：经验70%，随机事件概率50%
- 第7次后：经验50%，无随机事件

**猎魔递减**：
- 第1-3次：金币/经验/掉落100%
- 第4-6次：金币/经验/掉落70%
- 第7次后：金币/经验/掉落50%
- 战斗难度不变（保持挑战性）

**逛街递减**：
- 第1-5次：有概率触发随机事件
- 第6次后：纯移动，无随机事件（但仍可去商店/酒馆）

### 2.3 体力系统移除

#### 移除内容
1. `Player.stamina` / `Player.maxStamina` 字段
2. `Player.consumeStamina()` / `Player.restoreStamina()` 方法
3. `Player.getStaminaEfficiency()` / `Player.getStaminaLevel()` 方法
4. `locations.js` 中所有 `staminaCost` 字段
5. UI右侧面板的体力条显示
6. 休息行动中的体力恢复效果

#### 保留/迁移内容
1. **战斗受伤概率**：从"体力=0时可能受伤"改为"连续战斗第4次后可能受伤"
2. **疲劳状态**：从"低体力疲劳"改为"连续修炼/猎魔第7次后疲劳提示"
3. **休息功能**：保留，但只恢复HP/MP，不恢复体力

### 2.4 每日重置机制

- 每天0:00（或玩家睡眠后）重置所有行动计数
- 计数存储在 `Player.dailyActions = { cultivate: 0, hunt: 0, explore: 0 }`
- 新的一天开始时，所有计数归零
- 存档迁移：老玩家的stamina数据忽略，dailyActions初始化为0

## 三、具体改动清单

### 3.1 engine/player.js

**移除**：
- `maxStamina: 100` / `stamina: 100` 字段
- `consumeStamina(amount)` 方法
- `restoreStamina(amount)` 方法
- `fullRestoreStamina()` 方法
- `getStaminaLevel()` 方法
- `getStaminaEfficiency()` 方法
- `fatigueLevel` 字段（改为dailyFatigue）

**新增**：
```javascript
// 每日行动计数
dailyActions: {
    cultivate: 0,  // 修炼次数
    hunt: 0,       // 猎魔次数
    explore: 0     // 探索/逛街次数
},

// 获取修炼效率倍率
getCultivateEfficiency() {
    const count = this.dailyActions.cultivate;
    if (count < 3) return 1.0;
    if (count < 6) return 0.7;
    return 0.5;
},

// 获取猎魔奖励倍率
getHuntEfficiency() {
    const count = this.dailyActions.hunt;
    if (count < 3) return 1.0;
    if (count < 6) return 0.7;
    return 0.5;
},

// 重置每日计数（新的一天）
resetDailyActions() {
    this.dailyActions = { cultivate: 0, hunt: 0, explore: 0 };
},

// 记录行动
recordAction(type) {
    if (this.dailyActions[type] !== undefined) {
        this.dailyActions[type]++;
    }
}
```

### 3.2 engine/data/locations.js

**改动**：
- 移除所有 `staminaCost` 字段
- 新增 `actionType` 字段（用于计数）：
  - 修炼类：`actionType: 'cultivate'`
  - 猎魔类：`actionType: 'hunt'`
  - 逛街/探索类：`actionType: 'explore'`
  - 其他：不设actionType（无限制）

**示例**：
```javascript
// 修炼
{
    id: 'cultivate_1h',
    name: '修炼1小时',
    timeCost: 1,
    actionType: 'cultivate',  // 新增
    // staminaCost: 15,  // 移除
    ...
}

// 猎魔
{
    id: 'hunt',
    name: '猎魔',
    timeCost: 2,
    actionType: 'hunt',  // 新增
    // staminaCost: 25,  // 移除
    ...
}
```

### 3.3 engine/game.js

**改动**：
- `performAction()` 中移除 `Player.consumeStamina()` 调用
- 修炼行动：应用 `Player.getCultivateEfficiency()` 到经验奖励
- 猎魔行动：应用 `Player.getHuntEfficiency()` 到金币/经验/掉落
- 新的一天开始时：调用 `Player.resetDailyActions()`
- 行动完成后：调用 `Player.recordAction(actionType)`

### 3.4 engine/battle.js

**改动**：
- 受伤概率逻辑：从"体力=0时可能受伤"改为"连续猎魔第4次后可能受伤"
- 战斗结束时：如果是猎魔触发的战斗，调用 `Player.recordAction('hunt')`

### 3.5 engine/ui.js

**改动**：
- 右侧角色面板：移除体力条显示
- 修炼/猎魔行动按钮：显示今日剩余高效次数（如"今日高效修炼：2/3"）
- 行动结果提示：显示效率倍率（如"修炼效率：70%（今日第4次）"）

### 3.6 存档迁移

- 加载老存档时，忽略 `stamina` / `maxStamina` 字段
- `dailyActions` 初始化为 `{ cultivate: 0, hunt: 0, explore: 0 }`
- 版本号检测：v0.98.x及之前的存档需要迁移

## 四、体验预期

### 4.1 玩家体验变化

| 维度 | 改前 | 改后 |
|------|------|------|
| 资源管理 | 时间+体力+HP/MP | 时间+HP/MP |
| 修炼体验 | 算时间+算体力+怕疲劳 | 算时间，前3次高效，之后自然慢下来 |
| 探索体验 | 怕体力不够不敢去新地图 | 随时可以去，前5次有惊喜 |
| 休息体验 | 恢复体力+HP/MP，需要频繁休息 | 只恢复HP/MP，战斗后休息即可 |
| 多样化引导 | 靠体力不足强制 | 靠效率递减自然引导 |

### 4.2 设计验证点

1. **减负效果**：玩家是否不再需要频繁查看体力？
2. 多样化引导：玩家是否会自然尝试不同行动？
3. 节奏控制：升级速度是否合理（前3次高效+之后递减）？
4. 战斗风险：连续战斗受伤机制是否合理？

## 七、全面影响分析（19个文件）

### 7.1 物品系统（data/items.js + inventory.js）
- **体力药水**：改为"活力药水"，效果改为恢复20HP+20MP（保留物品价值）
- **商店**：体力药水保留但改效果，不新增/移除物品
- **任务奖励**：quests.js中体力药水奖励自动继承新效果

### 7.2 事件系统（event.js + data/events.js）
- 随机事件中`effects.stamina > 0`（恢复体力）→ 改为恢复HP/MP或给金币
- 随机事件中`effects.stamina < 0`（消耗体力）→ 改为消耗少量HP或无效果（仅文案）
- 原则：事件奖励/惩罚不消失，只是换一种资源体现

### 7.3 遭遇系统（encounter.js）
- 遭遇事件中`type: 'stamina'`消耗 → 改为`type: 'hp'`消耗少量HP（探索疲惫体现为轻伤）
- 或改为无资源消耗，仅文案提示

### 7.4 大事件系统（big-event.js + data/big-events.js）
- 大事件中`effects.stamina` → 同步改为HP/MP效果
- 博城灾难等大事件中的体力消耗改为HP消耗（战斗疲惫）

### 7.5 时间系统（time.js）
- 移除：每天早上恢复满体力
- 移除：等待消耗少量体力
- 移除：休息时体力恢复比例
- 移除：深夜体力消耗倍率
- 新增：新的一天开始时重置dailyActions
- 保留：时间流逝、HP/MP自然恢复

### 7.6 战斗系统（battle.js）
- 移除：`getStaminaEfficiency()`调用（v0.9.7已始终1.0，直接删除）
- 改动：疲劳减益从"低体力受伤"改为"连续猎魔第4次后10%概率受伤"
- 新增：战斗结束时如果是猎魔触发，记录hunt次数

### 7.7 调试系统（debug.js）
- 移除：体力输入框、设置体力按钮、恢复体力按钮
- 移除："满血满蓝满体力"改为"满血满蓝"
- 新增：重置每日行动次数按钮（测试用）

### 7.8 UI系统（ui.js）
- 移除：右侧面板体力条
- 新增：修炼/猎魔按钮显示"今日高效：N/3"
- 新增：行动结果显示效率倍率（如"修炼效率70%"）
- 调整：右侧面板布局，体力条位置改为显示今日行动概览

### 7.9 存档迁移
- 老存档加载时：忽略`stamina`/`maxStamina`字段
- `dailyActions`初始化为`{ cultivate: 0, hunt: 0, explore: 0 }`
- 版本检测：v0.98.x及之前的存档自动迁移

### 7.10 节奏影响评估
| 维度 | 改前 | 改后 | 评估 |
|------|------|------|------|
| 日修炼次数 | 受体力限制约5-8次 | 时间限制约3-12次，前3次高效 | 前期更快，后期自然减速 |
| 日猎魔次数 | 受体力+HP限制约3-5次 | 时间+HP限制约3-6次，前3次满奖励 | 基本一致，奖励递减防刷 |
| 探索自由度 | 怕体力不够 | 无体力顾虑，随时可去 | 显著提升 |
| 金币获取 | 体力限制 | 猎魔递减+时间限制 | 略降，需调优商店价格 |
| 升级速度 | 体力+时间双限制 | 时间单限制+递减 | 前期略快，需监控 |

## 八、不做的事

1. 不改变时间系统（时间仍是叙事刻度）
2. 不改变HP/MP系统（战斗资源保留）
3. 不增加新的资源类型（只做减法）
4. 不改变战斗核心机制（只改受伤概率来源）
