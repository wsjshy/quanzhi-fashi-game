# v3.0.0 架构改造设计文档

> 版本：v3.0.0 | 状态：设计中 | 最后更新：2026-08-22
> 目标：引入Vite + ES Modules，解决无模块化、核心文件过大、逻辑UI耦合等扩展性瓶颈

---

## 一、改造背景

### 当前架构问题

| 问题 | 严重度 | 具体表现 |
|------|--------|---------|
| 无模块化系统 | P0 | 58个`<script>`手动排序，全局变量，无import/export |
| 核心文件过大 | P0 | battle.js 8471行 / ui.js 7485行 / game.js 5211行 |
| 逻辑与UI耦合 | P1 | battle.js有36处直接DOM操作 |
| 上帝对象模式 | P1 | game.js直接引用其他系统157处 |
| 内联样式泛滥 | P1 | ui.js大量style="..."，无CSS类名 |
| 手动存档序列化 | P2 | Player.save()手动列60+字段，易遗漏 |
| 无类型系统 | P2 | 纯JS无TypeScript，数据结构变更无编译期检查 |

### 改造原则

1. **渐进式，不重写** — 每一步都可交付，功能不变，用128测试回归
2. **向后兼容** — 阶段一保持全局对象可访问（window.Game等），HTML onclick不破坏
3. **测试驱动** — 每迁移一批模块就跑全量测试
4. **最小风险** — 先迁移动纯数据层，再迁移引擎层，最后改入口

---

## 二、阶段一：Vite + ES Modules（本次实施）

### 目标

- 引入Vite作为构建工具
- 所有模块改为`export/import`，消除隐式全局依赖
- index.html改为单入口`<script type="module">`
- 保持向后兼容（关键对象挂到window）

### 实施方案

#### 2.2 模块改造规则

**数据文件（纯数据，最简单）：**
```js
// 改造前
const DataSkills = { ... };

// 改造后
export const DataSkills = { ... };
export default DataSkills;
```

**引擎文件（有依赖）：**
```js
// 改造前
const BattleSystem = {
    attack() {
        const skill = DataSkills[player.skills[0]];  // 隐式全局依赖
        UI.showDamage(...);  // 隐式全局依赖
    }
};

// 改造后
import { DataSkills } from '../data/skills.js';
import { UI } from './ui.js';

export const BattleSystem = {
    attack() {
        const skill = DataSkills[player.skills[0]];
        UI.showDamage(...);
    }
};
```

**入口文件 main.js：**
```js
import { Game } from './engine/game.js';
import { UI } from './engine/ui.js';
import { Player } from './engine/player.js';
import { BattleSystem } from './engine/battle.js';
// ... 所有模块

// 向后兼容：挂到window，HTML onclick和旧代码继续工作
window.Game = Game;
window.UI = UI;
window.Player = Player;
window.BattleSystem = BattleSystem;
// ...

// 启动游戏
Game.init();
```

### 风险与应对

| 风险 | 应对 |
|------|------|
| 循环依赖（A import B, B import A） | 入口文件统一组装，模块间尽量单向依赖；必要时用延迟import |
| HTML onclick访问不到模块函数 | 入口文件把关键对象挂到window |
| 测试框架不支持ES Modules | 用Node.js原生ESM支持（.mjs或package.json type:module） |
| 迁移过程中功能破坏 | 分批迁移，每批跑128测试；保留旧engine/目录可回退 |
| Vite构建后路径问题 | base: './'确保相对路径，assets用绝对路径 |

### 验收标准

- [ ] `npm run dev`启动开发服务器，游戏正常运行
- [ ] `npm run build`打包成功，dist/可部署
- [ ] 128个自动化测试全部通过
- [ ] 浏览器冒烟测试通过（开始游戏→修炼→战斗→对话→存档）
- [ ] 所有58个模块改为export/import
- [ ] index.html只有一个module script入口
