# v3.22.0 多敌人战斗系统设计

> **版本**：v3.22.0
> **日期**：2026-09-12
> **状态**：设计完成，待实施
> **依据**：v3.21.0白阳BOSS战需要支持幽狼兽+两只黑畜妖同时出现

---

## 一、目标

1. **支持多敌人同时战斗**：玩家可以同时面对多个敌人（如白阳+幽狼兽+两只黑畜妖）
2. **目标选择**：玩家可以选择攻击哪个敌人
3. **敌人轮流行动**：每个敌人都有自己的回合，按速度排序行动
4. **战斗结束条件**：所有敌人被击败后战斗结束
5. **UI支持**：战斗界面显示多个敌人的HP条和状态

---

## 二、设计原则

1. **向后兼容**：现有单敌人战斗不受影响，多敌人是扩展功能
2. **最小改动**：基于现有战斗系统修改，不重构核心架构
3. **渐进式实施**：先实现核心功能，再优化UI和体验
4. **数据驱动**：多敌人配置通过数据文件定义，不改代码

---

## 三、数据结构设计

### 3.1 敌人数据扩展

现有敌人数据（enemies.js）保持不变，多敌人通过战斗启动参数配置：

```javascript
// 单敌人（现有方式，保持兼容）
BattleSystem.startBattle(enemyData);

// 多敌人（新增方式）
BattleSystem.startBattle({
    id: "bai_yang_boss",
    name: "白阳+召唤兽",
    enemies: [
        { ...enemyData1, position: "center" },  // 白阳
        { ...enemyData2, position: "left" },    // 幽狼兽
        { ...enemyData3, position: "right" }    // 黑畜妖
    ],
    // 其他战斗选项
});
```

### 3.2 战斗状态扩展

```javascript
// 战斗状态
this.enemy = null;        // 保留：当前选中的敌人（兼容现有代码）
this.enemies = [];        // 新增：所有敌人数组
this.currentEnemyIndex = 0;  // 新增：当前行动的敌人索引
this.selectedEnemyIndex = 0; // 新增：玩家选中的攻击目标索引
```

## 四、核心逻辑设计

### 4.1 战斗启动

1. 检查enemyData是否包含enemies数组
2. 如果包含，初始化多敌人模式
3. 如果不包含，使用现有单敌人模式（向后兼容）
4. 按速度排序敌人行动顺序

### 4.2 玩家回合

1. 玩家选择技能/道具/防御
2. 如果是攻击技能，需要选择攻击目标（默认选中第一个敌人）
3. 执行攻击，对选中的敌人造成伤害
4. 检查被攻击的敌人是否死亡，如果死亡，从enemies数组中移除
5. 检查所有敌人是否都死亡，如果是，战斗胜利

### 4.3 敌人回合

1. 按速度排序，每个敌人轮流行动
2. 每个敌人选择技能并攻击玩家（或队友）
3. 检查玩家是否死亡，如果死亡，战斗失败
4. 所有敌人行动完毕后，回到玩家回合

### 4.4 战斗结束

1. **胜利条件**：所有敌人HP <= 0
2. **失败条件**：玩家HP <= 0
3. **逃跑条件**：玩家成功逃跑（多敌人战斗逃跑成功率降低）

## 五、UI设计

### 5.1 敌人信息显示

1. 单敌人模式：显示一个大的敌人信息框（现有方式）
2. 多敌人模式：显示多个小的敌人信息框，横向排列
3. 每个敌人信息框包含：头像/名字/HP条/状态效果
4. 选中的敌人高亮显示

### 5.2 目标选择

1. 玩家选择攻击技能后，进入目标选择模式
2. 点击敌人信息框选择攻击目标
3. 选中的敌人高亮显示
4. 确认后执行攻击

### 5.3 敌人行动指示

1. 当前行动的敌人高亮显示
2. 敌人行动时显示攻击动画
3. 敌人死亡时显示死亡动画，然后从UI中移除

## 八、测试要点

### 8.1 功能测试用例
1. 多敌人战斗启动：验证enemies数组正确初始化
2. 目标选择：验证玩家可以选择攻击不同的敌人
3. 敌人轮流行动：验证多个敌人按速度排序轮流行动
4. 敌人死亡：验证敌人死亡后从数组中移除
5. 战斗结束：验证所有敌人死亡后战斗胜利
6. 向后兼容：验证单敌人战斗不受影响

### 8.2 体验测试维度
1. 目标选择是否直观易用
2. 多敌人战斗节奏是否合理
3. UI显示是否清晰不拥挤
4. 白阳BOSS战是否有压迫感

### 8.3 Debug支持
1. Debug面板添加多敌人战斗快速启动
2. 可以设置敌人数量和类型
3. 可以跳过敌人回合快速测试

### 8.4 边界情况
1. 只有一个敌人：退化为单敌人模式
2. 所有敌人同时死亡：战斗正确结束
3. 玩家被多个敌人集火：伤害计算正确
4. 敌人速度相同：行动顺序稳定

## 九、风险和应对

### 9.1 风险
1. **改动量大**：需要修改多个战斗子模块，可能引入bug
2. **UI复杂**：多敌人UI可能在手机端显示拥挤
3. **性能问题**：多敌人战斗可能导致性能下降
4. **向后兼容**：修改可能影响现有单敌人战斗

### 9.2 应对
1. **渐进式实施**：分阶段实施，每阶段测试后再继续
2. **响应式UI**：PC端横向排列，手机端纵向排列
3. **性能优化**：限制同时显示的敌人数量（最多4个）
4. **完整测试**：实施后运行完整的自动化测试和黑盒测试
