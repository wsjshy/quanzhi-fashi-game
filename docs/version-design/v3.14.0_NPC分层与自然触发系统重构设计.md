# v3.14.0 NPC分层与自然触发系统重构设计

> **版本**：v3.14.0
> **日期**：2026-09-09
> **状态**：待用户确认
> **核心目标**：解决"对话负担过重"问题，让NPC对话自然出现，减少玩家主动对话压力

---

## 一、问题诊断

### 1.1 当前问题

| 问题 | 表现 | 影响 |
|------|------|------|
| NPC数量过多 | 49个NPC都在NPC列表中显示 | 玩家觉得"有一堆人等着我对话" |
| 全部需要主动点击 | 所有NPC都需要玩家点击才能触发对话 | 对话变成任务，不是体验 |
| 对话密度无控制 | 所有NPC的所有对话一开始就开放 | 玩家不知道先聊谁，产生焦虑 |
| 背景NPC也有完整对话树 | 31个NPC有>5节点对话树 | 很多NPC其实只需要一两句环境台词 |
| 缺乏自然触发 | 对话不会随着剧情/地点/时间自动出现 | 世界不够鲜活，玩家需要主动"找"对话 |

### 1.2 设计理念

> **对话是加分项，不是必选项。**
> 玩家不对话也能推进游戏；对话自然出现时，玩家会觉得"这个世界真鲜活"；
> 玩家主动想聊时，核心NPC有深度内容可挖。

## 二、NPC三层分层机制（动态）

### 2.1 层级定义

| 层级 | 设计 | 触发方式 | 交互方式 |
|------|------|---------|---------|
| **core（核心NPC）** | 完整对话树，有剧情线，关系变化影响剧情 | 主动对话 + 自然触发 | 点击进入完整对话树 |
| **background（背景NPC）** | 环境台词为主，无完整对话树，反映世界观/传闻 | **自然触发为主** | 点击只显示1-2句随机台词 |
| **functional（功能性NPC）** | 商店/任务/修炼等功能，少量对话 | 功能交互时触发 | 点击显示功能菜单+少量对话 |

> **关键：tier不是静态标签，而是随剧情阶段动态变化的。** 详见2.4节。

### 2.2 核心NPC选择规范

**一个NPC是否为core，取决于以下维度：**

| 维度 | 权重 | 判断标准 |
|------|------|---------|
| 剧情参与度 | 30% | 是否有独立剧情线？是否推动主线？ |
| 互动深度 | 25% | 是否有完整对话树？关系变化是否影响游戏？ |
| 出场频率 | 20% | 是否在多个stage持续出场？ |
| 玩家关联 | 15% | 是否与玩家有直接关系（老师/同学/家人/对手）？ |
| 不可替代性 | 10% | 是否有其他NPC可以替代其功能？ |

**评分 ≥ 70分 → core，40-69分 → background（可升级），< 40分 → background**

### 2.4 动态分层机制（核心创新）

> **问题**：NPC的重要性随剧情阶段变化。穆贺在觉醒前很重要，后续可能不重要；徐大荒在猎妖期很重要，但觉醒期只是背景。静态tier无法反映这种变化。

#### 2.4.1 设计原则

- **tier是动态计算的，不是静态标签**
- **每个NPC有一个"重要性曲线"，随stage变化**
- **系统根据当前stage + NPC配置，动态计算实际tier和活跃状态**
- **可复用：后续篇章扩展时，只需配置NPC的activeStages，不需要改代码**

#### 2.4.2 数据结构

```javascript
{
  id: "xu_dahuang",
  name: "徐大荒",
  
  // 基础tier（默认，当没有stage覆盖时使用）
  baseTier: "background",
  
  // 动态tier覆盖：在某些stage变为不同层级
  tierOverrides: {
    "stage_5": "core",   // 猎妖期变为核心
    "stage_6": "core",   // 灾难前仍是核心
    "stage_7": "core"    // 博城灾难期间
  },
  
  // 活跃阶段：在哪些stage有新对话/剧情推进（控制密度）
  activeStages: {
    "stage_5": { priority: 8, hasNewContent: true },
    "stage_6": { priority: 7, hasNewContent: true },
    "stage_7": { priority: 9, hasNewContent: true }
  },
  
  // 非活跃阶段的处理：仍可对话，但不显示"新对话"提示
  inactiveBehavior: "available_no_hint"  // available_no_hint / hidden / disabled
}
```

#### 2.4.3 动态计算逻辑

```
系统启动/ stage变化时：
  ↓
对每个NPC：
  1. 计算实际tier = tierOverrides[currentStage] || baseTier
  2. 计算活跃状态 = activeStages[currentStage] 是否存在
  3. 如果活跃，加入"活跃核心NPC"列表
  ↓
对活跃核心NPC按priority排序
  ↓
取前N个（默认3-5个）显示"新对话"提示
  ↓
其他活跃核心NPC：可对话，但无提示
  ↓
非活跃核心NPC：可对话，但无提示（inactiveBehavior=available_no_hint）
```

#### 2.4.4 核心NPC密度控制

| 控制项 | 默认值 | 说明 |
|--------|--------|------|
| 同时活跃核心NPC上限 | 5个 | 超过则按priority只显示前5个的提示 |
| 同时显示"新对话"提示上限 | 3个 | 避免列表中太多感叹号 |
| 背景NPC同时触发台词上限 | 2条/每次进入地点 | 避免消息条刷屏 |
| 背景NPC触发概率 | 0.3 | 每次检查30%概率触发 |
| 背景NPC冷却时间 | 3游戏小时 | 同一NPC不会频繁触发 |

#### 2.4.5 动态分层的可复用方法论

> **本机制可复用于所有需要"随阶段变化重要性"的内容，不仅仅是NPC。**

**可复用场景**：
- NPC分层（本次实现）
- 地点重要性（某些地点在特定stage才开放/重要）
- 任务优先级（某些任务在特定stage才出现/重要）
- 系统解锁（某些系统在特定stage才开放）

**通用模式**：
```javascript
{
  baseX: "默认值",
  xOverrides: { "stage_N": "阶段N的值" },
  activeStages: { "stage_N": { priority: N, hasNewContent: true } }
}
```

**记录到方法论**：本机制将在实施完成后，总结到 `docs/项目自迭代与创新方法论.md` 中，作为"动态分层设计模式"供后续开发参考。

### 2.5 数据结构变更

#### NPC数据新增字段

```javascript

  name: "赵坤三",
  tier: "background",  // 新增：core / background / functional

```

## 三、自然触发系统（AmbientDialogueSystem）

### 3.1 系统概述

新增独立模块 `src/engine/ambient-dialogue.js`，负责管理背景NPC的环境台词自动触发。

### 3.2 触发类型

| 类型 | 触发时机 | 说明 |
|------|---------|------|
| **location** | 玩家进入新地点时 | 检查该地点的背景NPC，按概率触发台词 |
| **time** | 时间变化时（早上→中午→晚上） | 检查当前地点的背景NPC，触发时间相关台词 |
| **event** | 完成任务/事件/达到等级后 | 触发剧情相关的环境台词 |
| **proximity** | 玩家在地点停留超过N分钟 | 触发额外的环境台词（可选，默认关闭） |

### 3.3 触发流程

```
玩家进入地点
  ↓
AmbientDialogueSystem.checkLocationTriggers(location)
  ↓
获取该地点的所有background NPC
  ↓
对每个NPC：
  - 检查autoTrigger.enabled
  - 检查冷却时间（cooldown）
  - 检查ambientLines中是否有满足当前stage/condition的台词
  - 按chance概率决定是否触发
  ↓
选择优先级最高的1-2条台词触发
  ↓
显示在底部消息条（不弹窗，不打断操作）
  ↓
设置该NPC的冷却时间
```

### 3.4 显示方式

**底部消息条**（复用现有UI.showMessage机制）：
- 显示格式：`[赵坤三] 穆白哥说得对！`
- 3-5秒后自动消失
- 不弹窗，不打断玩家操作
- 多条台词排队显示，不重叠
- 可以在设置中关闭环境台词

### 3.5 与现有系统的集成点

| 集成点 | 修改文件 | 修改内容 |
|--------|---------|---------|
| 移动到地点 | `game-travel.js` | 调用 `AmbientDialogueSystem.checkLocationTriggers(location)` |
| 时间推进 | `game.js` / 时间系统 | 调用 `AmbientDialogueSystem.checkTimeTriggers(time)` |
| 任务完成 | `quest.js` | 调用 `AmbientDialogueSystem.checkEventTriggers(event)` |
| NPC列表渲染 | `game-npc-list.js` | 按tier分层显示，background NPC简化交互 |
| 对话触发 | `ui-dialogue.js` | background NPC点击只显示随机台词 |

## 四、对话密度控制（核心+背景双层控制）

### 4.1 核心NPC对话按阶段解锁

- 核心NPC的dialogueTree节点增加`unlockCondition`
- 只有满足条件的节点才显示在选项中
- 条件类型：等级、任务完成、时间段、好感度、剧情阶段（stage）
- **default节点始终无条件显示**，确保玩家不会卡住

### 4.2 核心NPC活跃状态与密度控制

> **关键：核心NPC也需要控制密度。即使是核心NPC，也不应该同时有太多有新对话/可互动。**

#### 活跃状态机制

每个核心NPC有`activeStages`配置，定义在哪些stage是活跃的：

```javascript
activeStages: {
  "stage_1": { priority: 10, hasNewContent: true },  // 觉醒期活跃
  "stage_2": { priority: 8, hasNewContent: true },   // 觉醒初期活跃
  "stage_5": { priority: 5, hasNewContent: false }   // 猎妖期不活跃（但可对话）
}
```

#### 密度控制规则

| 控制项 | 默认值 | 说明 |
|--------|--------|------|
| 同时活跃核心NPC上限 | 5个 | 超过则按priority只显示前5个的提示 |
| 同时显示"新对话"提示上限 | 3个 | 避免列表中太多感叹号，按priority排序取前3 |
| 非活跃核心NPC行为 | 可对话，无提示 | 玩家仍可主动对话，但不显示"新对话"标记 |
| 活跃优先级计算 | priority + 关系加成 | 与玩家关系好的NPC优先级+2 |

#### 各层级"新对话"提示规则

| 层级 | "新对话"提示 | 说明 |
|------|------------|------|
| core（活跃） | 显示，但最多3个同时显示 | 按priority排序，有新内容时提示 |
| core（非活跃） | 不显示 | 玩家仍可主动对话，但无提示 |
| background | 不显示 | 环境台词自动触发，不需要提示 |
| functional | 仅在有新任务时显示 | 功能优先 |

### 4.3 背景NPC环境台词密度控制

| 控制项 | 默认值 | 说明 |
|--------|--------|------|
| 每次进入地点触发上限 | 2条 | 避免消息条刷屏 |
| 单NPC触发概率 | 0.3 | 每次检查30%概率触发 |
| 单NPC冷却时间 | 3游戏小时 | 同一NPC不会频繁触发 |
| 时间变化触发上限 | 1条 | 早上/中午/晚上切换时最多1条 |
| 事件触发上限 | 2条 | 完成任务/事件后最多2条相关台词 |

### 4.4 剧情阶段（stage）定义

新增全局剧情阶段概念，用于控制对话解锁、环境台词切换、NPC动态分层：

| stage | 名称 | 触发条件 | 对应小说章节 |
|-------|------|---------|------------|
| 1 | 觉醒前 | 游戏开始 ~ 觉醒仪式 | 第1-3章 |
| 2 | 觉醒初期 | 觉醒后 ~ 学会第一个技能 | 第4-10章 |
| 3 | 修炼期 | 学会技能后 ~ 雪峰山历练 | 第11-40章 |
| 4 | 历练期 | 雪峰山历练 ~ 城市猎妖 | 第41-60章 |
| 5 | 猎妖期 | 城市猎妖 ~ 地圣泉 | 第61-80章 |
| 6 | 灾难前 | 地圣泉后 ~ 博城灾难 | 第81-100章 |
| 7 | 博城灾难 | 灾难期间 | 第101-115章 |
| 8 | 灾后 | 灾难后 ~ 明珠篇前 | 第116-120章 |

> stage通过任务完成/事件触发自动推进，玩家不需要手动选择。
> stage变化时，系统自动重新计算所有NPC的动态tier和活跃状态。

  ```
  └─────────────────┘
  ```
- 或者直接在底部消息条显示台词，不弹窗（推荐）

### 5.3 自然触发台词显示

- 底部消息条，格式：`[赵坤三] 穆白哥说得对！`
- 3-5秒自动消失
- 不打断玩家操作
- 多条排队显示

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 环境台词触发过于频繁 | 玩家觉得烦 | 控制chance概率和cooldown冷却，默认每次进入地点最多触发1-2条 |
| 环境台词触发过少 | 感觉不到变化 | 调整概率，关键剧情节点强制触发 |
| 现有对话树unlockCondition导致对话无法触发 | 玩家卡住 | 保留default节点无条件显示，unlockCondition只用于额外分支 |
| background NPC原有对话树内容丢失 | 玩家觉得内容减少 | background中的"半核心"NPC保留对话树，点击时仍可进入 |
| 重构引入bug | 游戏崩溃 | 分阶段实施，每阶段测试，保留回滚能力 |
