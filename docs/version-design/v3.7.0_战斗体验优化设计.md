# v3.7.0 战斗体验优化设计

> 版本：v3.7.0 | 状态：设计中（待对齐） | 日期：2026-09-07

## 一、现状分析

### 已有基础
- v3.6.0完成8种元素反应，反应伤害已实装
- 战斗UI有状态效果图标、战斗日志、技能面板
- 响应式布局已支持PC横版和手机竖版

### 体验痛点
1. **玩家不知道能触发什么反应**：敌人有湿润状态时，玩家不会主动想到用雷系技能触发感电
2. **状态图标表冗余**：玩家和敌人各有一份完全相同的icons/colors/descriptions定义（约60行×2）
3. **元素反应反馈不够突出**：日志中有，但战斗场地上没有视觉反馈
4. **敌人元素属性不明显**：玩家不知道敌人是什么元素，无法针对性选择克制技能
5. **战斗节奏偏慢**：引导时间+动画，一场战斗可能需要较长时间

## 二、设计目标

1. **可感知**：玩家能直观看到"现在用什么技能能触发反应"
2. **有策略**：元素反应从"偶然触发"变成"主动规划"
3. **去冗余**：消除重复代码，提升可维护性
4. **快节奏**：减少不必要的等待，提升战斗流畅度

## 三、实施方案

### P0：元素反应提示系统（核心体验提升）

**技能按钮反应提示**：
- 当敌人身上有可触发反应的状态时，对应元素的技能按钮显示提示
- 示例：敌人有"湿润"状态时，雷系技能按钮右上角显示"⚡感电"小标签
- 提示颜色与反应颜色一致（感电=黄色，融化=橙色等）

**实现方式**：
- 在渲染技能按钮时，检查敌人状态效果
- 如果该技能的元素能与敌人任意状态触发反应，添加提示标签
- 复用 `battle-element-reactions.js` 中的反应配置表判断

### P1：架构优化（去冗余）

**状态效果渲染统一**：
- 提取 `renderStatusEffects(effects, maxWidth)` 公共函数到 `ui-battle.js`
- 玩家和敌人状态效果都调用这个函数
- 消除约60行重复代码

**元素反应判断工具函数**：
- 在 `battle-element-reactions.js` 中添加 `getAvailableReactions(targetEffects, skillElement)` 函数
- 返回该技能元素能触发的反应列表
- UI和AI都可以复用

### P2：视觉反馈增强

**元素反应场地特效**：
- 反应触发时，在战斗场地上显示短暂的反应名称动画（如"⚡感电！"从敌人头顶飘过）
- 颜色与反应一致，持续1秒后消失
- 不遮挡战斗操作，纯装饰性

**敌人元素属性显示**：
- 在敌人名称下方显示元素属性标签（如"🔥火系妖魔"）
- 颜色与元素颜色一致
- 帮助玩家选择克制元素

### P3：战斗节奏优化（可选）

**战斗速度切换**：
- 添加"1x/2x"速度切换按钮
- 2x模式下引导时间和动画速度翻倍
- 默认1x，玩家可自行切换

## 四、可玩性评审

| 维度 | 评估 |
|------|------|
| 策略深度 | ✅ 玩家会主动规划技能顺序来触发反应 |
| 可感知性 | ✅ 技能按钮提示+场地特效，双重反馈 |
| 低门槛 | ✅ tooltip+首次教程，新手能学会但不被喂饭 |
| 高上限 | ✅ 高手记住反应组合后可规划多回合连锁 |
| 原著契合 | ✅ 元素克制和反应符合原著设定 |
| 性能影响 | ⚠️ 场地特效需要控制频率，避免卡顿 |
