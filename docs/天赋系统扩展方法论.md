# 天赋系统扩展方法论

> 日期：2026-08-19 | 版本：v2.2.0 | 适用：新增系别天赋/新机制类型
> 核心原则：**按系别特点选择机制类型，不搞统一模板，确保可扩展性**

---

## 一、机制类型选择指南

### 1.1 五种机制类型

| 机制类型 | 核心玩法 | 适合系别特点 | 有无主动技能 |
|---------|---------|------------|------------|
| **资源积累型** | 战斗中积累资源，满层/消耗释放 | 需要爆发循环、资源管理的系 | 有 |
| **状态叠加型** | 给目标叠debuff层数，层数越高越强 | 控制为主、持续输出的系 | 有（引爆/破冰） |
| **形态切换型** | 两种形态自动/手动切换 | 有两种截然不同战斗模式的系 | 可选 |
| **条件触发型** | 满足特定条件（受击/闪避/击杀）触发 | 防守反击、高风险高回报的系 | 无 |
| **纯被动光环型** | 常驻被动+团队增益 | 纯辅助、功能型的系 | 无 |

### 1.2 如何为新系别选择机制类型

**决策树**：
```
新系别是纯辅助吗？
├─ 是 → 纯被动光环型
└─ 否 → 核心玩法是积累资源后爆发吗？
    ├─ 是 → 资源积累型
    └─ 否 → 核心玩法是给敌人叠状态吗？
        ├─ 是 → 状态叠加型
        └─ 否 → 有两种截然不同的战斗模式吗？
            ├─ 是 → 形态切换型
            └─ 否 → 条件触发型（受击/闪避/击杀触发）
```

**示例**：
- 火系：攻击积累燃点→爆炸 → 资源积累型
- 冰系：攻击叠寒霜→冻结/破冰 → 状态叠加型
- 水系：涨潮输出/退潮治疗自动切换 → 形态切换型
- 土系：受击积累岩力→反击 → 条件触发型
- 治愈系：每回合全队回血光环 → 纯被动光环型

## 二、新增系别天赋步骤

### 步骤1：确定机制类型和核心资源/状态

```javascript
// 在天赋数据中添加机制标识
{
    id: "new_element_talent_basic",
    name: "新系天赋名",
    element: "new_element",
    mechanism: "resource",  // 必选：resource/state/form/trigger/passive
    resourceType: "new_element",  // 资源型必填
    resourceMax: 10,  // 资源型必填
    stateType: "new_state",  // 状态型必填
    stateMax: 5,  // 状态型必填
    // ...
}
```

### 步骤2：在talent-combat.js中注册新资源/状态

**资源型**：在`init()`中添加资源字段，在`addEnergy/consumeEnergy`中自动支持（无需改代码，只需数据中指定resourceType）

**状态型**：状态存储在敌人身上（enemy.stateStacks），在battle.js的技能效果中处理

**形态型**：在`init()`中添加形态字段，在`onTurnStart()`中处理自动切换

**触发型**：在battle.js的对应事件（受击/闪避/击杀）中添加触发逻辑

### 步骤3：设计进化分支（2-3个）

**分支设计原则**：
- 不是简单的"输出向/功能向"
- 每个分支改变核心机制的玩法
- 分支之间有明显的策略差异

**示例（火系3分支）**：
- 爆炸流：强化AOE爆炸，满层自动爆炸
- 燃尽流：强化持续DoT，燃烧变真实伤害
- 强化流：消耗资源强化普攻，单体爆发

### 步骤4：设计主动技能（如适用）

```javascript
activeSkill: {
    id: "new_element_active_skill",
    name: "技能名",
    description: "技能描述",
    cost: 5,  // 资源消耗（资源型必填）
    cooldown: 2,  // 冷却回合
    damageMultiplier: 1.5,  // 伤害倍率
    // 其他效果字段...
}
```

**主动技能效果扩展**：在battle.js的`useTalentActiveSkill()`中添加新效果类型的处理。

### 步骤5：UI适配

**战斗UI**（ui.js的renderBattleScreen）：
- 资源型：在resourceLabels中添加新资源的显示配置
- 形态型：在形态显示部分添加新形态
- 触发型：在触发状态显示部分添加新状态
- 主动技能：自动显示（无需额外代码）

**天赋面板UI**：显示mechanism类型、资源/状态信息、主动技能

### 步骤6：debug快捷功能

在debug.js的天赋标签页添加新资源的快速设置按钮。

## 三、新增机制类型指南

如果五种机制类型都不适合新系别，可以新增机制类型：

### 新增机制类型步骤

1. **在talent-combat.js中添加状态管理**
   - init()中添加新状态字段
   - 添加对应的get/set/trigger方法
   - onTurnStart()中处理回合更新

2. **在battle.js中添加触发逻辑**
   - 找到对应的战斗事件节点
   - 调用talent-combat.js的方法

3. **在ui.js中添加UI显示**
   - 战斗界面显示新状态
   - 天赋面板显示新机制类型

4. **更新本文档**
   - 添加新机制类型的说明
   - 更新机制类型选择指南

### 机制类型设计原则

- **每个机制类型应该有独特的玩家决策点**
- **避免与现有机制类型重复**
- **确保可以通过数据配置，不需要改代码**
- **考虑与其他机制类型的组合可能性**

## 四、跨系组合设计指南

### 4.1 组合设计原则

- **机制互补**：两个系的机制类型不同，组合后产生新玩法
- **不是简单数值叠加**：组合应该改变战斗策略
- **触发条件合理**：同时装备两系且等级≥3

### 4.2 组合效果实现

在battle.js中添加组合效果检查：
```javascript
// 检查跨系组合
if (player.hasTalent('fire') && player.hasTalent('wind')) {
    // 火+风：火焰风暴
    // 闪避后燃点+3，疾风状态下爆炸伤害+50%
}
```

### 4.3 已有组合列表

| 组合 | 机制协同 | 效果 |
|------|---------|------|
| 火+风 | 资源+触发 | 闪避加速燃点，疾风强化爆炸 |
| 冰+雷 | 状态+资源 | 冻结加速电荷，破冰触发连锁 |
| 土+暗 | 触发+状态 | 受击上诅咒，反击引爆 |
| 水+光 | 形态+形态 | 形态切换时另一系获得增益 |
| 召唤+治愈 | 资源+被动 | 召唤兽享受光环，契约积累时全队回血 |

## 五、数据格式规范

### 5.1 天赋数据必填字段

```javascript
{
    id: "唯一ID",
    name: "天赋名称",
    element: "元素系别",
    rarity: "common/uncommon/rare/epic/legendary",
    type: "growth/innate",  // 成长型/先天型
    mechanism: "resource/state/form/trigger/passive",  // v2.2.0新增
    maxLevel: 10,
    description: "描述",
    evolutions: [/* 进化阶段 */],
    // 机制类型特定字段：
    resourceType: "fire",  // 资源型
    resourceMax: 10,       // 资源型
    stateType: "frost",    // 状态型
    stateMax: 5,           // 状态型
    activeSkill: { /* 主动技能 */ }  // 有主动技能的系
}
```

### 5.2 进化阶段格式

```javascript
{
    level: 5,
    stage: "进化",
    name: "分支选择",
    description: "描述",
    branchChoices: [
        {
            id: "branch_id",
            name: "分支名",
            description: "分支描述",
            effects: { /* 效果字段 */ }
        }
    ]
}
```

## 七、常见问题

### Q: 新系别应该用哪种机制类型？
A: 按决策树选择，核心是"这个系别的战斗特色是什么"。如果拿不准，优先选择资源积累型（最通用）或状态叠加型（最容易设计）。

### Q: 主动技能是必须的吗？
A: 不是。条件触发型和纯被动型通常没有主动技能。资源型和状态型建议有主动技能增加操作深度。

### Q: 分支应该设计几个？
A: 2-3个。2个适合机制简单的系，3个适合机制复杂的系。不要超过3个，避免选择困难。

### Q: 如何确保与现有天赋不冲突？
A: 新增数据前先Grep确认ID不重复，引用的技能/物品必须已存在。跑L1数据完整性测试。
