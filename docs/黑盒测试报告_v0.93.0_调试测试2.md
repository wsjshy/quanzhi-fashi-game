## 四、根因判断

### 对照结果判断表

| 判断情况 | 实际结果 | 是否匹配 |
|----------|----------|----------|
| appended exists=false → appendChild失败 | 不匹配（exists=true） | - |
| appended exists=true, after 100ms exists=false → 被立即移除 | 不匹配（100ms后仍存在） | - |
| **appended exists=true, after 100ms exists=true, 但看不到 → 样式问题或被遮挡** | ✅ appended=true, ✅ 100ms后=true, ❌ 看不到 | **完全匹配** |
| 完全没有appended日志 → appendChild之前return或报错 | 不匹配（有appended日志） | - |

### 最终根因（100%确认）

**两个overlay的z-index都是2000，而game-container的z-index是9999。overlay被append到document.body，但z-index远低于game-container，导致被game-container完全遮挡，用户看不到。**

具体证据链：
1. 按钮onclick正常触发（`[DEBUG] rest button clicked` / `[DEBUG] events button clicked`）
2. 函数正常调用（alert弹出确认）
3. overlay成功append到DOM（`exists=true`）
4. 100ms后overlay仍在DOM中（`exists=true`）
5. overlay样式正常（`display:flex`，非`none`，`opacity`正常）
6. overlay覆盖整个视口（rect: x:0, y:0, width:1365, height:945）
7. **overlay的z-index=2000**
8. **game-container的z-index=9999**
9. 结论：overlay被game-container遮挡

### 为什么前三轮z-index:2000修复无效？

前三轮给**按钮**添加了 `position:relative; z-index:2000`，但问题不在按钮，而在**overlay弹窗**。按钮的z-index调整无法解决overlay被game-container遮挡的问题。

---

## 五、修复方案

### 方案1（推荐）：提高overlay的z-index
将 `.rest-overlay` 和 `.ei-overlay` 的z-index从2000提高到大于9999，例如：
```css
.rest-overlay, .ei-overlay {
  z-index: 10000;  /* 或更高，如 99999 */
}
```

### 方案2：将overlay append到game-container内部
不append到document.body，而是append到game-container内部，这样可以继承game-container的层级上下文。

### 方案3：统一管理z-index
建立全局z-index管理体系，确保所有弹窗/overlay的z-index都高于game-container。

## 七、总结

### 调试结论
- **休息按钮**：overlay成功append到DOM且持续存在，z-index=2000，被z-index=9999的game-container遮挡
- **事件与情报按钮**：overlay成功append到DOM且持续存在，z-index=2000，被z-index=9999的game-container遮挡
- **共同根因**：overlay的z-index太低（2000），低于game-container的z-index（9999），导致被完全遮挡
- **非appendChild失败**：overlay确实被添加到DOM
- **非被立即移除**：100ms后仍存在
- **非display:none**：样式为display:flex

### 修复建议
将 `.rest-overlay` 和 `.ei-overlay` 的z-index从2000提高到10000或更高（大于game-container的9999）。这是一个一行代码的修复，预计修复后两个按钮都能正常显示弹窗。
